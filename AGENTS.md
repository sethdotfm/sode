# AGENTS.md

Notes for AI agents working in this repo. Only the non-obvious is here; code and git history hold the rest.

Sode: keyboard-first web patching for one SW-P-08 router (Ross Ultrix). Settings table and protocol summary are in README.md.

## Commands

go test ./...   (Dockerfile build runs it too)
go vet ./...
go test ./internal/app -run TestName -v
node --test 'web/test/*.test.mjs'
go run ./cmd/swp08sim   (simulator on :8910, SIM_* env in cmd/swp08sim and README)
SODE_ROUTER=127.0.0.1:8910 SODE_DEBUG=true go run ./cmd/sode   (:8080, SODE_DEBUG hex-dumps SW-P-08)
docker compose --profile sim up --build

Without SODE_CONFIG, config comes from SODE_* env and is not persisted. The web UI is go:embed (web/web.go): restart after frontend edits.

## Key decisions

- Go, stdlib-first. Deps only coder/websocket and yaml.v3; no new deps or frameworks without asking. Distroless image, HTTP :8080 (TLS is the user's proxy).
- SW-P-08 over TCP to one router, single matrix, always extended commands (16-bit src/dst). Protects honored. Auto-reconnect and keepalive. Names come from the router, re-polled (default 60s).
- Levels: wire = level + offset. Internally levels are UI 1..N everywhere. levelNumbering (1, 0, va) only changes display (Level.Label) and typing (parseLevels in levelview.js). levelTypedBase is dropped but kept so old files load. No free-text level names (user asked for removal).
- Config lives in /data/config.yaml, edited in Settings. SODE_* env only seeds the file on first start. Save stays open; leaving with unsaved server settings warns once, a second try discards.
- Settings PIN: PBKDF2 hash in settingsPin (json:"-", never sent to browsers, SaveSettings carries it over). Unlock is per connection and per hash, relocks when Settings closes or the PIN changes. unlock is handled inline in the read loop so a following lock wins. Wrong PINs counted globally, one check at a time, waits double from 30s after the 5th; pinMaxTries (default 10, 0 = never) locks until -reset-pin or restart. A non-hash settingsPin stops startup. SaveSettings is serialized by cfgMu and re-checks the lock.
- Device defaults (#49): deviceDefaults (theme, layout, clock, flip, scrollTop, searchFilters, setStack, nextMode) is what This device follows until a browser picks its own. Not router-side, no reconnect. Browser values are localStorage strings (sode-theme, sode-layout, sode-clock, sode-flip, sode-scroll-top, sode-search-filters, sode-set-stack, sode-next-mode); missing or unknown means Global. resolve() in web/prefs.js (pure) picks own, then global, then built-in. device.js pref/setPref ('' removes) are the only readers and writers. Global defaults are cached in localStorage sode-device-defaults on every hello for web/prepaint.js (sync in each head; other pages pass data-only="theme"), which repeats resolve() inline: keep them in step.
- Settings search: settingsindex.js (pure, own scorer) indexes fieldsets and labels (label[for], .sode__field-label[id], .pb-check, [data-find][data-label] for buttons etc). DICT maps section slugs (legend text) and control ids to search words. A new settings section must add its slug to DICT or settingsindex.test.mjs fails; add terms for new settings too. Esc in the box clears it, the next Esc leaves Settings. Its input events must not reach the form.
- Frontend: vanilla ES modules, no build. Follow patchbay rules exactly (https://github.com/sethdotfm/patchbay llms.txt): pb- classes only, tokens only, no Bootstrap utilities, no border-radius, status always with text. Vendored in web/vendor/patchbay (VERSION file, v2.1.0); copy missing icons from upstream, never fake them. UI scales with html font-size 125% (phone 100%), never zoom; sizes in rem; numbers use --pb-font-num, --pb-font-mono is for code/hex; no per-theme CSS; tooltips are data-pb-tip (+ pb-tip--end); green buttons pb-btn--ok; icon-only ghost buttons need pb-btn--icon; layout.js sets data-pb-layout="phone".
- Comments: context only (why, invariants, quirks, keep-in-step links); never restate the code, no issue numbers (git history has them).
- Build DOM with el(), never innerHTML: names come from the router.
- Users never ride the hello (it reaches locked pages): hello() blanks cfg.users. Names come in lockState.names (only when unlocked, S.userNames), PIN lengths in lockState.lens, the Users editor asks usersList. Keep new user fields out of anything sent before unlock.
- Confirm dialog: churning random letter plus lockout (default 500ms, Enter optional).
- Version (#95): Version and Stage in internal/app/version.go, sent in hello as BuildLabel(), shown in Settings, noted in README's Version line. Every release bumps both and adds a CHANGELOG.md section (#147). TestVersionNoted fails on mismatch, or with SODE_RELEASE_TAG if the tag differs or the heading says unreleased. See RELEASING.md. Only promote.yml may push the latest image tag.

## Shared saves and owned fields

- Filter sets and presets save through saveShared (app/shared.go: takes cfgMu, guardSave(c,true) re-checks PIN or trusted user, update mutates a copy then Normalize, Validate, save, optional small broadcast) and replyOp(c, kind, id, n, noun, err) (logs the command, answers <kind>Result echoing id, sets locked). New saved-apart features use both. Name rules: validateNames in config/names.go (count, empty, 32 runes, unique ignoring case).
- Owned fields: Config fields saved outside the Settings form carry owned:"true" (filterSets, presets, settingsPin, deviceDefaults, users). saveSettings does cur.KeepOwned(live) so a stale browser copy can't change them. Form-saved fields carry guard:"router|pin|open": router reconnects (config.Changed(old,c,"router")), pin means only the settings PIN may change it. TestEveryFieldChooses fails if a new Config field has neither tag. The Settings dialog strips owned lists from its config message (OWNED_KEYS in owned.js; socket limit wsReadLimit 64 KiB).
- Inputs saved apart from the Settings form carry data-apart so the unsaved check skips them. emit('settingsClose',{discard:true}) closes Settings discarding the form.
- Grid is parked on branch archive/grids (#150); old grids: and gridConfirm: keys load and are ignored.

## Architecture

- internal/swp08: frame.go, msg.go, client.go: one TCP session with reconnect and a keepalive probe (an interrogate, on connect and after 10s without rx). Up is reported, and Send accepts, only after the router's first reply. SetTarget reconnects without reporting down. A probe with no reply drops the link (~13s); other unanswered messages just trigger a probe. Rx times are monotonic offsets, writer is ACK-gated. Messages sent while disconnected are dropped. Callbacks OnUp, OnMsg, OnState.
- internal/app: App owns all router state (names, tally, protect, keyed dst to UI level) under one mutex. Config is an immutable runtime behind an atomic.Pointer; ApplyConfig saves, swaps and, if router-side fields changed, clears state and calls SetTarget. Run ticks every 100ms: flush() batches broadcasts and finishes name refreshes, periodic() re-polls.
  - Takes: take() = prepare + complete: plan, check, register, send, wait, collect, one takeLevel per level in the waiter. Tests drive takes through App.sendMsg with a fake router (take_test.go).
  - Check (checkTally, #57) interrogates every level and waits up to 1s so Prev (what undo restores) comes from the router, not a cache that misses unannounced changes (falls back to cache). Skips levels reported within checkFresh (15s) and all takes of a confirm of bigBatch (6)+ (NoCheck, #91), trading undo accuracy for router load.
  - Router load: one message per ACK, so timeouts count from when a take's last message was ACKed (Why.Done, sendTracked, leftQueue, queueMax); own keys register for queueMax + ownFor then shorten to ownFor.
  - Late answers: a take the router answers late is claimed (lateTake, lateFor; only levels the router said nothing about) and its entry amended (lateWorker, Entry.Late, a recent message with update).
  - Failures (#15, #17): the cache holds only what the router reported, so the next Prev is real state. waiter.see keeps the latest route for unconfirmed levels; whyMissing writes Failed and Now ([ui level, src], -1 = nothing); a level the router reports on src after all is already (#36). Undo of a failed take leaves out levels in Now and keeps no-answer levels (undoItem).
  - A router change cuts takes in flight (#106, cutTakes): they fail with "the router changed"; a waiter keeps the extTracker it started on.
  - history.go: JSONL with paging; a page never ends inside a group.
- internal/app/http.go: /, /healthz, /api/health (#140: 200 only while the router is up, else 503; no PIN or config), /ws. One WebSocket per browser, JSON with a t field. batch: all takes of one confirm, at most 8 at once, multi-take batches share a history group. history takes before (echoed) and n; takePage keeps a page only if it is for its current oldest entry. Server pushes ping every wsHeartbeat (5s) through the writer goroutine since browsers can't see ping frames (#142). Client IP honors X-Forwarded-For (nearest untrusted hop; X-Real-IP when none) only from trustedProxies; a hop that isn't an address ends the search at the peer.
- internal/config: Defaults, FromEnv (seed), Normalize, Validate; YAML load/save; LevelMap does UI/wire levels.
- cmd/swp08sim: fake router; must keep mimicking real Ultrix quirks (e.g. no Connected for no-op connects).

## Web layout

main.js wires modules then calls connect(). core.js is state/socket/bus (S, WebSocket, on/onFirst/emit/onMsg, el, fuzzy search, status helpers, nameProblem); it imports only tooltip.js and nothing may cycle (test/imports.test.mjs checks, and that every import exists). Modules reach handle() through events (helloCfg, helloData, wsclose, onMsg), so a page only gets them if it imports the module. Tests import everything via web/test/all.mjs.
- Helpers: globalsave.js (makeSaver is the one saver flow; globalSaver adds the PIN row and relock for save-for-everyone; profileSaver; profileProblem is the 48 KiB check), scopes.js (the one scope registry; setsIn, presetsIn), keyconfirm.js, trapDialog in widgets.js, owned.js, store.js (never-throwing readStr/writeStr/readJSON/writeJSON: use these, no hand-written try/catch), levelview.js, levels.js, routes.js, device.js, filterstore.js, history.js (histRows, quick search, pager, putEntry), plans.js (plans, planBlocked/planSummary, sendTakes, banners), widgets.js (levelBox, combobox, undo/retry buttons, disclosure, arrivals, feeding, labeled), pin.js, pinprompt.js (askPin/reask: the one prompt for a settings PIN needed mid-session, see docs/agents/users-locks.md), banner.js (result banner; plans.js re-exports it), settingstoc.js and settingspin.js (Settings' sections/phone pages and PIN fields), about.js (the Settings bottom row), shortcuts.js, keyboard.js (kbdUp), showall.js, settings.js (builds #settings-toc), filters.js, filter.js.
- Socket freshness (#142): core.js keeps ws.lastRx (set on open and each message; test stub sockets need it). A 1s check drops an open socket silent for 15s; wsSend refuses one silent for 7s; drop(ws) reports at once and the page reconnects. sendTakes shows Not sent when wsSend returns false.
- Source ends (#138): srcEnd in routes.js decides if a source is pickable; srcRow, currentlyNodes and stackSteps all use it. Desktop history rows fill a box with useEnd (opposite box next); Receiving's pickSrc goes to Levels.
- planBlocked returns {block, prot} without touching the plan; pass prot to planSummary.
- Failed-take banner (failureBanner, refreshResult): one line per distinct outcome, follows the takes' entries (takeResult carries entry), turns into a confirmation as takes are confirmed late or retried.
- desktop.js and mobile.js are the two layouts (layout.js picks: auto on narrow touch screens, per-browser override; index.html applies the same rule before first paint). Phone: one input stepping Source, Destination, Levels; summary pinned at top; match list floating; number pad for Levels.
- Desktop keyboard mode: Esc with all boxes empty (or Esc on a Recent button) focuses #history and sets keysOn, cleared by any click. onListKey: s/d/f boxes, j/k rows (Ctrl+J/K, Cmd+J/K on Mac, work too, as in the match lists), J next group, K latest take, h/l or Enter close/open, u/r, comma settings, / Filters, Shift+S/D filter by boxes, ? shortcut list (also Ctrl+?). Folders auto-open under the cursor (autoOpen); .sode__key-note shows each empty box's key.
- Keys: Ctrl+Z (or Cmd+Z on Mac) undoes the last Sode take, except that a box with text keeps the OS text undo. Ctrl+, Settings. Ctrl+G (Cmd+G on Mac) Presets popup. Modifier rule: Control = Sode commands and match-list moves (Ctrl+J/K) on every OS; Alt = theme toggle (Alt+Shift+T), Alt+1-9 firing the first nine pinned presets and Alt+Shift+1-9 filling the boxes from one (e.code Digit1-9, presetkeys.js), and in the Presets popup Alt+P (pin), Alt+arrows and Alt+Cmd/Ctrl+J/K (reorder pins); Cmd belongs to the OS except Cmd+Z, Cmd+G (preventDefault stops find-next), Cmd+J/K and Cmd+Enter in the Destination box; every check excludes the other two modifiers. Key labels are lowercase with ⇧ where Shift is needed.
- Key plumbing: keys.js (imports nothing) exports mac (the one platform test; never repeat the regex) and chord(e), naming a keystroke the same way everywhere (alt+p, ctrl+alt+j, alt+3, shift+enter: modifiers in fixed order, then the physical letter or digit via e.code, arrows as up/down) and the one set of listeners for html[data-shift] and html[data-alt] (cleared on window blur). New key handlers match on chord(e), not hand-written modifier checks. presetkeys.js has the page-level preset keys (Alt+1-9, Alt+Shift+1-9, Ctrl+G / Cmd+G, the Windows/Linux bare-Alt keyup cancel); presetpopup.js only the keys while it is open.
- Ctrl+S/D/F fill a patch box from the last take (useLast, lastTake() in plans.js: this browser's last patch from sendTakes, else the newest Sode take in history); destinations add to those present; focus goes to the opposite box only if empty, else Levels. Boxes show a Last chip. Destination-first order is per browser unless following the global default (flipped, setFlip, data-flip on html).
- Next chips (nextTake in plans.js) and Ctrl+Shift+S/D fill Source/Destination with the last take's numbers plus one. Pref nextMode number or fuzzy: fuzzy searches the name without its counter (nameStem: "Cam 3" to "Cam", #149) and takes the first higher match in router order (nextOf), else number + 1 (#196). Repeating (#195): nextTake(state) steps from what the last Next fill put in a box (run, set by usedNext) while the box still holds it, else from the last take; no reset hook, a take or Clear ends it. A side with no next does nothing. Desktop chip shows Next, opening via CSS to the value on hover, focus or Shift held (data-shift on html), hiding Last meanwhile.
- Destination box +, Ctrl+Enter, Cmd+Enter add another destination (#93): the match becomes a chip and the search stays open minus added ones. Enter with leftover text and chips is refused (Esc clears); Tab takes the best match (desktop).
