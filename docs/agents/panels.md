# Panels

Sode Panels: saved 4x8 grid pages on `/panels`, `/panels/editor` and `/panels/<id>`, driven over `/api/v1` only. The design and what was built are in docs/panels-design.md; this note holds what bites. Names that are stored or sent are in docs/persisted-names.md, routes in docs/api.md and `internal/app/openapi.yaml`.

## Storage

All beside the config, under `/data` in the image.

- `panels/<id>.yaml`: one file per panel. `<id>.art/<art id>` holds its artwork and `<id>.checkpoints` its Push checkpoints (at most 10). `panelStore` (`panelstore.go`) owns all three; artwork is capped by total bytes (`panelArtTotal`, 64 MB, `artBytes`), not by count, and `copyArt` (Push and Copy) copies what fits and returns the ids that did not; every write goes through `writeLocked`, which moves `Rev`.
- `panelsets/`: Checkpoint sets, `everyone.yaml` and `me-<hex of user>.yaml`.
- `templates/me/` and `templates/everyone/`: templates, apart from the panel files.
- `artdefaults.yaml` and `artdefaults.art/`: Default artwork (`artDefaultStore`, `artdefaults.go`; routes in `artdefaultsapi.go`). Images are keyed by content (`d-` ids), so setting one image twice stores it once, and a write deletes images no default names. The 64 MB cap covers all of them together. Uploads and copies both go through `checkArtBytes`.
- `icons.yaml` and `icons/`: the Icon library (`iconLib`, `iconlib.go`; routes in `iconlibapi.go`). Ids are random, not by content, so two names for one file stay two icons; files are `<id>.png` or `<id>.svg`. `freeName` turns a clash into "Name 2" and is the one place names are settled; a rename runs it against the other icons, so a case-only rename keeps its name. Delete leaves cells with their `lib:<id>` (they draw nothing) rather than rewriting panel files; `/icon-library/{icon}/uses` counts them for the Confirm (cells only; a Default artwork naming it is not counted). Push, Copy and templates keep `lib:<id>` untouched (`copyArt` walks `Art` only, `dropArtwork` drops `a-` ids only), and a Default artwork stores the reference after checking the icon exists, never a `d-` copy, so the 64 MB caps never see library bytes. `iconlibmove_test.go` covers these and a panel body moved to an install without the icon. The upload is JSON with the file base64 in `data`, so the PIN rides in the body; `iconBodyMax` sizes the read from the 2 MB cap. `icons/drop-in/` (`iconlibdrop.go`) is read by `rescan` at start (`New`) and on `POST /icon-library/rescan`: `checkLibBytes` is the upload's check, `dropName` keeps in step with `libNameOf`, an added file is removed so a second rescan never adds it again, and skipped files stay. Reads go through an `os.Root` after an `Lstat`, so a link never leads out; a linked `drop-in` is refused whole.
- `panelwatch.yaml`: who watches what, as watch keys: a panel id, or `<id>/<device lowercased>` for one instance (`watchKey` in `panelmon.go`; keep per-instance watches keyed by the device name, since #293 makes named instances first class). Never part of a panel file, and the API only sends the caller's own `watching` and `watchingInstances`.
- `yamlDir` (`yamldir.go`) is the mutex, directory, id retry, atomic write and name sort that the panel, template and Checkpoint set stores share; file names and skip rules stay in each store. Sets keep several records per file, so they use only part of it.
- A file whose id, name or directory disagrees with its content is skipped, not repaired.
- Pages (ADR 0007, `panelpagelist.go`): `Panel.Pages`, `Template.Pages` and `panelLayout.Pages`. `LegacyCells` (`cells`) is read only: `normalPages`, run by `normalize` and `Template.migrate`, makes it one enabled Page named after the record id's hex digits (stable across restarts until the first save), and it is never written. Pages win when a file has both, as one an older Sode saved would. `checkPages` runs in `validatePanel` and `Template.clean`, fits cells with `fitCells`, refuses a list with no enabled Page, and calls `checkPageTargets` (a malformed Go to Page `page` is 400, a missing target is kept) and `checkShowParts`. A PUT body with `cells` and no `pages` changes Page 1 only; a body with both is 400. Anything that walks a panel's cells uses `allCells(p.Pages)` (Default artwork, Icon library uses). In the page, `pageCells` (`web/panelpages.js`) is what `cellsIn` reads, Page 1 unless given an index; the editor keeps the Page list beside the grid (see Editor Pages below), and `saveBody` and `saveTemplateBody` send `pages` built by `storedPages` from the editor's live Page list (the focused Page's grid folded in), every Page fitted to the grid's size.

## Keys

- A panel that acts as an API client has an `apiClients` entry with `panel` set to the panel id. It is made and removed with its panel and does not count toward the 12-client limit. A Trusted user may make one, with Rights no wider than their own (`Rights.Within`, ADR 0006). The cap is checked only when a save sets Rights to something new, so a panel an administrator widened keeps saving.
- Its keys are key-store entries, one per named instance, and the key name is the instance's device name (`panelkey.go`). A link is always made for a name (400 `bad_request` without one). Making one for a held name rotates only that instance, and `DELETE /panels/{id}/key?instance=` revokes only that instance; `replaceInstance` does the end-and-make under one lock and refuses past `panelKeyMax` (20, keys and pending setup links together) without changing anything. `GET /panels/{id}/keys` lists them with `online` from the monitor (`deviceOnline`, matched by name ignoring case) and never a secret. A key made before instances existed is named `Link` and is just another instance. Ending an instance forgets only its device (`forgetDevice`). Network limits are the client's `networks`, a CIDR list of at most 16, checked in the auth path so every route and the setup exchange are covered.
- A setup link is a `keys.json` record with `"setup": true`, named for its instance. It lasts one hour and works once, and the page trades it at `/api/v1/panels/{id}/setup` for a key with the same name. It ends with that instance's key (rotate, revoke, a newer link for the name), not with the other instances'.
- The Share modal opens on the tab that fits the panel (`firstShareTab`: Link with key for an API or Both panel, People for a Session or Public panel). A Session or Public panel's Link with key tab is muted (`keyTabMuted`) (`muted` on the tab item, `aria-disabled`) and readable: it says a link to a Session panel asks for a sign-in, or that a Public panel needs no key, and offers no key action. The editor's saved note per mode is `actsSavedNote` and the Public warning `PUBLIC_WARNING`, both in `panelsrules.js` so node tests read them. Changing the Authentication mode in the editor saves the panel at once (`ed.save()`), since it makes or removes the client; a refusal (`trusted_required`, `outside_rights`) puts the choice back and is shown under the field.
- `acts` is `session`, `api`, `both` or `public`. `api`, `both` and `public` own a client and keys the same way: test with `actsHasClient` (Go) and `hasClient` (`panelsrules.js`), never `=== 'api'`, unless the rule really is "only with a key" (the panel page's refusal of a keyless open, the hidden Copy link, the link row's hint). `both` falls back to Session mode in `panelrun.js` by doing nothing: its only `acts` check is the `api` refusal. Switching `api` to `both` or back keeps the client and its keys; `session` ends them. A switch that makes or ends the client waits for the Confirm: call `guardActs` (`actsguard.js`) from any new place that changes `acts`, never `setFields` or a PUT on its own. The Confirm box (`confirmbox.js`) is the one Rotate and Revoke use.
- A panel has an optional `slug` (unique, `validPanelSlug`). `panelStore` checks uniqueness under its lock. `GET /panels/{id}` and the setup route turn a slug into the id (`panelIDOf`); every other route takes the id only. Build links with `linkFor` (`web/panellink.js`), never by hand. Panel keys and setup tokens are 128 bits and the fragment drops their `sode_` prefix (`fullKey` and `fullSetup` put it back).
- Links made on a page opened as localhost are useless on a phone, so `web/sharehost.js` asks once for the address other devices use (`localStorage` `sode-share-host`) and `linkBase()` swaps it into every link and QR code; `linkFor` itself stays pure.
- The panel page reads `#key=` (API mode), a stored `sode-panel-key-<id>`, then asks for a Public key, then starts a session key (Session mode). A key never rides a query string. A `#key=` that opened the panel is stored under that name and dropped from the address (`keepLinkKey` in `panelsetup.js`, `withoutKey` in `panelkeyrules.js`), only once the open succeeded, never a Public key, and only if `localStorage` reads it back; otherwise it stays in the address. A stored key from either path is forgotten on a 401. A test that opens a keyed link and then a plain one in the same browser must drop the stored key first (`TestChromePanelBothMode`).
- Public keys (`panelpublic.go`, ADR 0008): `POST /panels/{id}/public` is unauthenticated, so its keys live in `App.public`, never in `keyStore`: no disk write per request, nothing in `GET /keys`, the instance cap or `keys-ended.json`. They last 15 minutes each, at most 64 per panel; past that the asking address loses its own oldest key first (`publicRec.addr`) and the key's streams end. They have their own shape (`sode_pub.` and 43 characters, `isPublicShape`). A dropped one (expired, pushed out, the panel left Public) is remembered in `publicKeys.ended` (4096 hashes) and reads as ended, uncounted. An unknown one reads as `key_revoked` too, so a page that slept asks again, but it counts toward the failed-key throttle once `App.started` is more than a TTL ago; before that it may be a key a restart forgot. No ask counts toward the failed-key throttle: every keyless open of any panel asks, and counting those would lock out an office behind one address. Instead `publicAskMax` (128 asks per address per minute, or the API rate limit if lower) counts every ask whatever the id. Not Public, no panel and outside the client's networks all get the same 200 `{"public": false}`, so no run of asks tells which ids exist, and the browser logs no error on a keyless open. `endPublicKeys` runs when a save leaves `public` and on delete; expiry ends them in `expireKeys` with no log row each. Every Public key is named `Public`, so a call with no `X-Sode-Instance` is logged under the caller's address (`apiKey.public` in `panelHeaders`), not the key name. In the page, `askPublic` returns '' only for Sode's `{"public": false}` and throws on anything else, so a lockout or a lost link during a renewal reads as lost contact and the next call asks again; only the first ask at open (`askPublicAtOpen`) falls back to a session.
- Page lock on a Public panel: no PIN pad, only the idle letter Lock (docs/panels-design.md). This is page-only: `panelrun.js` emits `publicPanel` {on} (never from the editor's live test, off again when the page stops or a live update leaves Public), and `lock.js` rereads the last `lockState` through `pinFreeView`. The server's `lockState` for the panel page stays locked with no names, so do not lift the pad by letting the connection in on the server (`TestPageLockLeavesThePublicKeyAndSendsNoNames`, `TestChromePublicPanel`).

## Browser session key

A Session-mode page trades its signed-in session for a user key over the socket: message `sessionKey`, answer `sessionKeyResult` (`internal/app/sessionkey.go`, `web/sessionkey.js`, rules in `sessionkeyrules.js`). The key is memory only, ends with the session, and `sessionFetch` adds the Bearer header. A refused `sessionKeyResult` reaches `onSessionKey` watchers as step `refused` with the server's reason as a third argument; without it a page waits for a key forever and shows nothing (the editor's old blank page). Use `sessionFetch` for every `/api/v1` call from a Sode page; never build the header by hand.

Ended keys (the throttle lockout a stale tab caused): Sode answers a key that worked and then ended with 401 `key_revoked` (`key_expired` past its expiry) and never counts it toward the ten failed keys per address (`refuseEnded` in `apiauth.go`, its own cap of 120 a minute and one `endedKeyUsed` row per address per minute). The key store remembers the last 1024 ended keys by hash in `keys-ended.json` (`noteEndedMu`; every drop path records them, setup links and session keys left out). A session key has its own shape, `sode_ses.` and 43 base64url characters (`isSessionShape`), so an unknown one reads as ended even after a memory-only restart; 256 bits make an uncounted guess harmless. A session holds up to 16 keys (`sessionKeyMax`), one per tab, because tabs share a session token and a key per session made them end each other's on every renewal. In the page, `sessionFetch` renews once on `key_revoked`, `key_expired` or an older Sode's `invalid_key`: the first call to see the key refused asks for a fresh one if still signed in, and the others wait for it (signed out, they wait for the sign-in, sending nothing). A fresh key refused before it ever worked ends the module for good: every later call gets that answer without the network, and `onSessionKey` watchers hear step `ended`. `guardFetch` (`sessionkeyrules.js`) holds the next call until Retry-After has passed after a 429, and, given `final`, replays a final answer without the network; the panel page wraps its link key in it. On a stop, `panelrun.js` clears its timers, the update check and the keepalive (`keep.stop()`). `TestChromeEndedKeysStopWithoutLockingTheAddress` covers two tabs on one session, a forgotten key and a revoked link. For a JSON answer wrap it in `jsonCall(fetcher, { failed, down })` (`sessionkey.js`), which throws an Error with `status`, `code` and the server's message; a page with a URL key passes its own fetcher. Details are in docs/agents/users-locks.md.

## Seams

- REST: `panelsApp`, `userKey`, `makePanel`, `apiSend` and `apiSendRaw` in `panelsapi_test.go` run the real handlers against a fake router. Use them for any new route test.
- Web rules modules are pure and tested without a DOM: `panelmodel.js` (view, stage, Take), `panelrules.js`, `panelupdate.js`, `panelwatchrules.js`, `panelkeyrules.js`, `panelsrules.js`, `panelpushrules.js`, `gridmodel.js`, `editorrules.js`, `findrules.js` and `arttoolrules.js`. Put new logic there and keep the DOM modules thin.
- Browser harness: docs/agents/browser-checks.md. Chrome checks use the real Handler and a built simulator, never `panelsApp`.

## Undo cell

- `panelundo.go`: `GET` and `POST /panels/{id}/undo`, scope `take` only, so a panel key undoes without `history` (`config.PanelClientScopes` must not gain it). `panelUndoTarget` walks History newest first (at most `undoScan` entries, each a file read), counts an entry with `undo` set as undoing its target only when it is `ok` (a refused or failed undo leaves the take; a Late Result flips `ok`), and takes the first entry whose `panelId` and `instance` (ignoring case) are the caller's own, with its Group, read again from its own entry so another take's interleaved entries never split it. GET answers the take's newest entry as `id`; POST sends it back and gets 409 when the target moved. The instance is `Actor.instance` from `panelHeaders`; a caller with none (the editor's Test it live) has nothing to undo. Entries made before `panelId` existed never match.
- The Undo cell trusts the instance name the page sends (`X-Sode-Instance`), as every other instance feature does.
- The page keeps the answer in `undoNext` (`panelrun.js`) and greys the cell from it (`undoReady`). It asks when a poll first reaches Sode (load and reconnect), after its own take or undo, on a rename or live update, and when the tally of a destination in `undoNext.routes` moves (`undoMoved`); never on a timer, since each ask walks History. `finishUndo` shares the results with `finishTake` but leaves the plan staged, and puts the status in `st.undone`, since a done undo is no error.

## Push, Rev and live update

`panelStore.applyLocked` writes the checkpoint, then the panel. A checkpoint that cannot be saved stops the Push. Open pages poll `GET /panels/{id}` every 5 seconds and compare `rev` with the `artDefaults` it carries (`revOf` in `panelupdate.js`, since a changed default moves no panel rev; `panellive.js`; a 10 s countdown banner with a bar, Snooze 60 s (once per open page) and Apply now; staged routes hold the plain countdown but not a Snooze or Apply now, see docs/panels-design.md), so a Push, an editor save and a restore all reach them through the same store write. Push and import never copy `acts`, `client` or `clientRights`, nor id, name, owner or `share`. A Push also keeps the target's `settings.fixedDests` (`pushLayout`); a Checkpoint set and a restore put the whole layout back, list included. A template keeps the list only with `dests`. A new route that stores a panel must not widen that list. The group for Push is worked out in the page (`pushGroups`); the server only sees ids.

## Monitoring

`panelmon.go` keeps devices in memory, so a restart alerts nothing. A device is dropped after 24 hours. A page holds `GET /panels/{id}/instances/stream` (a `fetch` with the Authorization header, in `panelkeepalive.js`), so a closed page is seen at once and lost 8 seconds later (`monGrace`); a device that never held a stream, or beat again with none open, keeps the 45 second keepalive miss (`monMiss`). A panel is online while any device counts. A blank device (`askInstanceName` off and no name) is named by the caller's address (`deviceOrAddr`), so watches and notices work as for a named one; the page decides it once at start, so a live update that flips the setting waits for a reload. Notices go only to connections signed in as a watcher and not under the Lock, and are never in the hello. The Sode page shows a banner for the offline panels (`panelwatch.js`, the badge on pages without one). Its Clear menu sends `panelAlarm`: `clear` hides the outage for that user until the panel's next notice (memory only), `stop` removes the watch. The tests use `a.mon.now`, and `monHold` in `panelmonstream_test.go` for a real held connection. Each held stream (`monConn`) has a one-line `out` channel that its own handler goroutine writes, so nothing else writes to the response; an Assign or a rename is the only line sent on it and the stream ends after it, the old name forgotten with no lost notice (`panelassign.go`, `panelrename.go`; `assignHold` in `panelassign_test.go` reads the lines). `instances` rows carry `stream`, and only those rows are Sode's own panel pages and can be assigned. A watch is the whole panel or one device (`?instance=`); `watchersOf` decides who hears an event and an instance-only watcher gets the notice with `offline` false. `offlineFor` rows carry `instance` for those, and `panelAlarm` echoes it. A dead peer with no FIN is caught by `KeepAliveListener` (TCP keepalive, about 5 s) and then the 8 s grace; `TestChromeClosedPanelTabIsLostInsideFifteenSeconds` runs a closed tab on the real clock. The panels page polls every 2 s (`MON_POLL_MS`) instead of having a push channel.

Panels page extras (`panelmonup.go`, `panelsmon.js`, rules in `panelsrules.js`):

- Uptime: each instance keeps its `up` and `down` changes for 24 hours (`monHistory`, the same as `monForget`, so a longer window would describe instances already dropped) and at most 400 of them (`mark`). The down time is `seen` plus the instance's limit, not the sweep time. Instances go out with `uptime` (`from`, `to`, `start`, `trans`), and the strip is drawn with `uptime.js` and `uptimebars.js`, the same code as the /log graph, against the server's `to` so the browser clock does not shift it. Before an instance was first heard the strip is grey (no record). Bars on /panels are plain marks, not buttons: `paintOpenNow` skips its rebuild while focus is inside `#panels-open`.
- Hide: per user, in memory, in `panelMon.hide` next to `clear`, keyed by watch key. A hide ends no key and no watch and other users still see the instance. It is lifted when the device is next heard after it was lost or forgotten (`touchLocked`), and dropped by `forget` and `forgetDevice`, not by the 24 hour drop, so a hidden watched instance does not come back as a not-seen row. Not persisted, since the instances it hides are not. `hiddenInstances` is the caller's own; "Show them" lifts every hide of the panel.
- Status: `instancesOnline` and `instancesKnown` go to every reader, counted for the caller (known instances plus instances they watch by name, less the ones they hid). `panelStatus` reads All Online, Some Online or All Offline; no instance at all is All Offline. `online` is unchanged and still drives watches and alarms. Communication Log rows from a panel (takes, stream, lost, back, alarm) carry the panel's short name and the instance; docs/agents/comm-log.md has the headers and wording.

## Assign

- The key goes down the stream, never in the REST answer, and is made only once the stream is known to be held. It goes to the device's newest stream only (`sendNewest`, `sendKeyless`), since anyone who may use the panel can hold a stream under any device name. The handler answers on the line's `got` channel whether it wrote it, and a closing stream answers false for a line still queued (`unsent`); the Assign waits (`written`, `lastWait`), and when no stream wrote the line the key is dropped and the Assign answers 409. A name the target already holds, as a key or as any instance Sode holds (`heldNames`, shared with Rename), answers 409 `name_taken` with `error.suggest` (`suggestInstance`), because `replaceInstance` would rotate another device's key away; the request's `name` sends it under another. The cap is checked first, so a full target never offers a name. `jsonCall` copies `suggest` onto the thrown Error, and `clashOf` reads it.
- The page stores the key under the segment of the address it opens (`assignAddress` in `panelassignrules.js` returns it), since `storedKey` reads by address segment, not by panel id. With storage that does not read back, the key rides `#key=` instead, as `keepLinkKey` does.
- A target that acts as a user (`as` `user`, the default for a Session-mode panel, a choice for `both`; `assignBySignIn`) gets no key, no name-clash or cap check and no rollback: the line carries `signIn` `user` and no `key`, and `followAssign` forgets any key stored under the target's segment, since `panelrun.js` would open a `both` panel as its client with it. A device signed in as a user keeps its session there. Instance rows carry `trusted` (the user's flag, live in `monFields`) so `assignRows` can mark `notShared` with the same rule as `panelReach` (`opens`; keep in step), and the modal asks Send anyway first.
- Instance rows carry `page`, `addr`, `signIn`, `user` and `streamSince` from the last stream the device opened (`openStream`). `page` is kept apart from `streamed`, because a keepalive clears `streamed` and a timed-out page must still be told from a keepalive-only API client. `streamSince` is set when the device goes from no stream to one, so a second tab does not reset it and a reload does. The list shows uptime in whole minutes (`uptimeText`), since `paint` redraws only when a row's text changes.
- The Assign to list's Find box (`rankAssign`, `stepRow`, `enterRow` in `panelassignrules.js`) reuses `wordScore` and `stepPanel`, and its keys come from `resultStep` as on the panels list. The highlight is a row `key` (`panel\ndevice`), kept while the row is listed, else the first row. The list redraws only when rows, busy or the highlight change.
- Keyless instances (`panelkeyless.go`, ADR 0009): `panelMon.keyless` and `addrs` sit apart from `inst`, so they never count as instances, uptime or alarms; panel reads carry them as `keyless`, and `assignRows` lists them beside `instances`. The route is `scopeOpen` and must answer alike for a panel that does not exist. An Assign of one names `keyless`, sends to its newest stream only (`sendKeyless`) and checks `networkAllowed` against the address `clientIP` saw. In the page, `announce` in `panelrun.js` starts before the first read (a Session-mode page waits there for a sign-in), on a 401 at open or from a poll (`ended` only for `key_revoked` or `key_expired`) and on a session key's `ended` step, and `unannounce` runs when the keepalive starts and in `run.stop`. The stream carries no session or user: a device signs in over the page socket, which the idle clock covers. The Chrome check is `TestChromeKeylessPageIsAssignedAndRuns`.
- Rename (`panelrename.go`): the name clash reuses `nameTaken`, `suggestInstance` and `heldNames`: the client's key names and `deviceNames` (offline ones too, since reusing a lost name would read as that instance coming back). The clash check and key rename happen under `cfgMu` and the send after it, as in an Assign; the rename line goes to every stream of the device (`sendEvery`), and when none queued it the key's old name comes back. A refusal with `trusted_required` shows the Advanced Settings PIN field beside the name (`renameRefusal`). There is no cap check, since a rename adds no key. `followRename` moves per-instance watches. In the page, `hold` returns on a `renameOf` line and `renamed` in `panelkeepalive.js` writes `sode-panel-device`, or rewrites `?instance=` for a page named by its link, then restarts the keepalive. The browser check is `TestChromeRenameARunningPanelPageFromThePanelsPage` (two browsers, since the panel page cannot be framed).
- An Assign reads the target and never writes it, so `settings.fixedDests`, `acts` and `rev` stay. The editor's Authentication mode Confirm does not run for an Assign, since no panel's mode changes.

## Gotchas

- The editor's Test it live runs `runPanel` embedded (`editorlive.js`): `panelmount.js` builds the same elements as panel.html inside `#ed-live-view`, calls go through the editor's `sessionFetch`, and there is no keepalive, device name, kiosk, wake lock or title change, so it never shows as an instance. A panel that acts as an API client is tested with the user's own Rights, not the client's. The Share button is in the editor toolbar (`#ed-share`); `editoraccess.js` wires it.
- Routes for sets and templates are `/panel-sets` and `/panel-templates`, not under `/panels/`. Go's mux reports a conflict between `DELETE /panels/templates/{id}` and `/panels/{id}/key`.
- The glossary scan rejects every word on a `_Avoid_` line, in docs and UI strings alike, and only a few are exempt in backticks. Check GLOSSARY.md before choosing a word. It fails only in the full `go test ./...`, because `TestDocsUseGlossaryWords` and `TestUIStringsUseGlossaryWords` scan the whole tree; a `-run` on one panel test will not show it.
- `panelRows` in `web/panelpage.js` is the rows of a grid. Its name collides with a retired phrase, so it has an `identAllow` entry; keep it when moving the code.
- Web modules are capped at 1000 lines (`imports.test.mjs`). The editor and panels page are close; split by concern before crossing.
- Page rules on the panel page: `panelnav.js` decides (`landingPage`, `stepPage`, `goToState`, `navTarget`), `st.page` holds the current Page's id, and `pressPage` changes only that. `panelrun.js` rebuilds the grid from `drawnCells(panel, pageIndex(...))` on a Page change (`showNewPage`) and on a live update, where `carryView` is given every Page's cells so a Destination viewed on another Page survives. `paintGrid` needs `pages` and `wrap` in its context, or every navigation cell reads as going nowhere. `pagekeep.js` holds `sode-panel-page-<panel id>` (keyed by id, not by the address's short name); an embedded run skips it. The editor's grid paint takes `pages` too, for a Go to Page cell's text and the dashed deleted target, and the Cell tab's warning reads Page 1's cells from `storedGrid()` (`firstGrid`). `checkPageTargets` (Go) and `ITEM_FIELDS` (`gridmodel.js`, a kind change drops `page`) keep in step with them.
- Page Name and Info (`web/pagecells.js`): `pageCellText` takes the id of the Page the cell sits on, `st.page` on the panel page and the drawn Page's id in the editor (`paint`'s `page`), never Page 1. `show` is the stored list, checked by `checkShowParts` (Go); `SHOW_PARTS` keeps in step with it, and `ITEM_FIELDS` drops `show` on a kind change. The Cell tab's boxes are `editorshow.js`. Test it live passes the focused Page to `runPanel` as `page`.
- Fixed destination on the panel page: `createState` makes `fixed[0]` the view, so `currentSource`, the Current cell and `sourceState` read it, and `clear` puts it back instead of null. `carryView` returns the new state untouched when it has a list, or an old Destination cell could overwrite the new view. Destination cells are dropped by `drawnCells` (`panelrules.js`) in `panelrun.js` only; `cellsIn` stays whole, since the editor and the thumbnails use it and must keep stored Destination cells. There is no list of the fixed destinations on the page (a strip was removed on request), so a Result shows only through the Current cell and the router. Rules tests are `web/test/panelfixed.test.mjs`, the browser check `TestChromePanelFixedDests`.
- Editor clipboard: the block rules are `gridclip.js` (`copyBlock`, `readBlock`, `pastePlan`, `applyPaste`, `pasteNote`), the clipboard I/O is `editorclip.js`. On a plain HTTP address other than localhost `navigator.clipboard` is missing, so copy falls back to `execCommand('copy')` and paste reads the browser's own `paste` event (no permission prompt): the paste chord's command returns `false` so `onKey` leaves the key to the browser, and `readText` runs only when no paste event followed. A synthetic key fires no paste event, so a Chrome check either stubs `readText` or dispatches a `ClipboardEvent` (`TestChromeEditorCopyPaste`). Cut is `cutCells` in `paneleditor.js`: `copyCells` (which returns whether the write worked), then one `setGrid(clearSelection(g))`, the step an undo wraps. It removes nothing when the write fails or `g` moved during the await, and held Destination cells are out of `g`, so they are never copied or removed. A paste is one `setGrid` in `pasteText` (`paneleditor.js`), the step an undo wraps; a plan that does not fit goes to `pasteOverflow`, which opens `askPasteEdge` (`editorpasteedge.js`) over `edgeChoices` (`gridedge.js`, both choices worked out first so the dialog can count them) and applies the pick as one `setGrid`. Find hands its order in through `editor.useFillOrder(api.order)` at the end of `initFind`; Wrap reads it at paste time. `leave` ignores focus inside `#ed-edge`, or opening the dialog would deselect the grid and Cancel would not be a no-op. Wrap walks the whole grid's `squareOrder` from the paste square to its last square and returns the cells left in `left`; `edgeChoices` given `{ pages, from }` hands them to `cascadeWrap`, which fills later enabled blank Pages. `pasteOverflow` applies the choice inside one `edit` that also replaces the other Pages' cells, not through `setGrid`, so the paste and its cascade are one undo step. A Find fill does not cascade yet. `TestChromeEditorPasteEdge` drives Escape, Clip by the arrow keys, Wrap, undo and Find's order. `pastePlan` drops skipped Destination cells itself, since passing them to `setGrid` would put them in `held` and store them.
- Editor Pages: `g` is the focused Page (`focus`, its id) and `pages[fi()].cells` is stale while it is; `livePages()` is the list with them fresh, and is what `pages()`, saves, the dirty check and painting read. `open` is the ids side by side. `#ed-grid` always draws the focused Page, so Find, the grip, the menu and the paste reader keep their one node; `editorpageview.js` draws the others in a pool of three grids made once (each `createEditorGrid` adds document listeners, so never per open) and places every frame with CSS `order`. A press on another open Page calls `focusPage` and moves DOM focus to `#ed-grid`; only the press counts, not a drag that began there. `leave` ignores `#ed-open-pages`. Only an unsaved Page 1 has id `''`; the first save gives it one and `rekeyUndo` moves the undo steps to the new id. Page ops (`pageActs`) replace `pages` outside undo. A template apply is `replacePages(list, grid)`, a `list` step. The smart menu sits beside the selection and can cover the next Page's squares; the Chrome check presses Escape first.
- Editor undo: `edit(what, run, { join, list })` is the one place that records (rules in `gridundo.js`); `setGrid(next, { what, join })`, `setSize`, Copy to and `replacePages` go through it. It takes a `pageSnap` (every Page's cells by id, held Destination cells included) before the edit and records only when `samePages` says some Page's cells changed, so selection moves and no-op edits store nothing. `what` is the status line's name for the step ("Undid <what>."), `join` merges a run of edits into one step (the Cell tab's caption and font size typing). A new caller that edits cells passes a `what`; a paste past the edge (Clip or Wrap) is one `setGrid(next, { what: 'paste' })`. `step` restores outside `edit` through `restorePages` (by id, so a Page added since keeps its cells and one deleted since stays gone; a `list` step puts back the whole list) with `held` emptied first, so `holdOrPutBack` sets the Destination cells aside again; `show` empties the stack, `save` does not. `TestChromeEditorUndoRedo`, `TestChromeEditorPages` and the tail of `TestChromeEditorFixedDestsSaysWhatIsDropped` drive it.
- Fixed destination in the editor: while the list is not empty `paneleditor.js` keeps Destination cells in `held`, out of `g`, through `holdOrPutBack` in `setGrid`, `setFields` and `show`; `whole()` is the focused Page as stored, which `livePages()` reads. Other Pages are stored with their Destination cells and drawn with them set aside. Grid code never sees a held cell, so don't add a path that sets `g` without going through one of those three or `step` (undo and redo). `myRights` is caught at import time in `editorrights.js`, which Find and the picker share.
- In a worktree the lint hook's `go vet` prints noise about the package path. It is not a real failure; run `go vet ./...` from the worktree root.
- Panel pages sit at different URL depths and use `<base href="../">`. They share the `panel` page lock.
- Status on panel pages is an icon first, with optional text. This exception is in AGENTS.md and nowhere else in Sode.
- Panel theme is `settings.theme`. The panel page sets `data-theme` on `html` (`setTheme` in `panelrun.js`) and `auto` restores what the page started with. The editor cannot do that for one panel inside its own page, so `editorpanel.js` sets `color-scheme` on `#ed-grid` instead: patchbay's tokens are `light-dark()`, so the preview switches and the rest of the editor keeps the user's theme.
- The smart menu stays open for the sidebar's sake: `leave` in `paneleditor.js` exempts `#ed-side` from deselecting, because the Cell tab edits the selected cell. A sidebar click sets `menuAway` instead, which makes `refresh` pass `null` to `menu.show`; a grid click or key clears it. Don't make the sidebar deselect, and don't hide the menu by other means (the grip and Find read the same selection box).
- Find's flyout is positioned by patchbay CSS (`pb-menu__sub`, absolute beside the `li`) and then shifted with `style.translate` by `fit()` in `editorfind.js`. `fit` runs after `draw`, so a list that grows is re-fitted; a new place that opens or resizes the flyout must call it too.
- The Artwork flyout (`editorarttool.js`) shares Find's fill order through `setOrder(id, { focus: false })`; without `focus: false` a pick there moves focus into Find's box and the Artwork flyout closes. Its preview draws each square through `withDefault` and `artNode`, never from the `art` string, so any Icon A that is not a sprite icon gets the Icon B badge. Like Find, it refocuses its last choice after the menu rebuilds and calls `fit()` on open, hover, focus and rebuild.
- The smart menu stays inside an area, not the viewport: `menuArea` (`editorrules.js`) cuts the viewport at the sidebar's left edge while the sidebar sits beside the grid, so a selection in the last column puts the menu on its left instead of over the Cell tab. Each flyout (Type's list, Find's panel) then picks its own side with `subSide` (`placeSubs` in `editormenu.js`: the menu's side when it fits, else the other), measured with the flyout shown but invisible for a moment, and the `li` carries `data-sub-side` for the arrow key that enters it. `TestChromeEditorMenuFlipsOffSidebar` walks every column at 1600 px.
- `artNode` (`panelview.js`) is the one artwork renderer: a `.sode-panel__art` row (a size container) holding `.sode-panel__art-a` (icon or image) and `.sode-panel__art-b` (the glyph). The editor square, the sidebar preview and the panel cell all use it, so a change there shows in all three. `textHidden` counts Icon B as artwork. Callers read Icon B through `artBOf`, never `artB`. Beside a vendored icon, A takes 40% of the row and B 60% (`:not(:only-child)` rules in `panels.css`; a two-character glyph carries `--wide` so its font fits); alone, either fills the row. When Icon A draws as an image, the row carries `--fill` and the image fills it with contain (never cover), and Icon B carries `--badge` and sits in the top end corner on a plate. `artBBadge` (`panellook.js`) decides the badge for any Icon A that is not a sprite icon, so library icons and Default artwork drawn as images get it through `artNode` with no change of their own. Hidden text draws the row at full strength (`[data-hide-text] > .sode-panel__art`), so the preview sets that attribute too.
- A library icon is `lib:<id>` in `art`. `artOf` gives `{id, lib: true}`, never `.icon`, so `artNode` draws it as an image with the Icon B badge, and `artUrlPath` sends it to `/icon-library/`, so `createArt` fetches and revokes it like any artwork. Only the fetch knows whether it is an SVG, so `createArt`'s `look` gives the blob's type with its URL, and `artImage` (`panelview.js`, also used for the picker tiles) swaps the `img` for a `span.sode-panel__art-mask` with the blob URL as `mask-image`. A panel's own and Default artwork SVGs stay `img`s in their own colours. The editor's Uploaded section (`editorlib.js`, rules in `iconlibrules.js`) draws its tiles through the panel's `ed.art()`, so before the panel is first saved a tile shows its name's first letter; it keeps its tiles in their own grid (`data-lib`), since the search and `aria-pressed` loops in `editorart.js` read the vendored grid's `aria-label`s as icon names. `panelImage` there tells a panel's own picture (Remove Image) from an icon (Remove Icon). Manage shows from the `access` event's `trusted`; after a delete the section calls `createArt(...).forget('lib:<id>')` (one blob URL, not `revoke()`), `ed.refresh()` for the canvas and `gone()` so the Cell tab's preview draws again with the same value. Its Confirm box stops its own keydown, so the letter never reaches the grid's Delete and arrow keys.
- Default artwork is resolved only for drawing: `withDefault` (`panellook.js`) returns a copy with the default's `art`, `artB` and `hideText`, and `panelrun.js`, `editorview.js` and the Cell tab call it before `artNode` and `textHidden`. Never put its result into the editor's `g` or a saved panel, or the default freezes into the cell. A default image id starts `d-`, so `artOf` gives `{id}` (an image, badge and all) and `artUrlPath` sends it to `/default-artwork/images/`. `artDefaults` is output only (`panelKnown`). The Cell tab's controls show what the cell stores, except Hide text, which shows as drawn; `hideText: false` is stored only against a default.
- The panel page's `paintGrid` must never detach a cell's artwork: a sprite `<use>` that is removed and re-added re-resolves its sprite and blinks on every one-second redraw. The row is appended once in `buildGrid` and `fill` replaces only the other children, and only when they changed, so an idle cell sees no DOM mutation (`TestChromePanelArtHolds` watches one with a MutationObserver). Keep every paint function on `fill`, never `replaceChildren`.
- The editor's level picker (`editorlevels.js`) is the main page's: `pickButtons` from `levelview.js` over `S.levels`, which the page's socket fills from the hello (not `/api/v1/tally`), with its CSS in `base.css`. The sidebar redraws it on the `hello` event.
- The pulse (`--pulse` in `panels.css`) is a registered inherited property, so animating it restyles everything below it every frame. It runs on `.sode-panel__grid:has(...)` only while a cell pulses, never on `:root` (that idled the editor at 27% CPU with renderer memory growing). `TestChromeEditorHoldsNoMemory` checks the editor runs no CSS animation and a staged live panel runs the one; `panellook.test.mjs` pins the CSS.
- Things a page makes per open or per run must be let go: `trapDialog` drops a hidden dialog from its Esc stack (a held modal root kept a copy of the icon sprite document alive per Share open), `createArt(...).revoke()` frees blob URLs when a panel or live run ends, and `start` in `panelrun.js` returns after each await when `run.stop()` already ran. The harness that found them is `paneleditormem_browser_test.go`: a probe counts intervals, document listeners, object URLs and fetches, and `Memory.getDOMCounters` counts nodes and documents.
- Icons are local `<use href="#pb-i-<name>">` (docs/agents/web-layout.md): an external sprite `<use>` made per redraw is what grew the run page by gigabytes. `TestChromeRunPageHoldsNoMemory` checks it.
- The Lock button bar is `position: fixed` top left on every page and adds no height. On the desktop layout `panels.css` keeps the header row clear of it with `padding-inline-start` from `--sode-who-w` (the bar's width, set by a `ResizeObserver` in `lockchip.js`), so the grid, the Panels link and the status line never move when it appears. It hides for a kiosk (`data-sode-kiosk`, set by `applyLook` in `panelrun.js`).
