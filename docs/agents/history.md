# History, ext and External follow

Moved from AGENTS.md unchanged.

JSONL history plus a shared server recent/undo list. Routes made elsewhere are ext entries (ext*.go).
- Ext: Connected messages none of our takes sent, plus found entries (#57): a tally differing from a known cached value that isn't a take in flight or one that just gave up (awaited, late keys for 5s). Found entries are never an External follow and are grouped apart.
- own holds each take's (dst, router level, src); the router's answer uses a key up, so the same route made elsewhere right after still logs. Changes gather into bursts (500ms quiet or 3s total), one entry per dst+src; a burst over several dsts shares a group.
- External follow (#53): an ext change of the same src to another dst within 500ms of one of our takes (waiter.cause, a.causes). Of several, the latest last confirm wins. Changes at a router panel are never followed. In a multi-take confirm followers carry followGroup and histRows lists them as f.followers (not in f.entries, so Undo all leaves them; keyboard stop w<group>). Otherwise follow = the take's ID, ungrouped, shown as e.follows unless filters hide the take. Undo plans carry the External follow as plan.extra, sent only if the confirm's box is ticked. A burst that might follow a take in flight waits for it (extAwaitsTake) once its connects went out (cause.sent). An undo confirm flags levels where dst no longer has the undone take's source (changedSince).
- Same-dst same-levels ext entries within 30s merge (merged count, chain); any other entry on that dst breaks the chain. stackSteps shows a stack as a timeline with Restore (restorePlan).
- histRows applies this browser's filter (filterstore.js, sode-filter). Groups keep all entries in f.entries, visible ones in f.shown.
- Stacked sets (#131): set buttons toggle. One set is sode-filter-active. Two or more are a stack, sode-filter-stack [{scope,name}], no active set. stackAllows (filter.js) judges per set; pref setStack: and or or. useSets is the one builder, setActive the one writer, setFilter the edit path (leaves the stack), snapshot/restore for share-link Undo. The dialog shows "A + B", edits the first, disables Save as and share while stacked.
- Filter language: web/filter.js, pure, no imports; the server's hiddenDsts uses it too. Sets come from built-in All, cfg.filterSets, localStorage sode-filter-sets; active is sode-filter-active {scope,name,base}; followGlobal() on hello applies a changed global set unless the browser edited it. Names unique per scope ignoring case.
- Quick search: not kept, doesn't merge rows, reads 500-entry pages (server caps at 500). Ignores the filter unless sode-search-filters is on.
- Redo (#153): every row and Group has one Retry/Redo button (againPlan in plans.js, againButton in widgets.js). Failed takes retry (a Group retries just failures); everything else redoes src to dst on its levels as a new take, including undo, ext, found, follow rows. Skipped with no real source or level (canRedo). Frontend only. Undo/Redo/Retry are outlined pb-btn--sm; Undo has undo-2, Redo redo-2, Retry text only; phone swipe Undo hides the icon in CSS. Verb wording in VERBS (plans.js); only patch resets the boxes. Confirm shows Already there (alreadyThere) when dst has the source on every level. Keyboard r does what the button says.
- Desktop History sits apart from the patch boxes by a thin divider (end of history.css); the phone has none.
