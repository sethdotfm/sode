# History, ext and External follow

JSONL history plus a shared server recent/undo list. Routes made elsewhere are ext entries (ext*.go).
- Router: `App.record` gives every entry `router` (the router UID) and `routerTitle` (the title at that time). Thus an entry still names its router after a rename or delete. Without SODE_CONFIG the UID is new on each start, so do not match an entry's `router` against the running router's UID.
- Step in: a take made while stepped in has `browserOf` (the original user, or the address) beside `client` (the stepped-in user). Filters and `actorUser` read `client` only; `byText` shows "by Bo (browser of Ana)". docs/agents/users-locks.md.
- Ext: Connected messages that none of our takes sent, plus found entries (#57). A found entry is a tally that differs from a known cached value. It is not a take in flight or one that recently gave up (awaited, late keys for 5s). Found entries are never an External follow and are grouped apart.
- own holds each take's (dst, router level, src); the router's answer uses a key up, so the same route made elsewhere right after still logs. Changes gather into bursts (500ms quiet or 3s total), one entry per dst+src; a burst over several dsts shares a group.
- External follow (#53): an ext change of the same src to another dst within 500ms of one of our takes (waiter.cause, a.causes). Of several, the latest last confirm wins. Changes at a router panel are never followed. In a multi-take confirm followers carry followGroup and histRows lists them as f.followers (not in f.entries, so Undo all leaves them; keyboard stop w<group>). Otherwise follow = the take's ID, ungrouped, shown as e.follows unless filters hide the take. Undo plans carry the External follow as plan.extra, sent only if the confirm's box is ticked. A burst waits for a take in flight (extAwaitsTake) when it is possible that the burst is the External follow of that take. It waits after the take's connects went out (cause.sent). An undo confirm flags levels where dst no longer has the undone take's source (changedSince).
- Stacked rows: histRows merges changes to one dst on the same levels when each comes at most stackGapMs() (pref stackGap, history.js) after the one before. stackGap is a This browser pref like setStack: 0 (off), 10, 30 (default), 60, 120 or 300 seconds, kept as text in `sode-stack-gap` and `browserDefaults.stackGap`. 0 never stacks. This is the gap between neighbours, not the whole span, so a monitor punched all day stays one row. Any instance stacks: Sode takes from any browser, panel or API client, and ext entries (merged count, chain). A failed take, an undo or Restore, a Group, a follow, a hidden entry or any other entry on that dst ends the row. Found and announced entries do not mix. No search merges. Frontend only: no wire field, and the only persisted value is the pref. The row shows the oldest prev (stackBefore, stackFrom) "to" the newest src, ids `#oldest–#newest` and a count on the disclosure. stackSteps shows each change as a timeline with Restore (restorePlan). Add from History picks the newest, which is the row's end state.
- histRows applies this browser's filter (filterstore.js, sode-filter). Groups keep all entries in f.entries, visible ones in f.shown.
- Stacked sets (#131): set buttons toggle. One set is sode-filter-active. Two or more are a stack, sode-filter-stack [{scope,id}], no active set. A Me set's ref also holds its user. stackAllows (filter.js) judges per set; pref setStack: and or or. useSets is the one builder, setActive the one writer, setFilter the edit path (leaves the stack), snapshot/restore for the Filters dialog's Cancel. The dialog shows "A + B", edits the first, disables Save as while stacked.
- Filter language: web/filter.js, pure, no imports; the server's hiddenDsts uses it too. A filter set (config.FilterSet `router`) and hiddenDsts (`hiddenDstsRouter`) carry an optional router UID. Blank is the one router. With a router, compileFilter's number and range terms match only an entry on that router. The matcher gets the entry's router as its third argument. filterAllows passes the entry's router, else the hello's routerUid. routerTermsProblem is the rule for a second router: a set with no router allows only name, exact and regex terms. Nothing calls it while there is one router. Sets come from built-in All (id `All`), cfg.filterSets, Profile.filterSets and localStorage sode-filter-sets {id,name,f}. Each set has a hidden id, as a preset has (config.FilterSet `id`). Normalize gives a blank or repeated id a new one, and WithFilterSetExtras gives a set sent without an id the saved id of its name. The page makes This browser ids and a new set's id (newPresetId). The active set, a stack, bookmarks and Palette picks name a set by scope and id, so a rename moves nothing. Active is sode-filter-active {scope,id,base}; followGlobal() on hello applies a changed global set unless the browser edited it. Names unique per scope ignoring case.
- Quick search: not kept, does not merge rows, reads 500-entry pages (server caps at 500). Ignores the filter unless sode-search-filters is on.
- Loaded entries stay bounded (history.js `trimHist`). Clearing a search drops S.hist back to the newest 200, whole Groups. So does a live take that brings it past 1000 (`HIST_CAP`) while no search runs and no pager shows past 200. `histMore` is then true, so Load more reads the rest again. The desktop page redraws History once per frame for a burst of `recent` messages (desktop.js).
- Redo (#153): every row and Group has one Retry/Redo button (againPlan in plans.js, againButton in widgets.js). Failed takes retry (a Group retries only failures). Everything else redoes src to dst on its levels as a new take, including undo, ext, found, follow rows. Skipped with no real source or level (canRedo). Frontend only. Undo/Redo/Retry are outlined pb-btn--sm; Undo has undo-2, Redo redo-2, Retry text only; phone swipe Undo hides the icon in CSS. Verb wording in VERBS (plans.js); only patch resets the boxes. Confirm shows Already there (alreadyThere) when dst has the source on every level. Keyboard r does what the button says.
- Desktop History sits apart from the patch boxes by a thin divider (end of history.css); the phone has none.
- Protect entries (protect.go): `protect` is `set` or `clear`, `src` is -1 and `levels` is every level. `still` names the levels Sode still holds after a failure. They never stack (`stacks` in history.js) and have no Redo. Their Undo is the other one (`protectRow` in protects.js, `undoPlan` in plans.js), offered only while it is Sode's own. Ctrl+Z skips them, since it undoes the last take. The API's History Undo, Redo and Retry answer 409 for them.
