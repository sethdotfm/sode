# Web layout: modules, keys, layouts

- Control heights (base.css): there are three, and one for the Confirm button. `--sode-h-field` (4rem) is the big patch boxes. `--sode-h-action` (2.5rem) is for anything used live: patching, panels, Take, chips and list rows that take a press. Nothing used live is lower. `--sode-h-compact` (2rem) is for toolbars and forms away from the patch flow. `--sode-h-confirm` (3rem) is only for the churning-letter Confirm button. On the desktop layout base.css sets patchbay's control sizes from them. A plain or small control is compact, a large one is an action and an icon button is square. A page part used live lifts its buttons to the action height with a `:where()` rule (`#patch-view` has one). Then a button with its own size keeps it. A History row is the press target and is an action high, so its buttons stay compact. The phone keeps patchbay's own sizes.
- Root size (base.css, top): html font-size is 100%, and 90% on a Grid panel page and its Live Editor. The Live Editor of a Grid panel gets it when it starts (`data-live="grid"` on `.sode-ed`, editorlive.js). Its grid comes after a fetch, and the Edit lists drawer must not move then. The phone is 100% on every page. On the desktop layout a window wider than 2400 px is a big screen with no OS scale. There `@media (min-width: 2400px)` adds 1px to the root for each 360 px over 2400: `min(125%, 100% + (100vw - 2400px) / 360)`. That is about 103% at 2560 px and 125% at 3840 px and wider. The Grid panel page grows the same way from 90%, to 112.5% (`/ 400`). At 2400 px there is no step. A 4K screen with an OS scale of 150% or more is 2560 CSS px wide or less. It changes little or not at all. Media queries use 16px rems, not the root, so no breakpoint moves. JS that changes rem to px reads the root's computed font size (editorrouterlist.js, lock.js). bigscroll.js measures its bars and needs no change.
- Main page width (base.css `--sode-main-w`): `.sode` is 75rem wide at most up to a 1920 px window. On a wider window it keeps 69rem of side space, so it is about 64% of a 3840 px window. Compact view and the side pad for the icon bar (desktop.css) use the same width. Help text and other running text keep their `ch` limits.
- Big scroll bars (bigscroll.js, rule in AGENTS.md): Firefox cannot set a scroll bar's width, and macOS overlay bars show only during a scroll. So Sode draws its own bar, a track and a thumb in a `.sode-bigscroll` div, 1.4rem wide (`--sode-bigscroll-w`). That is the big size, the default. The little size (`.sode-bigscroll--little`, `--sode-littlescroll-w`, 0.7rem) is for small secondary lists where a big bar hides the content. Use `{ size: 'little' }` in `bigScroll`, or a third `'little'` entry in `SCROLLERS`. The page's bar is always big. Little today: the History filter match lists (`.sode__search .sode__menu`), the sign-in name list (`.sode-namepick__list`), the filter sets row and the key lists in dialogs. The panel editor's Pages list (`.sode-pages__list`) is little too. Put a little entry before any broader big entry, since the first match wins. `[data-bigscroll]` on the scroller hides the native bar (base.css). The bar shows only while there is something to scroll. While it shows, the scroller gets padding for it, so the thumb never covers a row. Drag the thumb, or press the track to page (hold to repeat). A wheel over a sideways bar scrolls it sideways. Pointer events, so touch and pen work too. The bar has `aria-hidden` and no tab stop, because keys already scroll. pointerdown and mousedown on it keep focus, so an open match list stays open.
  - `bigScroll(el, axis, size, { watch })` draws one bar, or two for axis `'xy'`, and returns `{ update, now, stop, bar, room }`. The bar is the scroller's next sibling, placed over its inside edge. A static parent gets `.sode-bigscroll-host` (position: relative). The page's own scroller (`document.scrollingElement`) gets a fixed bar at the window's right edge. While it shows, html gets `data-bigscroll-on`. On the desktop layout html keeps the bar's room (`padding-right` and `--sode-page-bar`) while the bar is hidden too. So the page never moves sideways when the bar shows or goes. A Grid panel's Live Editor never scrolls, so it keeps the room only while the bar shows. Fixed items at the right edge use `--sode-page-bar` to keep clear of the bar (`#conn`, the pick bar, the Settings sections).
  - Axis `'xy'` (the Grid page) draws a bar on each axis, both big, and a `.sode-bigscroll__corner` square where they meet. Each bar is shorter by the other's thickness while the other shows. One layout pass decides both, since the side gutter can make the grid overflow across. `room()` gives `{ right, bottom }`, the px of the shown bars in the client box. A drawn bar is on the client box, but a native bar is outside it. gridpanelview.js takes it off `clientWidth` and `clientHeight` in `read()`, so the window maths, `cellAt`, `hit` and `bodyBox` stop at the bars. `now()` lays out at once; `setAxes` calls it before it sizes the pools, since a pool never shrinks. `watch` is an element whose size changes with the content. It replaces the subtree MutationObserver: on the Grid, crosspoint writes would run a layout each time. The Grid scroller has `isolation: isolate` on the desktop layout, so its sticky bands never paint over the bars. The bars are siblings of the scroller, so the Grid's own pointer and wheel listeners never get a press or a wheel on them.
  - `bigScrollAll()` runs on the main page (main.js), /log (log.js), /panels and the editor (panelpage.js), but not on a panel page. The Grid page calls `bigScroll` itself (gridpanelview.js). It draws the page's bar and one on each `SCROLLERS` match, also on ones added later. A bar goes when its scroller leaves the page. On the main page, `SCROLLERS` holds the match lists (`.sode__menu`), the Settings search results and sections, and every dialog body. It also holds the Currently and Sending lists, and the Grid popup's staged list (little). It also holds the Inbox and Sent lists (`.sode-inbox__list`). It also holds the Presets list, the key list, the filter sets row, the Communication Log table and the Lock. It also holds the Levels box's picks (`.sode__box--levels .sode__levels`, sideways). They are the main control for levels, so their bar is big in a small box. The Lock does not make its own bar inert. In the editor, it holds the sidebar, the Pages list, the lists, the router lists, the icon lists, Find, Templates and the overview lists. It also holds the Artwork panel in the Live Editor's drawer. A new scroller that users need goes in that list.
  - After the bar is drawn, a scroll only changes the thumb's transform. No element is added or removed, so a MutationObserver on the content sees nothing. ResizeObserver (scroller, its parent, the body's children for the page) and a MutationObserver on the scroller's rows keep the size right. A sticky scroller also gets an update on each page scroll.
  - The phone layout keeps native bars (a touch screen scrolls the content). On the Grid page they are the thin styled bars in gridpanel.css. Geometry is in bigscrollrules.js (pure, node tests). `TestChromeBigScroll` checks it.

main.js wires modules then calls connect(). core.js is state/socket/bus (S, WebSocket, on/onFirst/emit/onMsg, el, fuzzy search, status helpers, nameProblem). It imports only tooltip.js, sprite.js, fuzzy.js and buildrules.js. The hello handler reloads the page when the build label differs from the first hello (buildChanged). prepaint.js runs first on every page: a browser without the `sode-format` stamp loses every `sode-*` key before anything reads one. Imports must not form a cycle (test/imports.test.mjs checks this, and that every import exists). ESLint enforces the keys.js and core.js import lists, and bans DOM and storage globals in web/*rules.js. Modules reach handle() through events (helloCfg, helloData, wsclose, onMsg), so a page only gets them if it imports the module. Tests import everything through web/test/all.mjs.

- Icons: `icon()` in core.js makes `<use href="#pb-i-<name>">`, and sprite.js copies that one symbol from `lucide.svg` into a hidden `<svg>` in the page. Static markup writes the same local href and `adoptIcons` brings its symbols in. Never point a `<use>` at `lucide.svg#...`. For every such `<use>` made, Chrome loads and lays out its own copy of the 370 KB sprite. It frees that copy only at a major GC. A panel's tick icon grew the renderer from 0.4 to 4 GB in two minutes. `test/sprite.test.mjs` fails on one. A name that starts with `sode-` is read from `web/sodeicons.svg` instead (Sode-owned, owner-approved). `sode-grid` marks Grid panels and the Grid popup button. Buttons panels keep `layout-grid`. Add one only with the owner's approval. A `#pb-i-` href means nothing outside the page, so an icon serialised out (export, print) needs its symbol inline.
- Panel pages (`panelrun.js`) apply the socket's tally frames (`tallyRows` from core.js) to the last `GET /api/v1/tally` (`paneltally.js`). After a hello, until the socket closes, the 2 s poll leaves out `/tally`. A check reads it every 60 s. The 2 s poll of the small reads stays, since it finds a revoked key or a lost Sode API. A hello, a `protectedRows` or `names` event, or a Router link change starts a poll at once. If the 60 s check differs from the kept tally, the page reads the tally every 2 s until the next hello. A Hidden caller's tally leaves routes out, so for that caller a frame only starts a poll. With the socket down the page polls every 2 s, as before.
- Service worker (`sw.js`, served by `internal/app/sw.go`): it keeps the app shell. So a main page or panel page that the device opened also opens while Sode is down. When Sode serves the file, it fills in `BUILD` and `SHELL`. `BUILD` is the version label and a hash of every web file. `SHELL` is every .js, .css, .svg, .png and .woff2 file. On install the worker keeps `SHELL`; on activate it deletes the other builds' caches and keeps the address of each open page. A page (`/`, `/panels`, `/panels/editor`, `/panels/<id>`) is kept by its path without the query. A page or a shell file goes to Sode first, and a new ETag replaces the kept copy. With no answer, or a 5xx from a proxy, the kept copy answers. It never keeps `/api` (so `/api/v1`, PINs, tokens and session keys), the WebSocket (the hello), `healthz` or `sw.js`. The rules are top-level functions that `test/sw.test.mjs` runs in a vm.
  - The skipWaiting and reload rule: a new build's worker takes over at once (`skipWaiting`, `clients.claim`). A page that started online has its files from Sode, and the hello's build check reloads it when Sode changes. A page that started while Sode was down (its socket closed before the first hello) has the old build's files. At its first hello `swreg.js` asks for the worker again (`update()`), and a `controllerchange` reloads it, so it never runs with a newer Sode.
  - `swreg.js` registers it from main.js and panelpage.js, only on a secure origin (localhost, or HTTPS through the user's proxy; README). The main page's Offline state is the lost-link banner and the socket's own retries. A panel page waits in `waitForSode` (`panelwait.js`) before it opens: the Offline cover shows and `healthz` is asked every 2 s. The Live Editor does not wait. `TestChromeServiceWorkerOpensWithSodeDown` checks both pages; `TestServiceWorkerIsFilledIn` and `TestServiceWorkerBuildFollowsTheFiles` check the served file.
- Socket freshness (#142): core.js keeps ws.lastRx (set on open and each message; test stub sockets need it). A 1s check drops an open socket silent for 15s; wsSend refuses one silent for 7s; drop(ws) reports at once and the page reconnects. sendTakes shows Not sent when wsSend returns false.

- Compact view (pref compact): html[data-compact] (prepaint.js, then device.js) and the desktop.css Compact view rules, desktop only. They hide #patch-view's History and make .sode a viewport-high grid with place-content:center. Then compactcentre.js nudges #patch-view so the patch row (the three groups, Source to Clear) is at the viewport's centre. The nudge is relative left/top from --sode-centre-x/y (centreNudge in compactrules.js, clamped to the viewport). The nudge is active only while that grid is. The rules also put #result out of flow below Presets, so a result never moves the boxes (the match lists already are out of flow). They shrink Presets and centre them under the boxes. All of that gives way while a preset picks takes from History (data-sode-pick=""). The Lock bar's bar and #conn fade with opacity over --sode-motion-reveal (250ms, 0 under reduced motion). They never fade with visibility, so hover and :focus-within still reach them. #conn fades only while it has sode__conn--ok, set by renderConn from connState().ok (both links up), never by prepaint. Each has a transparent ::before apron (6rem toward the middle, out to the viewport edges) so a pointer near the corner reveals it. The apron must stay off the patch boxes, Take and Presets, which TestChromeMainCompact checks. historyShown() in desktophistory.js mirrors that rule. While it is false, keyboard mode never starts (Esc with empty boxes does nothing, keys on the page body skip onListKey). When it turns on, focus moves out of History to Source. Alt+Shift+C writes the opposite of the resolved value to This browser, never '' (with Everyone on, '' would change nothing). It is chord 'alt+shift+c' in desktopkeys.js and works from any focus, including a box. preventDefault stops macOS Option+Shift+C from typing Ç. test/compact.test.mjs fails if another module binds it or the ? list shows it twice.
- Level picks on the desktop main page are small squares, 1.375rem (`--sode-pick-w` in desktop.css), always in two rows. levelbox.js sets the columns as `--sode-bar-cols`. The patch row is three groups of one width (desktop.css `.sode__boxes`): Source, Destination with + (`.sode__group--dst`), and Levels with Take and Clear (`.sode__group--levels`). An empty grid track gives the Levels group its wider gap. levelview.js sets `data-levels` (`on` or `off`) on `.sode__boxes` on each hello, and the CSS for a hidden Levels box reads it. The Levels text box is beside Take and Clear, and the picks go under all three (subgrid). Thus from 850 to 1600 px the picks show 9 columns (17 levels) and Select All. Below about 1100 px the Levels group keeps the room of its controls and is wider than the other two. More columns, or a narrower box, scroll sideways inside the picks with a big scroll bar. They show only whole columns (`round(down, …)` against the picker, a size container). They never wrap into a tall stack. Select All is two rows high and always beside the picks, in the same place. Only an odd number of levels makes the first pick two rows high (`sode__levels--odd`, base.css); with an even number every pick is a square. Compact view keeps the page width, so the boxes keep their width. `TestChromeMainBoxesLayout` and `TestChromeMainCompact` check 4, 5, 11, 12 and 17 levels (no scroll) and 24 (scroll).

The panel editor's level subset (editorlevels.js) is a setting, not a take, and keeps plain toggles.

- Tooltips (tooltip.js): before a patchbay CSS tip shows, `fitTip` measures its text in a copy. - Keys: Ctrl+Z (or Cmd+Z on Mac) undoes the last Sode take, except that a box with text keeps the OS text undo. Ctrl+, Settings. Ctrl+G (Cmd+G on Mac) Presets popup. Modifier rule: Control is for Sode commands on every OS (Ctrl+E, Ctrl+S, Ctrl+L, Ctrl+Shift+L, Ctrl+Shift+P). Ctrl+Shift+L is Sign out (or Step out) after a Confirm, on every page with the Lock bar (docs/agents/users-locks.md, Chip). `mod` is Ctrl, or Cmd on a Mac, and never the Windows key. The `mod` commands are undo, redo, save, select all, copy, cut and paste. They are also the list moves (Ctrl+J/K), Ctrl+G, Ctrl+Enter in the Destination box and Ctrl+Home/End on a grid. On the Panels list they are Ctrl+E and Ctrl+Enter. Cmd+G needs preventDefault to stop the browser's find-next. Alt is for bookmarks and for moving rows. Alt+1-9 opens the first nine bookmarks, and Alt+Shift+1-9 fills the boxes from a preset bookmark (e.code Digit1-9, presetkeys.js). In the Palette, Alt+B bookmarks the row. Alt+arrows, Alt+Home and Alt+End move a row in the Bookmarks editor and the panel editor's lists, and no other modifier does. Alt with Shift is for page commands: the theme key (Alt+Shift+T, themekey.js), Compact view (Alt+Shift+C), Keyboard mode (Alt+Shift+K) and the Home key (Alt+Shift+H). Every check excludes the other modifiers. Key labels are lowercase, with ⇧ where Shift is the only modifier.
