# Web layout: modules, keys, layouts


main.js wires modules then calls connect(). core.js is state/socket/bus (S, WebSocket, on/onFirst/emit/onMsg, el, fuzzy search, status helpers, nameProblem); it imports only tooltip.js and sprite.js, and nothing may cycle (test/imports.test.mjs checks, and that every import exists). ESLint enforces the keys.js and core.js import lists, and bans DOM and storage globals in web/*rules.js. Modules reach handle() through events (helloCfg, helloData, wsclose, onMsg), so a page only gets them if it imports the module. Tests import everything via web/test/all.mjs.
- Helpers: formbits.js (btn, opt, field, check, labeled, for the Manage users, My API keys and API settings modules), tabs.js (makeTabs, stepTab), globalsave.js (makeSaver is the one saver flow; globalSaver adds the PIN row and relock for save-for-everyone; profileSaver; profileProblem is the 48 KiB check), scopes.js (the one scope registry; setsIn, presetsIn), keyconfirm.js, trapDialog in widgets.js, owned.js, store.js (never-throwing readStr/writeStr/readJSON/writeJSON: use these, no hand-written try/catch), levelview.js, levels.js, routes.js, device.js, filterstore.js, history.js (histRows, quick search, pager, putEntry), plans.js (plans, planBlocked/planSummary, sendTakes, banners), widgets.js (levelBox, combobox, undo/retry buttons, disclosure, arrivals, feeding, labeled), pin.js, pinprompt.js (askPin/reask: the one prompt for an Advanced Settings PIN needed mid-session, see docs/agents/users-locks.md), banner.js (result banner; plans.js re-exports it), devicesettings.js (Settings' This browser section, my-default buttons, signed-in user block), settingstoc.js and settingspin.js (Settings' sections/phone pages and PIN fields), about.js (the Settings bottom row), shortcuts.js, keyboard.js (kbdUp), showall.js, settings.js (builds #settings-toc), filters.js (the Filters dialog and set bar), filtereditor.js (one filter's rule editor, editor(key, {read, write, mode})), searchbox.js (History's quick search boxes and emptyNote), filter.js.
- Icons: `icon()` in core.js makes `<use href="#pb-i-<name>">`, and sprite.js copies that one symbol from `lucide.svg` into a hidden `<svg>` in the page; static markup writes the same local href and `adoptIcons` brings its symbols in. Never point a `<use>` at `lucide.svg#...`: Chrome loads and lays out its own copy of the 370 KB sprite for every such `<use>` made and frees it only at a major GC (a panel's tick icon took the renderer from 0.4 to 4 GB in two minutes). `test/sprite.test.mjs` fails on one. A `#pb-i-` href means nothing outside the page, so an icon serialised out (export, print) needs its symbol inline.
- Socket freshness (#142): core.js keeps ws.lastRx (set on open and each message; test stub sockets need it). A 1s check drops an open socket silent for 15s; wsSend refuses one silent for 7s; drop(ws) reports at once and the page reconnects. sendTakes shows Not sent when wsSend returns false.
- Source ends (#138): srcEnd in routes.js decides if a source is pickable; srcRow, currentlyNodes and stackSteps all use it. Desktop history rows fill a box with useEnd (opposite box next); Receiving's pickSrc goes to Levels.
- planBlocked returns {block, prot} without touching the plan; pass prot to planSummary.
- Failed-take banner (failureBanner, refreshResult): one line per distinct outcome, tracks the takes' entries (takeResult carries entry), turns into a confirmation as takes are confirmed late or retried.
- desktop.js and mobile.js are the two layouts; desktop.js splits into desktophistory.js (History rows, pager, keyboard mode; owns that state) and desktopkeys.js (the document keydown handler), both built by factories taking desktop.js's hooks, never importing it (layout.js picks: auto on narrow touch screens, per-browser override; index.html applies the same rule before first paint). Phone: one input stepping Source, Destination, Levels; summary pinned at top; match list floating; number pad for Levels.
- Desktop keyboard mode: Esc with all boxes empty (or Esc on a History button) focuses #history and sets keysOn, cleared by any click. onListKey: s/d/f boxes, j/k rows (Ctrl+J/K, Cmd+J/K on Mac, work too, as in the match lists), J next group, K latest take, h/l or Enter close/open, u/r, comma settings, / Filters, Shift+S/D filter by boxes, ? shortcut list (also Ctrl+?). Groups auto-open under the cursor (autoOpen); .sode__key-note shows each empty box's key.
- Keys: Ctrl+Z (or Cmd+Z on Mac) undoes the last Sode take, except that a box with text keeps the OS text undo. Ctrl+, Settings. Ctrl+G (Cmd+G on Mac) Presets popup. Modifier rule: Control = Sode commands and match-list moves (Ctrl+J/K) on every OS; Alt = theme toggle (Alt+Shift+T), Alt+1-9 firing the first nine pinned presets and Alt+Shift+1-9 filling the boxes from one (e.code Digit1-9, presetkeys.js), and in the Presets popup Alt+P (pin), Alt+arrows and Alt+Cmd/Ctrl+J/K (reorder pins); Cmd belongs to the OS except Cmd+Z, Cmd+G (preventDefault stops find-next), Cmd+J/K and Cmd+Enter in the Destination box; every check excludes the other two modifiers. Key labels are lowercase with ⇧ where Shift is needed. Settings: Ctrl+J/K (Cmd on Mac) move the search results when the box is focused and has some (resultStep in keys.js, built on the listStep the combobox uses), else settingstoc.js steps sections; the search box handler runs first and preventDefault makes the stepper skip.
- Key plumbing: keys.js (imports nothing) exports mac (the one platform test; never repeat the regex) and chord(e), naming a keystroke the same way everywhere (alt+p, ctrl+alt+j, alt+3, shift+enter: modifiers in fixed order, then the physical letter or digit via e.code, arrows as up/down) and the one set of listeners for html[data-shift] and html[data-alt] (cleared on window blur). New key handlers match on chord(e), not hand-written modifier checks. presetkeys.js has the page-level preset keys (Alt+1-9, Alt+Shift+1-9, Ctrl+G / Cmd+G, the Windows/Linux bare-Alt keyup cancel); presetpopup.js only the keys while it is open. The panel editor's grid commands (Cmd or Ctrl with a letter) are one table, `GRID_CHORDS` in gridchords.js: `gridCommand(e)` names the command (null in a text field) and `gridCommands` in paneleditor.js runs it; a new grid command adds a row to each. A command that returns false leaves its key to the browser (paste waits for the paste event, docs/agents/panels.md).
- Ctrl+S/D/F fill a patch box from the last take (useLast, lastTake() in plans.js: this browser's last patch from sendTakes, null until it makes one, never read from History); destinations add to those present; focus goes to the opposite box only if empty, else Levels. Boxes show a Last chip. Destination-first order is per browser unless following the global default (flipped, setFlip, data-flip on html).
- Next chips (nextTake in plans.js) and Ctrl+Shift+S/D fill Source/Destination with the last take's numbers plus one. Pref nextMode number or fuzzy: fuzzy searches the name without its counter (nameStem: "Cam 3" to "Cam", #149) and takes the first higher match in router order (nextOf), else number + 1 (#196). Repeating (#195): nextTake(state) steps from what the last Next fill put in a box (run, set by usedNext) while the box still holds it, else from the last take; no reset hook, a take or Clear ends it. A side with no next does nothing. Desktop chip shows Next, opening via CSS to the value on hover, focus or Shift held (data-shift on html), hiding Last meanwhile.
- Destination box +, Ctrl+Enter, Cmd+Enter add another destination (#93): the match becomes a chip and the search stays open minus added ones. Enter with leftover text and chips is refused (Esc clears); Tab takes the best match (desktop).
- Greyed rows: combobox takes `outside(it)` and greys a row the signed-in rights exclude (class `sode__menu-off`, a data-pb-tip and an Outside rights tag), still pickable so planBlocked can say why. Sources and dsts in rights are the router's numbers (items' `.n`), shown numbers are `n + numberOffset`; levels are UI levels 1..N.
