# Web layout: modules, keys, layouts

- Big scroll bars (bigscroll.js, rule in AGENTS.md): Firefox cannot set a scroll bar's width, and macOS overlay bars show only during a scroll. So Sode draws its own bar, a track and a thumb in a `.sode-bigscroll` div, 1.4rem wide (`--sode-bigscroll-w`). That is the big size, the default. The little size (`.sode-bigscroll--little`, `--sode-littlescroll-w`, 0.7rem) is for small secondary lists where a big bar hides the content. Use `{ size: 'little' }` in `bigScroll`, or a third `'little'` entry in `SCROLLERS`. The page's bar is always big. Little today: the History filter match lists (`.sode__search .sode__menu`), the filter sets row and the key lists in dialogs. Put a little entry before any broader big entry, since the first match wins. `[data-bigscroll]` on the scroller hides the native bar (base.css). The bar shows only while there is something to scroll. While it shows, the scroller gets padding for it, so the thumb never covers a row. Drag the thumb, or press the track to page (hold to repeat). A wheel over a sideways bar scrolls it sideways. Pointer events, so touch and pen work too. The bar has `aria-hidden` and no tab stop, because keys already scroll. pointerdown and mousedown on it keep focus, so an open match list stays open.
  - `bigScroll(el, axis, size, { watch })` draws one bar, or two for axis `'xy'`, and returns `{ update, now, stop, bar, room }`. The bar is the scroller's next sibling, placed over its inside edge. A static parent gets `.sode-bigscroll-host` (position: relative). The page's own scroller (`document.scrollingElement`) gets a fixed bar at the window's right edge. While it shows, html gets `data-bigscroll-on` and `--sode-page-bar`. Fixed items at the right edge use that width to keep clear of it (`#conn`, the pick bar, the Settings sections).
  - Axis `'xy'` (the Grid page) draws a bar on each axis, both big, and a `.sode-bigscroll__corner` square where they meet. Each bar is shorter by the other's thickness while the other shows. One layout pass decides both, since the side gutter can make the grid overflow across. `room()` gives `{ right, bottom }`, the px of the shown bars in the client box. A drawn bar is on the client box, but a native bar is outside it. gridpanelview.js takes it off `clientWidth` and `clientHeight` in `read()`, so the window maths, `cellAt`, `hit` and `bodyBox` stop at the bars. `now()` lays out at once; `setAxes` calls it before it sizes the pools, since a pool never shrinks. `watch` is an element whose size changes with the content. It replaces the subtree MutationObserver: on the Grid, crosspoint writes would run a layout each time. The Grid scroller has `isolation: isolate` on the desktop layout, so its sticky bands never paint over the bars. The bars are siblings of the scroller, so the Grid's own pointer and wheel listeners never get a press or a wheel on them.
  - `bigScrollAll()` runs on the main page (main.js), /log (log.js), /panels and the editor (panelpage.js), but not on a panel page. The Grid page calls `bigScroll` itself (gridpanelview.js). It draws the page's bar and one on each `SCROLLERS` match, also on ones added later. A bar goes when its scroller leaves the page. On the main page, `SCROLLERS` holds the match lists (`.sode__menu`), the Settings search results and sections, and every dialog body. It also holds the Currently and Sending lists. It also holds the Presets list, the key list, the filter sets row, the Levels row and the Communication Log table. In the editor, it holds the sidebar, the lists, the router lists, the icon lists, Find, Templates and the overview lists. It also holds the Artwork panel in the Live Editor's drawer. A new scroller that users need goes in that list.
  - After the bar is drawn, a scroll only changes the thumb's transform. No element is added or removed, so a MutationObserver on the content sees nothing. ResizeObserver (scroller, its parent, the body's children for the page) and a MutationObserver on the scroller's rows keep the size right. A sticky scroller also gets an update on each page scroll.
  - The phone layout keeps native bars (a touch screen scrolls the content). On the Grid page they are the thin styled bars in gridpanel.css. Geometry is in bigscrollrules.js (pure, node tests). `TestChromeBigScroll` checks it.

main.js wires modules then calls connect(). core.js is state/socket/bus (S, WebSocket, on/onFirst/emit/onMsg, el, fuzzy search, status helpers, nameProblem). It imports only tooltip.js and sprite.js. Imports must not form a cycle (test/imports.test.mjs checks this, and that every import exists). ESLint enforces the keys.js and core.js import lists, and bans DOM and storage globals in web/*rules.js. Modules reach handle() through events (helloCfg, helloData, wsclose, onMsg), so a page only gets them if it imports the module. Tests import everything through web/test/all.mjs.

- Icons: `icon()` in core.js makes `<use href="#pb-i-<name>">`, and sprite.js copies that one symbol from `lucide.svg` into a hidden `<svg>` in the page. Static markup writes the same local href and `adoptIcons` brings its symbols in. Never point a `<use>` at `lucide.svg#...`. For every such `<use>` made, Chrome loads and lays out its own copy of the 370 KB sprite. It frees that copy only at a major GC. A panel's tick icon grew the renderer from 0.4 to 4 GB in two minutes. `test/sprite.test.mjs` fails on one. A `#pb-i-` href means nothing outside the page, so an icon serialised out (export, print) needs its symbol inline.
- Panel pages (`panelrun.js`) apply the socket's tally frames (`tallyRows` from core.js) to the last `GET /api/v1/tally` (`paneltally.js`). After a hello, until the socket closes, the 2 s poll leaves out `/tally`. A check reads it every 60 s. The 2 s poll of the small reads stays, since it finds a revoked key or a lost Sode API. A hello, a `protectedRows` or `names` event, or a Router link change starts a poll at once. If the 60 s check differs from the kept tally, the page reads the tally every 2 s until the next hello. A Hidden caller's tally leaves routes out, so for that caller a frame only starts a poll. With the socket down the page polls every 2 s, as before.
- Socket freshness (#142): core.js keeps ws.lastRx (set on open and each message; test stub sockets need it). A 1s check drops an open socket silent for 15s; wsSend refuses one silent for 7s; drop(ws) reports at once and the page reconnects. sendTakes shows Not sent when wsSend returns false.
- Source ends (#138): srcEnd in routes.js decides if a source is pickable; srcRow, currentlyNodes and stackSteps all use it. Desktop history rows fill a box with useEnd (opposite box next); Receiving's pickSrc goes to Levels.
- planBlocked returns {block, prot} without touching the plan; pass prot to planSummary.
- Failed-take banner (failureBanner, refreshResult): one line per distinct outcome. It tracks the takes' entries (takeResult carries entry). It turns into a confirmation as takes are confirmed late or retried.
- desktop.js and mobile.js are the two layouts. layout.js picks: auto on narrow touch screens, per-browser override; index.html applies the same rule before first paint. desktop.js splits into desktophistory.js (History rows, pager, keyboard mode; owns that state) and desktopkeys.js (the document keydown handler). Factories that get desktop.js's hooks build both, and neither imports desktop.js. Phone: one input stepping Source, Destination, Levels; summary pinned at top; match list floating; number pad for Levels.
- Compact view (pref compact): html[data-compact] (prepaint.js, then device.js) and the desktop.css Compact view rules, desktop only. They hide #patch-view's History and make .sode a viewport-high grid with place-content:center. Then compactcentre.js nudges #patch-view so the span from Source to Levels is at the viewport's centre. The nudge is relative left/top from --sode-centre-x/y (centreNudge in compactrules.js, clamped to the viewport). The row also pads its left by Take's width (--sode-take-w), since Take sits flush right. The nudge is active only while that grid is. The rules also put #result out of flow below Presets, so a result never moves the boxes (the match lists already are out of flow). They shrink Presets and centre them under the boxes. All of that gives way while a preset picks takes from History (data-sode-pick=""). The footer, the Lock bar's bar and #conn fade with opacity over --sode-motion-reveal (250ms, 0 under reduced motion). They never fade with visibility, so hover and :focus-within still reach them. #conn fades only while it has sode__conn--ok, set by renderConn from connState().ok (both links up), never by prepaint. Each has a transparent ::before apron (6rem toward the middle, out to the viewport edges) so a pointer near the corner reveals it. The apron must stay off the patch boxes, Take and Presets, which TestChromeMainCompact checks. historyShown() in desktophistory.js mirrors that rule. While it is false, keyboard mode never starts (Esc with empty boxes does nothing, keys on the page body skip onListKey). When it turns on, focus moves out of History to Source. Alt+Shift+C writes the opposite of the resolved value to This browser, never '' (with Everyone on, '' would change nothing). It is chord 'alt+shift+c' in desktopkeys.js and works from any focus, including a box. preventDefault stops macOS Option+Shift+C from typing Ç. test/compact.test.mjs fails if another module binds it or the ? list shows it twice.
- Desktop keyboard mode: Esc with all boxes empty (or Esc on a History button) focuses #history and sets keysOn, cleared by any click. onListKey: s/d/f boxes, j/k rows (Ctrl+J/K, Cmd+J/K on Mac, work too, as in the match lists), J next group, K latest take. Also h/l or Enter close/open, u/r, comma settings, / Filters, Shift+S/D filter by boxes, ? shortcut list (also Ctrl+?). Groups auto-open under the cursor (autoOpen); .sode__key-note shows each empty box's key.
- Keys: Ctrl+Z (or Cmd+Z on Mac) undoes the last Sode take, except that a box with text keeps the OS text undo. Ctrl+, Settings. Ctrl+G (Cmd+G on Mac) Presets popup. Modifier rule: Control = Sode commands and match-list moves (Ctrl+J/K) on every OS. Alt = theme toggle (Alt+Shift+T), Compact view (Alt+Shift+C), Alt+1-9 and Alt+Shift+1-9 (e.code Digit1-9, presetkeys.js). Alt+1-9 fires the first nine pinned presets, and Alt+Shift+1-9 fills the boxes from one. In the Presets popup, Alt is also Alt+P (pin), Alt+arrows and Alt+Cmd/Ctrl+J/K (reorder pins). Cmd belongs to the OS except Cmd+Z, Cmd+G (preventDefault stops find-next), Cmd+J/K and Cmd+Enter in the Destination box. Every check excludes the other two modifiers. Key labels are lowercase with ⇧ where Shift is needed. Settings: Ctrl+J/K (Cmd on Mac) move the search results when the box is focused and has some. That is resultStep in keys.js, built on the listStep the combobox uses. Else settingstoc.js steps sections. The search box handler runs first, and preventDefault makes the stepper skip.
- Key plumbing: keys.js (imports nothing) exports mac (the one platform test; never repeat the regex). It also exports chord(e) and the one set of listeners for html[data-shift] and html[data-alt] (cleared on window blur). chord(e) names a keystroke the same way everywhere: alt+p, ctrl+alt+j, alt+3, shift+enter. That is modifiers in fixed order, then the physical letter or digit through e.code, with arrows as up/down. New key handlers match on chord(e), not hand-written modifier checks. presetkeys.js has the page-level preset keys (Alt+1-9, Alt+Shift+1-9, Ctrl+G / Cmd+G, the Windows/Linux bare-Alt keyup cancel); presetpopup.js only the keys while it is open. The panel editor's grid commands (Cmd or Ctrl with a letter) are one table, `GRID_CHORDS` in gridchords.js. `gridCommand(e)` names the command (null in a text field), and `gridCommands` in paneleditor.js runs it. A new grid command adds a row to each. A command that returns false leaves its key to the browser (paste waits for the paste event, docs/agents/panels.md).
- Ctrl+S/D/F fill a patch box from the last take (useLast, lastTake() in plans.js). That is this browser's last take from sendTakes, null until it makes one, never read from History. sendTakes stores it in `localStorage` `sode-last-take` (numbers with names, read back against the router's names; anything that fails to parse or match is no Last). A memory copy answers only when storage is blocked or this tab's last write did not land. A failed write also removes the key, so an older value cannot outrank it. A `storage` event for the key emits 'last', which redraws the Last and Next chips in other tabs. lastFromPlan decides: a patch, or a redo with one source and one set of levels. The Next run stays in memory, so a reload ends it. Destinations add to those present; focus goes to the opposite box only if empty, else Levels. Boxes show a Last chip. Destination-first order is per browser unless following the global default (flipped, setFlip, data-flip on html).
- Next chips (nextTake in plans.js) and Ctrl+Shift+S/D fill Source/Destination with the last take's numbers plus one. Pref nextMode number or fuzzy: fuzzy searches the name without its counter (nameStem: "Cam 3" to "Cam", #149). It picks the first higher match in router order (nextOf), else number + 1 (#196). Repeating (#195): nextTake(state) steps from what the last Next fill put in a box (run, set by usedNext), while the box still holds it. Else it steps from the last take. There is no reset hook; a take or Clear ends it. A side with no next does nothing. The desktop chip shows Next. It opens through CSS to the value on hover, focus or Shift held (data-shift on html), and hides Last meanwhile.
- Destination box +, Ctrl+Enter, Cmd+Enter add another destination (#93): the match becomes a chip and the search stays open minus added ones. Enter with leftover text and chips is refused (Esc clears); Tab picks the best match (desktop).
- Ctrl-click (also Cmd-click on a Mac) adds a destination as + does: History destination ends, Followed by, and rows of the Destination match list (desktop). pickOrAdd and addClick in keys.js are the one modifier test; a Mac's Ctrl-click fires contextmenu, never click. A plain click still fills the box. Last chips and Sending to already add.
- Greyed rows: combobox accepts `outside(it)` and greys a row that the signed-in rights exclude (class `sode__menu-off`, a data-pb-tip and an Outside rights tag). The row is still pickable, so planBlocked can say why. Sources and dsts in rights are the router's numbers (items' `.n`), shown numbers are `n + numberOffset`; levels are UI levels 1..N.
