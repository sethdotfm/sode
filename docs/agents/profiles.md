# Profiles (#161), guests (#187), sharing (#169)

Moved from AGENTS.md unchanged.

A profile is a user's saved This browser settings, filter sets and presets, stored on the server so they follow the person. Third scope Me beside Everyone (global) and This browser (local). Exists only where users do; with nobody signed in there are no Me options or wording and a guest gets browser and everyone values.
- Config: User.Profile (config/profile.go: Prefs map, FilterSets, Presets; json:"-", never in hello). Normalize drops unknown prefs, Validate reuses preset and filter rules, capped at MaxProfileBytes (48 KiB JSON). TestPrefTable compares Go prefs with prefs.js. SaveUsers carries a profile over by Was (rename keeps it); removed users lose theirs.
- Messages (app/profile.go): profile {name,prefs,filterSets,presets} is pushed only to connections signed in as that user (and after saves; {name:""} clears). profileSave {id,name,prefs?,filterSets?,presets?} (omitted parts kept) is allowed for your own name, or anyone's for a trusted user or the PIN (rule.self, guardProfile under cfgMu); answers profileSaveResult. profileGet is needTrusted. The command log notes whose profile and how many items, never values. profMemo caches each user's marshalled profile per config snapshot.
- Browser: web/profile.js is the one owner of the profile messages (onMsg allows one handler per type): profile(), profileName(), bus profile, saveProfile(parts,name) (queued one at a time, updates own copy at call time, dropped socket settles pending calls with an error, emits profileSaved), fetchProfile, editTarget, pure toProfile. Prefs resolve this browser, then Me, then Everyone, then built-in (resolve in prefs.js; device.js defaultPref/myPref; settings labels Default (X), X (my default), X (everyone's default), with Set/Clear my default buttons). Sets and presets use scope user (userSets, userPresets); active entries are {scope:'user', user, name} so another user never picks up a same-named set; followProfile; Me presets have their own pinned; sode-preset-pins is for everyone's presets only. Saving to Me uses profilesaver.js profileSaver (no PIN row, refuses oversize).
- Guests: the last user's prefs are cached in localStorage sode-profile-prefs {user,prefs} for pre-paint, but cachedProfile (prefs.js, repeated in prepaint.js) uses them only while a session token is kept, and device.js drops them on an access event for nobody or another user.
- Profile editor (profiles.js, profilesrules.js): bus openProfile {name} (own from cache, others via fetchProfile); a select per pref (prefFields, prefsWith; Not set removes) and Add/Edit/Remove for sets and presets, saved with saveProfile. Entry points: Profile… per saved row in Manage users (profileButtonOff for new or renamed rows); trusted users without the PIN see S.userNames with Profile… buttons; My profile… and Export / import… in the signed-in user's block. Add/Edit emit openFilterEditor / openPresetEditor {user,name?,profile}; filters.js and presets.js then run in target mode saving through profileSaver({target}) and must not import profiles.js. Pref changes apply optimistically (withParts). Export emits openTransfer {scope:'user',user}. Wording: never call a profile private; admins and trusted users can see and edit all. Per-user restrictions are #184, not built; profiles.js marks where.
- Dialogs: trapDialog (dialogkeys.js) returns {show(), hide()}; use them, don't flip root.hidden. One document capture handler sends Esc to the newest open dialog (topDialog): no per-module Esc handlers or observers. Backdrop close needs mousedown and click both on the backdrop. show() moves the root to the end of its parent (bringToFront).
- Export, import, share: one preset or filter set is a link #share=<base64url JSON> (a fragment, never sent to the proxy; old ?f= still works, stripped in main.js); everything else is YAML. POST /api/yaml (app/yamlconv.go) is a deliberate exception to WebSocket-only: stateless, open, no config, 1 MiB cap, JSON to YAML or (?from=yaml) back, no schema (exportfmt.js checkDoc checks shape and sode:1, save paths and config.Validate check content); the browser holds no YAML code. exportfmt.js is pure: doc building, matching against live names (ambiguous never first-match), conflicts, "Name 2" renames, default file name YYYY-MM-DD-Sode-Export-<Site>-<User>.yaml, size checks. transfer.js is the Export & import modal and applySharedLink; reviewsheet.js is the one review sheet (Replace / Keep both / Skip, target scope, Apply now) and saves only through existing savers. A #share= link stays pending until the page is uncovered (mayOpenSheet: names loaded, an access event, no lock up; the sheet closes on locking and re-queues; the address is cleaned once the sheet shows). Share shows the link; Copy link copies it.
- Server config export/import (app/configfile.go, web/configfile.js, Settings > Access, Advanced Settings PIN only): configExport {id,pins} returns yaml.Marshal of a clone of live config (drop-in config.yaml; hashes blanked unless pins); not /api/yaml because hashes and profiles are json:"-". configImport {id,yaml} parses with config.Parse, replaces the whole config (no KeepOwned) via applyConfig; a hash in the file is used, none keeps the live one by user name (KeepPins); a new user without a PIN is refused. The 64 KiB read limit widens for one message: configImportBegin {size} (inline in the read loop) grants it, the answer configImportBeginResult must be ok before the page sends configImport. ExportConfig re-checks the PIN under cfgMu. Settings closes after success.
