# Profiles (#161), guests (#187), sharing (#169)

A profile is a user's saved This browser settings, filter sets and presets, stored on the server so they follow the person. Third scope Me beside Everyone (global) and This browser (local). Exists only where users do; with nobody signed in there are no Me options or wording and a guest gets browser and everyone values.
- Config: User.Profile (config/profile.go: Prefs map, FilterSets, Presets; json:"-", never in hello). Normalized (what the browser gets) drops unknown prefs, and Normalize keeps them for the file. Validate reuses preset and filter rules, capped at MaxProfileBytes (48 KiB JSON). TestPrefTable compares Go prefs with prefs.js. SaveUsers carries a profile over by the row's user id (a rename keeps it); removed users lose theirs.
- Messages (app/profile.go): profile {name,prefs,filterSets,presets} is pushed only to connections signed in as that user (and after saves; {name:""} clears). profileSave {id,name,prefs?,filterSets?,presets?} (omitted parts kept) is allowed for your own name, or anyone's for a Trusted user or higher (rule.self, guardProfile under cfgMu). It answers profileSaveResult. profileGet needs a Trusted user. The command log notes whose profile and how many items, never values. profMemo caches each user's marshalled profile per config snapshot.
- Browser: web/profile.js is the one owner of the profile messages, since onMsg allows one handler per type. It has profile(), profileName(), bus profile, saveProfile(parts,name), fetchProfile, editTarget and pure toProfile. saveProfile is queued one at a time and updates its own copy at call time. A dropped socket settles pending calls with an error. saveProfile emits profileSaved. Prefs resolve this browser, then Me, then Everyone, then built-in (resolve in prefs.js; device.js defaultPref/myPref). Settings labels: Default (X), X (my default), X (everyone's default), with Set/Clear my default buttons. Sets and presets use scope user (userSets, userPresets). Active entries are {scope:'user', user, name}, so another user never picks up a same-named set; followProfile. Me presets have their own pinned; sode-preset-pins is for everyone's presets only. Saving to Me uses profilesaver.js profileSaver (no PIN row, refuses oversize).
- Guests: the last user's prefs are cached in localStorage sode-profile-prefs {user,prefs} for pre-paint. But cachedProfile (prefs.js, repeated in prepaint.js) uses them only while a session token is kept. device.js drops them on an access event for nobody or another user.
- Profile editor (profiles.js, profilesrules.js): bus openProfile {name} (own from cache, others through fetchProfile). It has a select per pref (prefFields, prefsWith; Not set removes) and Add/Edit/Remove for sets and presets, saved with saveProfile. Entry points: Profile… per saved row in Manage users (profileButtonOff for new or renamed rows). Trusted users without the PIN see S.userNames with Profile… buttons. My profile… and Export / import… are in the signed-in user's block. Add/Edit emit openFilterEditor / openPresetEditor {user,name?,profile}. filters.js and presets.js then swap in a profile target from editortargets.js and save through profileSaver({target}). They must not import profiles.js. Pref changes apply optimistically (withParts). Export emits openTransfer {scope:'user',user}. Wording: never call a profile private; admins and trusted users can see and edit all. Per-user restrictions are #184, not built; profiles.js marks where.
- Dialogs: trapDialog (dialogkeys.js) returns {show(), hide()}; use them, do not flip root.hidden. One document capture handler sends Esc to the newest open dialog (topDialog): no per-module Esc handlers or observers. Backdrop close needs mousedown and click both on the backdrop. show() moves the root to the end of its parent (bringToFront).
- Export and import are YAML. Item links (itemlink.js, pure) hold ids only, never a copy. A preset's is `#preset=<id>&install=<uid>`. A panel's is the panel link plus `#install=<uid>`. The install is the config's `installUid` (made once, written back by Load, kept through a config import), sent as the hello's installUid. A link from another install opens nothing and says so; anything that goes to another install goes through Export. POST /api/yaml (app/yamlconv.go) is a deliberate exception to WebSocket-only: stateless, open, no config, 1 MiB cap, JSON to YAML or (?from=yaml) back, no schema. exportfmt.js checkDoc checks shape and sode:1, and save paths and config.Validate check content. The browser holds no YAML code. exportfmt.js is pure: doc building, matching against live names (ambiguous never first-match), conflicts, "Name 2" renames, default file name YYYY-MM-DD-Sode-Export-<Site>-<User>.yaml, size checks. transfer.js is the Export & import modal. reviewsheet.js is the one review sheet (Replace / Keep both / Skip, target scope) and saves only through existing savers; a lock closes it. itemlinkopen.js opens a preset Item link in the preset popup on that preset. The link stays in the address until itemLinkStep can judge it. It waits for the install, the names, an access event and no lock up. For a signed-in user it also waits for the profile with the Me presets. Then the address is cleaned. The preset editor's Item link button (itemlinkview.js) shows the link, Copy link and a QR code. The panel link row (panellinkrow.js) shows the panel's Item link, with a QR code in the Share modal. A panel page opened by a link with an install waits for the hello before it runs (panelpage.js).
- Export file (v2, app/exportfile.go, exportload.go, exportschema.go, exportroute.go): one zip. It holds `manifest.yaml` and one YAML file per category. It also holds `names/<router uid>.yaml` per router, in the saved names table form. Images are plain files under `art/panels/<panel id>/`, `art/defaults/` and `art/icons/`. `exportEntryRe` is the fixed list of entry names, and the import refuses all other names. The manifest holds `exportFormat`, which is not config.Format. It also holds the Sode version, the install UID and per router the UID, prefix, title, matrix, levels, level offset and numbering. Per router it also holds `namesHash`, a hash of the names only. Items write the router prefix in `router` and `hiddenDstsRouter` (`toPrefixes`). With one router a reference (a mapping with `n`) leaves it out, and a filter set or `hiddenDstsRouter` keeps the prefix. The loader puts the UID back (`toUIDs`). With one router, a reference with `n` and no router gets that router. settings.yaml is by section (`exportSections`, the data-section names of the page). TestExportSectionsCoverTheConfig fails on a config key that is in no section and not in `exportNotSettings`. Users carry the PIN hash and length only with `includePins`. API clients keep the user id of their owner. No keys, tokens, History, Communication Log, uptime or Sent lists go. `POST /api/export` takes the JSON `exportReq` and answers the zip. `exportReq` has categories, per-item `pick`, `sections`, `includePins` and the values of This browser in `browser`. browser.yaml holds This browser's own preferences as top-level keys, with `filterSets` and `presets` beside them. `POST /api/import` writes the upload to `import-staging/` beside the config, checks it and answers `importCheck`, which holds the Add import plan with the preselected choices. Then it removes the staging directory. `GET /api/export/items` (exportitems.go) lists each category with its items and sizes. An item's `id` is what `pick` takes for it, and `router` says it names the router. TestExportItemsRoundTripThroughPick keeps the two in step. `POST /api/export/size` answers the zip size of an `exportReq`. All four routes need the session token of an Administrator in `X-Sode-Session` (`httpAdmin`). The socket message `exportSession` (Administrator) answers the connection's token. A connection with none gets a tab token, as with `sessionKey`. The page keeps the token in memory only. With no users, every caller is an Administrator, as in roleMu. Caps: `exportMaxUpload`, `exportMaxEntries`, `exportMaxEntry` (vars for tests). The import reads an entry through a limit and ignores its header size. A format above `exportFormat` is refused with "made by a newer Sode". Each format has a loader in `exportLoaders` and a hand-written fixture in testdata/export-v<N>/. The loader removes and lists the keys that a known format does not name (`pruneUnknown` walks the node beside the Go type). A file with two routers that share one UID is refused.
- Add import (app/importplan.go, importapply.go): `POST /api/import/apply` takes multipart/form-data, the `plan` part (`importReq` JSON: mode `add`, categories, pick, sections, choices) first, then the `file` part. It stages the file again, so no state is kept between check and apply. `planImport` runs under cfgMu and is the one source for both routes. Categories are planned in order: Settings, Routers, Users, Presets, Filter sets, API clients, Panels. Each is planned on a copy that `validateSave` checks alone. So a refused category leaves the others (all or nothing per category). With no categories given, Routers and This browser are left out: a file brings its router for the references, and This browser is the page's. Only a router with the live UID applies. Matching: a file from this install (install UID) by hidden id, then by name; a foreign file by name. Choices per category and item key (`importItem.Key`): `new`, `current`, `skip`, `rename` ("Name 2", `nextName`); unset is `new` for this install and `rename` for a foreign file. An item equal to the live one is `same` and writes nothing. Critical: any `new` on a clash that changes something, Settings sections included. The route then needs a PIN recheck on a connection of the same session token (`tokenRechecked`), else 403 `recheck`. Users arrive PIN needed (no hashes in this release); `new` on a live user keeps that user's PIN. File user ids map to live ids, and API client and panel owners follow the map. An owner the import leaves out, or one without a PIN (as `dropOwnerless` would drop), becomes the importing Administrator. A panel's own API client is not imported and is listed with `refused`, since imported panels need a new key link. `new` on a panel keeps the live Authentication mode and client. Panel Share names follow the user map; a foreign name the import does not map is left out. Each panel passes `validatePanel`, and a public panel waits while Public panels allowed is off. Such an item gets `refused` and the rest of its category imports. References are checked against the live names (`refCheck`): router UID, level range, name at the number (case and spaces ignored, both blank agree). What does not agree goes in the item's `broken` list (`config.Missing`). Presets (Me presets too), filter sets (router only) and panels have it. On a panel, cells, Grid edges and preset buttons the import skipped are checked. Rights keep their references unmarked. With no names read yet, a category with references is refused and waits. Panels are written after the config commit, one file each; a failed one is in `failed`. Templates, Checkpoint sets, Push checkpoints and Artwork are listed in `deferred` and not imported yet. One Settings saves row (why `import`) carries `import`: mode and counts per category, no values. The API audit rows (`auditAPISettings`, `auditRequireHTTPS`) follow as for a save; Require HTTPS from a request that is not secure refuses Settings.
- Export & Import dialog (web/exportdialog.js, pure rules exportrules.js, routes and session token exportcalls.js; Settings > Server, `#xi-open`): `pb-modal--md` with Export and Import tabs. Export ticks categories and items from `api/export/items` and keeps Include PINs (default on). After each change it asks `api/export/size` (debounced) for the size on the Export button. It downloads the zip from `api/export`. Back up everything sends `backupBody`: all nine categories, PINs, This browser's values. The router shows Always included and Brought by <item> when a ticked item names it. A picked panel, template or Default artwork entry brings the Icon library icons it uses (`libIcons`, the list's `icons`). Those icons show ticked with Brought by <item>. The Import tab is a placeholder until the import review. On the phone the dialog shows only the desktop-only message. The profile transfer dialog (transfer.js) stays for My user until its own replacement.
