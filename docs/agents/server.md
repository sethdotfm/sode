# Server architecture: router, takes, HTTP


- internal/swp08: frame.go, msg.go, client.go: one TCP session with reconnect and a keepalive probe (an interrogate, on connect and after 10s without rx). Up is reported, and Send accepts, only after the router's first reply. SetTarget reconnects without reporting down. A probe with no reply drops the link (about 13s). Other unanswered messages only trigger a probe. Rx times are monotonic offsets, writer is ACK-gated. Messages sent while disconnected are dropped. Callbacks OnUp, OnMsg, OnState.
- internal/app: App owns all router state (names, tally, protect, keyed dst to UI level) under one mutex. Each router has a `routerUnit` (routerunit.go): its state, Router link, sender, take timers, External tracking, waiters, checks, caches, Protect waits, uptime and status. `App.routers` holds the units by router UID. New makes one for each router in the settings. Each has its own Router link to its address. A commit that adds or removes a router swaps in a new map of units (`syncUnitsMu` in `applyConfigWith`), so readers use `units()` with no lock. A new unit gets its link and, while Run runs, starts it on `linkCtx`. A removed unit has its takes cut, leaves the map and then stops (`endUnit`); its late callbacks change nothing (`gone`). `App.first` (`firstUnit()`) is the first router's and always stays. App has no single-router fields: every caller names its unit. The link callbacks name their unit (`onUnitMsg`, `onUnitState`, `onUnitUp`), so a message changes only the state of its router. `unitOrFirst` gives the unit of a UID, or the first router for a blank or unknown one. Code with no router on hand yet (preset, rights, panel and Default artwork names, swaps, imports, the setup names, approval labels) uses the first router. A change to the link fields of one router (`config.RouterReconnectChanged`) starts only that router's unit again (`reconnectMu`, then its `SetTarget`). Takes in flight on the other routers go on. A filter set with no router is the first router's for the Broken check. In config, the embedded `Router` is the first router and `MoreRouters` holds the others; `Routers()` and `RouterByUID` read them. Load reads every router in `routers`. Validate checks each one (a problem of a router after the first starts `router <prefix>:`) and refuses two routers with one UID or one prefix. Settings > Routers adds and removes a router after the first (routeradd.go, docs/agents/settings-saves.md). The first router cannot go. Config is an immutable runtime behind an atomic.Pointer; ApplyConfig saves, swaps and, if router-side fields changed, clears state and calls SetTarget. A commit that changes the prefix of a router that both configs have sends every `/ws` page `{"t":"reload"}` (`prefixMoved`). Every page kind connects through core.js `connect`, panel pages too. The hello's `routers` list carries the prefix of each router, and its UID for the references This browser presets store. So core.js `search` accepts `A.23`, and `boxSearch` accepts the prefix of every router (web/routerprefix.js, docs/agents/web-layout.md). Run ticks every 100ms: flush() groups broadcasts and finishes name re-reads, periodic() re-polls. Both go through each router unit. The name read, the route re-reads, the Broken check and the names table of a router use its unit and its settings (`routerOf`). The link status and the link row (its address and `Router`) name their router. A Communication Log row counts in the uptime of its router. The API reads names and tally and the API stream use the unit of the `router` parameter (`apiUnit`). A stream gets names and tally frames only from its router (`from` on the message, `hears`). Health and status (health.go) are about every router. `/api/health`, `GET /api/v1/status` and each frame of the status topic give the state of Sode as a whole (`wholeState`: `healthy`, `degraded` or `down`). A router that is connecting counts as down. They also give one element for each router in the order of the settings (`routerLinks`), and the flat fields of the first router. The hello's `protected` and `protectBy`, the protected message and `/healthz` carry the first router (`firstUnit`). The `uptime` request names its router (`router`, blank for the first), and the log download's uptime parts hold every router (docs/agents/comm-log.md). Only the first router's uptime has a file (`SODE_UPTIME`). The uptime of each other router is in memory only, so a restart clears it. The hello's `routers` list (`helloRouters`) carries every router in the order of the settings. Each element has the unit UID, prefix, title, address, matrix, number offset, levels, `levelNumbering`, `defaultLevels`, names, tally and link status. The `tally`, `names`, `namesChecked` and `status` messages name their router in `routerUid` (the unit UID). Each item of a `take` message can name its router in `router`; blank is the first router. A route has one router: the page sends the source number of the destination's router. The hello has no flat fields of one router: every page kind reads the list (`routerData` in core.js). The UID of an element is the router's UID in the settings, also when the first router's unit has an older one after an import. The saved names table (namestable.go): `names/<router uid>.yaml` beside the config, one file for each router UID, in the export's form (`namesTable`, lists sorted by number). flush() writes it after it releases mu, only when the names differ from what that router's file holds. New loads the file of each unit. So the names are there before the first read. The router's `savedAt` in the hello's `routers` list is its time until a read with replies clears it. The last change of each tie line (tiechanges.go) is in `names/tielines.changes.yaml` (`tieLines`: `id`, `at`, `found`). `applyUnitTally` stamps each tie line that starts at the destination of a changed level, with `App.now`. The first read of a level is no change. `found` marks a tally that no Connected announced. The planner gets it as `Changes` and `Found` (`tieInput`), and `GET /tielines` as `changed` and `before` (before = `found`, or `at` older than `App.started`). flush() writes it when a stamp changed and drops the stamps of deleted tie lines. An address change empties the names as before and does not reload the file. Remove router deletes the file of that router (`namesStore.remove`). Shutdown (shutdown.go): browser messages whose rule sets `write` are counted at dispatch and refused after shutdown starts; their handler must call `m.finish()` on every path. Run then waits up to drainLimit (6s) before it cuts the router link, logSent and uptime. Those run on their own context, so the stop row stays last. main waits 8s for Run.
  - Takes: take() = prepare + complete: plan, check, register, send, wait, collect, one routeLevel per level in the waiter. Each routeReq carries its `Router` UID (blank is the first router; not sent on the wire yet). takeAllowed puts the routes with their router (byRouter) and runs the part of each router side by side (takeOnRouter). The check, waiter, own keys, late claims, native fire and the four take timers come from that router's unit (`w.u`). The History entry and each Communication Log row name that router (`swp08.Why.Router`, set by the unit's link). A route on an unknown router gets "unknown router" and no entry. An Undo or a Retry with no router goes to the router of its entry. Levels belong to a router (docs/tielines-design.md, Levels). `runtime.levelsOf(uid)` gives the level map of each router: count, wire offset and numbering. `planRoute` reads the typed levels as levels of the destination's router (`routerLevels.typed`). On a router with one level, any typed level is level 1. Thus a take of levels 1-17 sends one connect, and its entry has level 1. A router with more levels refuses a level past its count ("unknown level"). The tally, Protect and dump paths, the log rows, `GET /tally` and the failure texts use the levels of their router. Rights `levels` name their router (`config.RouterLevels`), so `outsideRights` and `protectRights` match the levels of the route's router. Matrix, fire mode and presets still use the first router. Tests drive takes through the unit's sendMsg with the test kit's fake router (take_test.go). `newFakeRouter` puts one on the first router. `addFakeUnit` adds a router unit with its own fake, so a test can have several. `f.msg` is a message from that router, `f.drop(err)` cuts its link (sends fail with `ErrDown`) and `f.restore()` brings it up again.
  - Rights (rights.go): take() first runs rightsPass, which refuses the whole take (also before takeNative) if any route is outside the caller's Rights. Each item gets a failed takeResult with no History entry, plus one `api` row. Undo skips the Before source; Retry and presets do not. Each end is matched with its router. That is the route's own, else for an Undo or a Retry the router of its entry (`itemRouter`). `rightsUID` turns blank and the first unit's UID into the settings UID. So a right for A.5 refuses B.5. Protects match the same way (`protectRights`). The hidden view (`apiView`, apiview.go) matches each number on its router (`on(uid)`). Reads and the stream use their unit, History entries their `router`, presets each reference. callerOf(c) gives the Actor and Rights: c.api if set (API callers), else the signed-in user, else Guest. Protected stays per route (guardPhase).
  - Check (takecheck.go): every take reads its routes before its first connect. So Prev (what undo restores) comes from the router, not a cache that misses unannounced changes. It skips levels reported within checkFresh (15s). takeAllowed runs checkRoutes once for the whole take before any prepare, whatever its size. It reads per level. Under bigTake (6) routes, each level gets one interrogate per destination. From bigTake routes, each level gets one interrogate per destination or one ExtTallyDumpReq, whichever needs fewer messages. A dump answers 64 destinations a message. The count comes from the highest destination named or reported; with none, it interrogates. Native fire reads before it stages. Answers reach the checks of the router unit through applyUnitTally. A timeout (checkTimeout, plus checkTimeout/32 per dump answer) or a refused send falls back to the cache and logs the unread levels. A route with a protected level is not read. The check's result says whether it finished, which is the API's `checkSkipped`. One silent destination delays every route of the take by checkTimeout.
  - Router load: one message per ACK, so timeouts count from when a take's last message was ACKed (Why.Done, sendTracked, leftQueue, queueMax). Own keys register for queueMax + ownFor then shorten to ownFor. The four take timers (checkTimeout, routeTimeout, routeGrace, queueMax) are fields of the router unit. newTestApp shortens them on every router unit through shortTimers (testkit_test.go). addFakeUnit shortens those of the unit it adds.
  - Protects (ADR 0012): protect.go runs them, protectstore.go keeps Sode's record, protectserve.go has the page messages and apiprotect.go the API. `router.protect` is dst → UI level → `protHold{dev, kind}`. The `protected` message and the hello carry `[dst, level, device, kind]` and `by`/`protectBy`, Sode's record (`protects.json` beside the config, `protectStore`). `protectSet` and `protectClear` send one 0x8C or 0x8E for each level and wait in `protWait` for the 0x8D or 0x8F (`applyProtect` feeds it). They run one at a time under `protMu`. A set that a level does not confirm sends a clear to the levels that were set (`protectRollback`). What stays goes in the record and the entry's `Still`. A History entry has `protect` (`set` or `clear`) and src -1. The panel Undo cell never sees one (no `panelId`). `protectClear` needs the record's user or client; else `protectAdmin` (the Role, or an Approval's approver). `askNeed` gives `protectClear` an Administrator. `GuestActs` gives a guest the Protect right from the Guest role, and from the Administrator Role with no users. `pushRightsMu` sends a guest's Rights to a guest page too, and `protectRight` in protectrules.js reads them. The page offers Clear to an Administrator without the Protect right (`protectOffer`'s `admin`). TestProtectByRole holds the table of each Role and action. `clearSodeProtects` is `protectClearAll` (Critical). On each router that is up, it clears each dst that has Sode's device in the state or a record. Protects are per router: each `protectDst` carries its `Router` UID (blank is the first router; not sent on the wire yet). These come from that router: the holds, the device number (`ProtectDevice`), the sends, the `protWait`s and the timers. The record (`protectStore`) is keyed by router UID and dst, and the History entry names the router. An Undo must name an entry on the same router. The hello and `/api/v1/protected` still carry the first router only. The `protected` message of a router after the first has its `routerUid` and no `by`. The page keeps no Protect state from it: it only makes an open Tie line picker plan again. The take path needs no change: `guardPhase` refuses any Protected level, Sode's own too. The Protect of a tie take names the unit of the tie line's router (tieprotect.go). It is the one path from the page that protects a router after the first. The main page's Protect and `POST /protected/{dst}` still act on the first router only.
    - Page messages `protectSet` and `protectClear`: the page sends `protect:{dsts:[{dst, undo}]}`, one action with one History Group, a single destination too. `undo` is the History entry it undoes, or absent. The server also reads `protect:{dst, undo}` as `dsts` of one (`protectReq.reqs`). It refuses the whole message (bad_request) for: both `dst` and `dsts`; `undo` beside `dsts`; no destination; a destination two times; more than `protectManyMax`. The reply `<t>Result` is `{t, id, ok, err, results}`. `ok` is true only when every row is. `err` is set only when the server refused the whole message before it read the destinations; `results` is then `[]`. `results` is always an array, one row for each destination in the order sent: `{dst, ok, err, entry, still, admin, recheck, approval}`. `entry` is the History entry id (absent when refused before anything was sent). `still` is the levels Sode still holds after a failure. `admin`: another Sode user's Protect, so an Administrator or an Approval frees it. `recheck` and `approval` are as in `opResult`. A policy refusal puts the same `err` and flags on every row. Examples are a lock, the Role, a PIN recheck or a refused Approval in person. `protectClearAll` keeps its own reply `{t, id, ok, err, cleared, recheck, approval}`. `/api/v1/protected/{dst}` keeps its one-destination answer.
  - Late answers: a take that the router answers late is claimed (lateTake, lateFor; only levels the router said nothing about). Its entry is amended (lateWorker, Entry.Late, a recent message with update).
  - Failures (#15, #17): the cache holds only what the router reported, so the next Prev is real state. waiter.see keeps the latest route for unconfirmed levels. whyMissing writes Failed and Now ([ui level, src], -1 = nothing). A level that the router reports on src after all is already (#36). Undo of a failed take leaves out levels in Now and keeps no-answer levels (undoItem).
  - A router change cuts that router's takes in flight (#106, cutRoutes): they fail with "the router changed"; a waiter keeps the extTracker it started on.
  - history.go: JSONL with paging; a page never ends inside a group.
- internal/app/http.go: /, /healthz, /api/health (health.go: 200 only while Sode is Healthy, else 503; no PIN or config), /ws. One WebSocket per browser, JSON with a t field. The wire type `take` carries all takes of one confirm, at most 8 at once, and a confirm of several takes shares a History Group. history accepts before (echoed) and n; takePage keeps a page only if it is for its current oldest entry. Server pushes ping every wsHeartbeat (5s) through the writer goroutine since browsers cannot see ping frames (#142). Require HTTPS (ADR 0005): httpsGate in https.go wraps the whole mux. client.secure is set at the WebSocket upgrade and gates saves that turn it on (saveSettings). Client IP honors X-Forwarded-For (nearest untrusted hop; X-Real-IP when none) only from trustedProxies. A hop that is not an address ends the search at the peer.
- REST /api/v1: one `apiRoute` per path in `apiRoutes`, added with `registerAPI` from the init of its area's file. Numbers are router numbers (0-based, `numberOffset` in /names), levels UI levels. Guide for callers: docs/api.md. openapi.yaml is embedded and served open at /api/v1/openapi.yaml; TestOpenAPIDocumentsEveryRoute fails when it and `apiRoutes` disagree. No CORS headers.
  - apiv1.go, apiauth.go: `mountAPI` (in Handler) wraps each route in `apiWrap`. That is `apiAuth` (Bearer key or keyless Guest, throttles; the API is always on), the scope check, then an optional `read` row (Log API reads). Between auth and scope, `routerOK` refuses a `router` query parameter that is no router UID (404 `unknown_router`, `knownRouter`). With two or more routers, the reads about one router (names, tally, status and those stream topics) need the parameter (`apiReadUnit`, 400 `router_needed`). In `POST /takes`, each end of a route is `{router, n}` or a bare number (`apiEnd`). With two or more routers, `routeUnit` gives 400 `router_needed` for a bare number. Ends on two routers with no `ties` get 409 `tie_line_needed` or `no_path`; with `ties` they run as a tie take (tietake.go). `apiAuth` returns the resolved `*apiCtx` (Actor with key name and `via`, live Rights, Scopes, key, IP). A user key's scopes are userKeyScopes (`config.AllScopes` minus log); client and keyless scopes come from the config. A keyless call gets Guest Rights and the keyless scopes, never Guest role. Failed keys: ten per address per minute, then that address waits; one `authFailed` row per address per window with the count (flushAuthFails from periodic). Only unknown keys count. A key that worked and ended is 401 `key_revoked` or `key_expired` from `refuseEnded`, even during a lockout, with its own cap and `endedKeyUsed` row. Sode knows such a key by the ended set and session-key shape in `apikeys.go`, or as a found key whose owner or session went. Rate limit per key id, or per address for keyless calls. A route whose Scope is `none` (`scopeOpen`) skips `apiAuth` and gets a nil `apiCtx`; two routes use it. The setup-link exchange (panelsetup.go) shares `authWait`/`authFailed`. The keyless announcement (panelkeyless.go) grants nothing, so it counts no failures and has no throttle. `keylessMax` caps its entries: the oldest without a stream goes, else 429 `too_many_streams`. `keylessPerAddr` caps the entries per address and `keylessConnsMax` the streams per entry. After the key resolves, `apiAuth` refuses an API client's key from outside its `networks` (panelnet.go, 403 `network_not_allowed`, not counted as a failed key). Setup links are `keyRec`s with `Setup` set, skipped by `find`, `list`, `countMu` and `expire`. `httpsGate` answers /api/v1 paths as JSON (`https_required`). The one Save's `api` and `guestApiScopes` fields (Administrator) save the API settings area and the keyless scopes. A keyless scopes change is Critical. It writes `guestApi`, `keylessScopes`, `logApiReads` and `apiLimits` rows.
  - apiview.go: `cl.view()` is the one place where visibility applies to reads (ADR 0004): Destination/Source/Preset/Route, and `Entry`. `Entry` returns the entry as the caller sees it, or false. In that entry, hidden Before-source levels are removed, and Group size and hidden preset names are cleared. Undo, Redo and Retry planning for an API caller must build from `view().Entry(e)` and treat false as not found.
  - apitake.go, apiplan.go, apiidem.go: `POST /takes`, `/presets/{scope}/{name}`, `/history/{id}/undo|redo|retry` (scopes `take` and `history`; `apiRoute.Scope` holds several, space-separated), and panelundo.go's `POST /panels/{id}/undo`. `client.api` points at the `apiCtx`. Its `sink` makes replies land in the request instead of a.clients (deliver checks the sink first). Answers are `apiAnswer`; errors are `apiProblem` (`write`), which `apiFail` calls. The planner mirrors web/plans.js (undoItem, againItem, resolvePreset): keep them in step. `checkSkipped` is takeAllowed's unread: the check did not finish for some route. The per-request write deadline is `takeDeadline(n)` through `http.ResponseController`. Never set `http.Server.WriteTimeout`: it would cut /ws and the stream. Test helpers `apiPost` and `takerApp` are in apitake_test.go. All of these routes go through `apiTakeRun`, in this order:
    - It reads the body.
    - Idempotency-Key: it needs an API key. A keyless Guest gets 400, since guests behind one NAT share an address. There is a slot per key id, tied to a hash of the request. A repeat replays the first answer or waits for it. A slot in flight is never evicted, and a committed answer is replayed even if the map dropped the slot. Only requests that ran are kept.
    - It builds the plan.
    - Then `apiTakeExec` runs `rightsPass` (403 `outside_rights`, replayable), the global cap on takes in flight (`API.TakeCap`, 429 `take_cap`, `apiS.takeStart`), the `sent` row, and `takeAllowed`.
  - apihistory.go: `GET /history/groups/last` returns the newest take Group with a route the caller can see, entries oldest first; single-route takes and External groups never count.
  - apistream.go: GET /api/v1/stream is a send-only WebSocket, topics chosen with ?topics= (names, tally, status, history, results). Frame shapes are in the file's header comment and openapi.yaml. `broadcast` also calls `streamFan`, which turns each browser message into per-stream frames filtered through `cl.view()`. Connect and disconnect write `streamConnect` and `streamDisconnect` `api` rows. A stream records its key id (`apiStream.keyID`) and cancel. Every key lifecycle path (`RevokeOwnKey`, `RevokeKeys`, `pruneKeys`, `expireKeys`) calls `endStreams` with the keys it dropped. The disconnect row's Note says why (`closed: key revoked`, `key expired`, or owner changed or removed). A new path that drops keys must call `endStreams` too. `apiStreamServe` re-checks `keys.alive` after registering, for a key that ended between auth and registration. `refreshStreams` (called from `commit` in settings.go) re-resolves every stream's view and ends one whose keyless API, topic scope or log scope is gone. At most 8 streams per key and per address, else 429 `too_many_streams`.
  - panelstore.go, apipanels.go: panels (docs/panels-design.md). `panelStore` keeps one YAML file per panel in `panels/` beside the config (memory only without a config path), written with `config.AtomicWrite` before the map changes. A bad file is logged, kept in `probs` and skipped; tests read `probs` through `problems()` in panelsapi_test.go. `Panel.Extra` (yaml inline) keeps unknown fields, and its JSON hooks keep them over the API. Stored `Panel` values are never mutated in place. `panelReach` is the one access rule: owner by name, Trusted read live from the config, shared by name or Everyone is use only. A client reaches the panel named in `client`. A panel that the caller is not allowed to use is 404. Artwork type comes from the bytes (`sniffArt`); it is served with a sandbox CSP and nosniff. Routes are in `apiRoutes` like the rest, scopes `panels` and `panelsmanage`.
- internal/config: Defaults, FromEnv (seed), Normalize, Validate; YAML load/save; LevelMap does UI/wire levels.
- Setup wizard (setup.go, web/setupwizard.js with pure setupwizardrules.js): a config path with no users is setup pending, also when the file exists. main writes no file from `SODE_*` any more; env only fills the wizard through the hello's cfg. While setup is pending:
  - `admit` refuses every message whose rule lacks `setup`. Only `hi`, `activity`, `history`, `setupClaim`, `setupRouter`, `setupRestoreKey` and `setupFinish` have it. `needRoleMu` refuses every Role check. Both give `errSetup`, which is not a lock, so the page asks for no PIN. `apiWrap` answers every `/api/v1` route 503 `setup_pending`.
  - The hello carries `setup` (`setupHelloFor`). It holds the preselected Access preset (`SODE_ACCESS_PRESET`, else standard) and each preset's Yes and No rows (`setupRows`). So the page keeps no copy of the preset table. On first start only (no config file yet, `setupEnv`), `setup.env` maps each wizard field that `SODE_*` set to its variable (`config.WizardEnv`, in step with `FromEnv`). The page shows "Filled from SODE_ROUTER." under that field (`envHint`). `SODE_ACCESS_PRESET` preselects only then. A config file with no users came from no env, so it gets neither.
  - `setupRouter {router}` moves the live link to the typed address through `applyConfigWith(..., false)`, which swaps the runtime without `config.Save`. flush keeps the names table back. So nothing is on disk before Finish.
  - One browser runs setup (`setupHold`, under `cfgMu`). The page sends `setupClaim` on every hello, except on a phone. The first claim, or the first `setupRouter` or `setupFinish`, gets it; others are refused with `errSetupElsewhere`. `setupClaim {take: true}` is Take control: it moves setup, puts back the address the old owner's Router step set, and sends the old owner `setupTaken`. When the owner disconnects, `setupLeft` puts the address back and sends every page `setupFree`. A waiting page says so and keeps Take control; it does not claim, since the owner can be reloading. Finish clears the hold.
  - `setupFinish {setup}` checks again under `cfgMu` and writes the answers. It calls the preset's `Apply` and adds the first Administrator with the preset's New user defaults. Its commit is the one save that writes the file; then it saves the names table. It signs the connection in and answers `setupFinishResult` with a token as a sign-in does. It writes one Settings saves row (`setup`, every value new). A second Finish is refused, since users exist.
  - Env-only mode (no config path) has no wizard. The hello's `notSaved` shows the Not saved banner (web/notsaved.js, one copy for each layout). main applies `SODE_ACCESS_PRESET` with the page locks off (`config.ApplyEnvOnlyPreset`). Roles and the first user: docs/agents/users-locks.md.
  - Restore from a backup (setuprestore.go, web/setuprestore.js): `setupRestoreKey` gives the setup owner a key (Take control and a closed owner drop it). `POST /api/setup/restore` takes it in `X-Sode-Setup`, with a `plan` part {pin} and the `file` part. It answers 409 once setup is done. It is a Replace import of every category in the file, with Keep current Administrators off and no PIN recheck. Unlike Replace import it plans onto every file router with its UID, and onto the file's install UID. The first file router becomes the first router. So the remap keeps every reference, and each router's `names/<uid>.yaml` checks them. The commit writes the routers and the install UID, and the new routers get their units. Then each router's table becomes its saved names table and its live names (as at start) until that router answers. If no Administrator in the file has a PIN hash, it answers 409 `pin_needed` with the first Administrator's name. The page then asks for a new PIN and sends the file again. A refused category refuses the whole restore, since setup cannot run twice. The answer carries `browser`, which the page applies (web/browserapply.js) before it reloads.
  - Run setup again (Settings > Server, web/setupagain.js) uses the same steps with no setup messages: see docs/agents/settings-saves.md.
- Config load and the format marker (internal/config/format.go): config.yaml starts with `format: 2` (`config.Format`). `Defaults()` sets it and `Save` writes it, so every written file has it. `Parse` reads the raw key before it decodes over the defaults. A file with settings but no `format` key is v1 (`ErrV1`). A file with no keys (empty, comments only, `{}`) loads as a new install (`noKeys`). A higher number is "made by a newer Sode". `Load`, config import and `BackupUnknown` all go through `Parse`, so none of them reads a v1 file. Raise `Format` only when an older loader would misread the file; a new key with a safe default does not need it. A hand-written fixture needs `format: 2` at the top, or the loader refuses it.
  - Loader defaults for access fields: a release can add an access field. Then a file without its key loads the value that keeps the previous release's behaviour. That value is fixed in `Defaults()` (which `Parse` decodes over), never taken from an Access preset. `newUserDefaults` loads both off, as new users started before it. An unset Use tie lines right (`tieLines` in Rights) is on, as every caller could cross routers before it (testdata/before-tie-lines-right.yaml). Each such field gets a fixture in internal/config/testdata and a test (`TestLoaderKeepsBehaviourForNewAccessFields`).
- Router references (`config.Ref`, `{router, n, shown, name}`): every store names a source or destination by router UID and number, never by a bare number.
  - Each reference holds the UID in config.yaml presets (Everyone and Me) and Rights (users, Guest, API clients).
