# Server architecture: router, takes, HTTP


- internal/swp08: frame.go, msg.go, client.go: one TCP session with reconnect and a keepalive probe (an interrogate, on connect and after 10s without rx). Up is reported, and Send accepts, only after the router's first reply. SetTarget reconnects without reporting down. A probe with no reply drops the link (~13s); other unanswered messages just trigger a probe. Rx times are monotonic offsets, writer is ACK-gated. Messages sent while disconnected are dropped. Callbacks OnUp, OnMsg, OnState.
- internal/app: App owns all router state (names, tally, protect, keyed dst to UI level) under one mutex. Config is an immutable runtime behind an atomic.Pointer; ApplyConfig saves, swaps and, if router-side fields changed, clears state and calls SetTarget. Run ticks every 100ms: flush() groups broadcasts and finishes name re-reads, periodic() re-polls. Shutdown (shutdown.go): browser messages whose rule sets `write` are counted at dispatch and refused once shutdown starts; their handler must call `m.finish()` on every path. Run then waits up to drainLimit (6s) before cutting the router link, logSent and uptime, which run on their own context so the stop row stays last. main waits 8s for Run.
  - Takes: take() = prepare + complete: plan, check, register, send, wait, collect, one routeLevel per level in the waiter. Tests drive takes through App.sendMsg with a fake router (take_test.go).
  - Rights (rights.go): take() first runs rightsPass, which refuses the whole take (also before takeNative) if any route is outside the caller's Rights. Each item gets a failed takeResult with no History entry, plus one `api` row. Undo skips the Before source; Retry and presets do not. callerOf(c) gives the Actor and Rights: c.api if set (API callers), else the signed-in user, else Guest. Protected stays per route (guardPhase).
  - Check (checkTally, #57) interrogates every level and waits up to 1s so Prev (what undo restores) comes from the router, not a cache that misses unannounced changes (falls back to cache). Skips levels reported within checkFresh (15s) and all takes of a confirm of bigTake (6)+ (NoCheck, #91), trading undo accuracy for router load.
  - Router load: one message per ACK, so timeouts count from when a take's last message was ACKed (Why.Done, sendTracked, leftQueue, queueMax); own keys register for queueMax + ownFor then shorten to ownFor. The four take timers (checkTimeout, routeTimeout, routeGrace, queueMax) are App fields; newTestApp shortens them via shortTimers (ext_test.go).
  - Late answers: a take the router answers late is claimed (lateTake, lateFor; only levels the router said nothing about) and its entry amended (lateWorker, Entry.Late, a recent message with update).
  - Failures (#15, #17): the cache holds only what the router reported, so the next Prev is real state. waiter.see keeps the latest route for unconfirmed levels; whyMissing writes Failed and Now ([ui level, src], -1 = nothing); a level the router reports on src after all is already (#36). Undo of a failed take leaves out levels in Now and keeps no-answer levels (undoItem).
  - A router change cuts takes in flight (#106, cutTakes): they fail with "the router changed"; a waiter keeps the extTracker it started on.
  - history.go: JSONL with paging; a page never ends inside a group.
- internal/app/http.go: /, /healthz, /api/health (#140: 200 only while the router is up, else 503; no PIN or config), /ws. One WebSocket per browser, JSON with a t field. The wire type `batch` carries all takes of one confirm, at most 8 at once, and a confirm of several takes shares a History Group. history takes before (echoed) and n; takePage keeps a page only if it is for its current oldest entry. Server pushes ping every wsHeartbeat (5s) through the writer goroutine since browsers can't see ping frames (#142). Require HTTPS (ADR 0005): httpsGate in https.go wraps the whole mux; client.secure is set at the WebSocket upgrade and gates saves that turn it on (saveSettings). Client IP honors X-Forwarded-For (nearest untrusted hop; X-Real-IP when none) only from trustedProxies; a hop that isn't an address ends the search at the peer.
- REST /api/v1: one `apiRoute` per path in `apiRoutes`, added with `registerAPI` from the init of its area's file. Numbers are router numbers (0-based, `numberOffset` in /names), levels UI levels. Guide for callers: docs/api.md. openapi.yaml is embedded and served open at /api/v1/openapi.yaml; TestOpenAPIDocumentsEveryRoute fails when it and `apiRoutes` disagree. No CORS headers.
  - apiv1.go, apiauth.go: `mountAPI` (in Handler) wraps each route in `apiWrap`: `apiAuth` (API switch, Bearer key or keyless Guest, throttles), the scope check, then an optional `read` row (Log API reads). `apiAuth` returns the resolved `*apiCtx` (Actor with key name and via, live Rights, Scopes, key, IP). A user key's scopes are userKeyScopes (`config.AllScopes` minus log); client and Guest scopes come from the config. Failed keys: ten per address per minute, then that address waits; one `authFailed` row per address per window with the count (flushAuthFails from periodic). Only unknown keys count: a key that worked and ended (the ended set and session-key shape in `apikeys.go`, or a found key whose owner or session went) is 401 `key_revoked` or `key_expired` from `refuseEnded`, even during a lockout, with its own cap and `endedKeyUsed` row. Rate limit per key id, or per address for keyless calls. A route whose Scope is `none` (`scopeOpen`) skips `apiAuth` and gets a nil `apiCtx`; two routes use it. The setup-link exchange (panelsetup.go) shares `authWait`/`authFailed`. The keyless announcement (panelkeyless.go) grants nothing, so it counts no failures and has no throttle; `keylessMax` caps its entries, oldest dropped first. After the key resolves, `apiAuth` refuses an API client's key from outside its `networks` (panelnet.go, 403 `network_not_allowed`, not counted as a failed key). Setup links are `keyRec`s with `Setup` set, skipped by `find`, `list`, `countMu` and `expire`. `httpsGate` answers /api/v1 paths as JSON (`https_required`). `apiSettings` (needAdmin, SaveAPISettings) saves the API settings area and writes `apiEnabled`, `guestApi`, `logApiReads` and `apiLimits` rows.
  - apiview.go: `cl.view()` is the one place visibility applies to reads (ADR 0004): Destination/Source/Preset/Route, and `Entry`, which returns the entry as the caller sees it (hidden Before-source levels removed, Group size and hidden preset names cleared) or false. Undo, Redo and Retry planning for an API caller must build from `view().Entry(e)` and treat false as not found.
  - apitake.go, apiplan.go, apiidem.go: `POST /takes`, `/presets/{scope}/{name}`, `/history/{id}/undo|redo|retry` (scopes `take` and `history`; `apiRoute.Scope` holds several, space-separated), and panelundo.go's `POST /panels/{id}/undo`, all through `apiTakeRun`: read body, Idempotency-Key (needs an API key, a keyless Guest gets 400: guests behind one NAT share an address; slot per key id, tied to a hash of the request; a repeat replays the first answer or waits for it; a slot in flight is never evicted and a committed answer is replayed even if the map dropped the slot; only requests that ran are kept), build the plan, then `apiTakeExec`: `rightsPass` (403 `outside_rights`, replayable), the global cap on takes in flight (`API.TakeCap`, 429 `take_cap`, `apiS.takeStart`), the `sent` row, and `takeAllowed`. `client.api` points at the `apiCtx`; its `sink` makes replies land in the request instead of a.clients (deliver checks the sink first). Answers are `apiAnswer`; errors are `apiProblem` (`write`), which `apiFail` calls. The planner mirrors web/plans.js (undoItem, againItem, resolvePreset): keep them in step. 6+ routes sets `checkSkipped` (bigTake). The per-request write deadline is `takeDeadline(n)` through `http.ResponseController`; never set `http.Server.WriteTimeout`, it would cut /ws and the stream. Test helpers `apiPost` and `takerApp` are in apitake_test.go.
  - apihistory.go: `GET /history/groups/last` returns the newest take Group with a route the caller can see, entries oldest first; single-route takes and External groups never count.
  - apistream.go: GET /api/v1/stream is a send-only WebSocket, topics chosen with ?topics= (names, tally, status, history, results); frame shapes are in the file's header comment and openapi.yaml. `broadcast` also calls `streamFan`, which turns each browser message into per-stream frames filtered through `cl.view()`. Connect and disconnect write `streamConnect` and `streamDisconnect` `api` rows. A stream records its key id (`apiStream.keyID`) and cancel; every key lifecycle path (`RevokeOwnKey`, `RevokeKeys`, `pruneKeys`, `expireKeys`) calls `endStreams` with the keys it dropped, and the disconnect row's Note says why (`closed: key revoked`, `key expired`, or owner changed or removed). A new path that drops keys must call `endStreams` too. `apiStreamServe` re-checks `keys.alive` after registering, for a key that ended between auth and registration. `refreshStreams` (called from `commit` in settings.go) re-resolves every stream's view and ends one whose API switch, Guest API, topic scope or log scope is gone; at most 8 streams per key and per address, else 429 `too_many_streams`.
  - panelstore.go, apipanels.go: panels (docs/panels-design.md). `panelStore` keeps one YAML file per panel in `panels/` beside the config (memory only without a config path), written with `config.AtomicWrite` before the map changes. A bad file is logged, kept in `probs` and skipped; tests read `probs` through `problems()` in panelsapi_test.go. `Panel.Extra` (yaml inline) keeps unknown fields, and its JSON hooks keep them over the API. Stored `Panel` values are never mutated in place. `panelReach` is the one access rule: owner by name, Trusted read live from the config, shared by name or Everyone is use only, a client reaches the panel named in `client`. A panel the caller may not use is 404. Artwork type comes from the bytes (`sniffArt`); it is served with a sandbox CSP and nosniff. Routes are in `apiRoutes` like the rest, scopes `panels` and `panelsmanage`.
- internal/config: Defaults, FromEnv (seed), Normalize, Validate; YAML load/save; LevelMap does UI/wire levels.
- cmd/swp08sim: fake router; must keep mimicking real Ultrix quirks (e.g. no Connected for no-op connects).
