# Communication Log (#72, /log)

Every message written to the router, captured at the wire, plus event rows (#139). swp08.Client.OnTx fires once per message from transmit (after ACK, NAK or give-up, with Tries) or for messages still queued when a session ends. sendMsg logs unsent when Send refuses. Each Send carries a swp08.Why. OnTx only pushes onto txq (it never blocks the ACK-gated writer). logSent decodes, appends to SentLog (sentlog.go: JSONL with own seq, rotated to .1 at half SODE_COMMLOG_MB) and queues logAdd/logPage for connections that asked. A failed write keeps its seq unused and is not broadcast, so seqs have no gaps. A damaged file is renamed .bad-..., not fatal. Read-only, no clear, no PIN.
- Router: logSent gives router messages (cmd 0 or more) and `link` rows `router` (the router UID) and `routerTitle` (the title at write time). Other event rows are about the server, so they name no router.
- Events: kinds browser, api, command, link and server. They have cmd/wire/dst/src -1 and empty hex (event(); the page uses EVENT_KINDS in logkinds.js), detail in Note. logEvent pushes onto evq. logSent is the single writer of txq and evq, so seq, file and feed agree. On shutdown it drains both and writes stop (Run waits for it, main waits for Run, 3s). logLink (under mu) logs down once per outage (again if the error changes) and up. A router change resets it, logs changed and marks uptime down, because SetTarget never reports down. Default kinds: Connects, Commands, Router link.
  - browser: connect/disconnect, By = IP.
  - api: only apiEvent in app/apiaudit.go writes them. The why values come from the REST side. By = actor and key name. Note = detail, then the panel tag, then the unverified `via` text. Key-shaped text is redacted. On by default in the page filter. The why values:
    - `read` (Log API reads), `refused` (a missing scope).
    - `authFailed` (one row per address per minute, By = the address, Note = the count).
    - `endedKeyUsed` (the same, for calls with a key that ended).
    - `guestApi`, `keylessScopes`, `logApiReads`, `apiLimits`.
    - The take rows (`take`, and the refusals of the rights pass).
    - `keyCreate`, `keyRevoke`, `keyEnded` (owner changed or PIN changed) and `keyExpired` (By is Sode).
    - `streamConnect` and `streamDisconnect` (Note says why when a key's end closed the stream).
    - `panelLost` and `panelBack` (By is Sode). A panel device closed its stream and 8 s passed, or missed its keepalive for more than 45 s, or returned. Note is the panel tag, then the seconds, and says when no device is left online. One row per change, never per keepalive.
    - `panelSetup` (Note is the panel tag).
    - `assign` (By is the user). Note is the panel tag of the instance's old panel, then `to` and the target's tag, then the address (`at <addr>`, or `keyless from <addr>`).
    - `rename` (By is the user). Note is the panel tag with the old name, then `to` and the new name, then the address. A keyless page's row says `keyless`.
    - `reload` (By is the user). One row per page that a Reload from the Open now list reached. Note is the panel tag, then the address.
    - `publicBack` (By is the page's address, never a user). A Public panel page asked after a `public` line and got a key. A refused ask writes nothing.
  - command: `take`, rereadNames, clearHistory, `panelAlarm`, `download`, config, filterSets, the PIN and Lock kinds, and Send a copy (`inboxSend`, `inboxAccept`, `inboxDecline`, `inboxWithdraw`, `inboxExpired` by Sode; docs/agents/profiles.md). A native fire writes lock, release and result rows (docs/agents/salvos.md). Never a PIN or settings. `approvalRequest` rows (By = the requester) have result `sent`, `approved`, `denied`, `timeout` or `cancelled`. Note has the action and who answered. A `stepIn` row is by the stepped-in user, with note "browser of <original>". A failed try is a `refused` `stepIn` row by the browser, with note "as <name>" and the reason in err. `stepOut` rows are by the stepped-in user, and Note says how the step-in ended and whose browser it was (docs/agents/users-locks.md). For `panelAlarm`, Note is `clear` or `stop` and the panel tag, with the instance only for a watched instance.
  - link: up, down, changed. `routerNames` (By Sode) is the Broken check after a name read, with result `renamed`, `moved` or `broken`. Note lists the renames as `source 13 CAM 3 to CAM C`. It also names the items that became Name moved or Broken (docs/agents/server.md).
  - server: start, stop.
  - settings (Settings saves, on by default): one row per write to shared settings (savesrecord.go). Why is `save`, `api`, `import`, `setup` or `browserCopy`. `browserCopy` is Copy this browser to My user (browsercopy.go). By is that user. It has one field per changed pref, with old and new. It has one field per list (`Filter sets`, `Presets`) with the added names and a note that names the replaced ones. The section is My user, under Preferences. It is never Critical. Other My user and This browser changes get no row. `setup` is the setup wizard's Finish: every field it writes has only a new value, and the new user's PIN shows as `changed`. `import` is one Add import (importapply.go): no fields, only `import` with the mode and counts per category. `save` is the one Save (Manage users included). `api` is a panel's own API client changed through `/api/v1` (create, update, copy and delete of a panel, and `PUT /panels/{id}/networks`), from clientChanges. My user's own clients get no row. The `settingsSave` command row and the `panelNetworks` api row stay beside it. `save` holds the fields: topic, section, label, then old and new, or added and removed for a list, or `changed` for a secret (a PIN). Values come from the config before and after the commit, never from the request, which can hold a PIN. Rights lists that are null show as `everything`. A user's Rights field notes the panel clients that user created. Interruptions are the review's lines at save time (docs/agents/settings-saves.md). A reader below Administrator gets only their count (`hiddenInterruptions`), since they name users and Public panels. Preset stays empty until the ticket that fills it. Only fields that were written count; no row when none was. History gets nothing.
    - Own file: SaveLog (savelog.go, `SODE_SETTINGS_SAVES`, memory only without it), kept keepAge (365 days) or keepBytes (5 MB). Over the cap the oldest go down to lowWater (80%), so the file is not written again on each append; uptime does the same. In no export.
    - Merge: logSent gives each row `seq` = the Communication Log's next seq (its anchor) and its own `id`. mergeSaves adds to a page of seqs [lo, before) the rows anchored in (lo, before]; with no more entries, all older rows come. The page keys rows with `rowKey` and sorts with `byNewest` (logpager.js): a row sits below its anchor. The `before` cursor stays a seq. SetSettingsSaves moves anchors past the Communication Log's next seq (a fresh log) to its oldest seq.
    - Readers: forReader leaves values of Hidden sections (Access, Server) only for an Administrator; the others get `changed`. broadcastSent marshals the two forms; the API always gets the narrow one, since a key never acts as an Administrator.
    - The page shows the row's fields in a `details` (logsaves.js). A filter saved before this kind gets it once (`addNewKinds`, `known` in sode-log-filter).
- Panel tag: every row that a panel page causes names the panel and the instance in Note as `panel <short name> (<name>), instance <instance>`. This is `panelTag` in apiaudit.go. The short name is the slug, else the id (`panelShort`). A panel's own client key proves the panel (`apiCtx.Panel`). Its key name stands in for the instance when the page sends none, since keys are made per instance. The page sends `X-Sode-Panel` (the id) and `X-Sode-Instance` (its instance name) on every `/api/v1` call. This is `fromPanel` in panelwatchrules.js, wired in panelrun.js after the keepalive names the instance. The editor's live test sends neither. With a user's key (Session mode), the id must name a panel that exists, and the tag is prefixed `unverified`, like the `via` text. An instance with no panel is dropped. `panelHeaders` in apiauth.go reads them. The tag is kept on unexported `Actor` fields so the actor's name and JSON stay as they were. The router messages of a panel's take carry the same tag in Note (`swp08.Why.Note`, set in `planPhase`). The History entry gets `panel` (the panel's name, else its short name, `panelNames`) and `instance`, which the History row shows after the user. The instance name is the page's own word everywhere, as the keepalive's device name is. The page's `WHY_LABEL` (logkinds.js) has words for every why the server writes. TestEveryLogReasonHasWords (logwhy_test.go) finds the whys in the source. They are the string literals that reach `event()` or a `swp08.Why`'s Reason, through each function that passes its parameter on. The policy table's keys count too, since a refusal logs them. Give a new why a label in the same change.
 There is no text filter on By or Note.
- Downloads (logdownload.go, web/logdownload.js, web/logfile.js, web/zipfile.js): `/log` has Download filtered rows and Download full log. The page makes both files from the whole log, never only from the rows it loaded. The filter, sort and words exist only in the page: the server has no copy of them. `POST /api/log/download` takes `{parts, for}` and answers one JSON object with a key per part. A new part is a row in `logParts`, so it needs no new route. `for` is `full` or `filtered` and changes only the download row.
  - Parts: `log` is every Log row from both log files, oldest first (`SentLog.Each`), as on the page. Settings saves rows sit below their anchors. `uptimeStates` is `[{t, s, router}]` and `uptimeMinutes` is `[{m, bad, slow, router}]` (only minutes with a count). Both hold every router in the order of the settings, the first router first, and `router` is the router UID. The reply goes out as the server reads, so a cut reply is not valid JSON and the page shows Download failed.
  - Download full log asks for all three parts. The page makes a zip of them (zipfile.js, deflate from CompressionStream). It holds `log.csv`, `uptime-states.csv` (time, state, note) and `uptime-minutes.csv` (minute, bad, slow). With two or more routers each file gets a last column, `router`, with the Router prefix (`routerWord` in logdownload.js). It is blank for a row that names no router.
  - Download filtered rows asks for `log`. It keeps the rows that pass the page's filters (kinds, Problems only, Source, Destination, From, To). It puts them in the page's sort (`passes` and `sortRows` in log.js) and gives one CSV.
  - logfile.js writes the CSV. The columns are the old Download CSV's (`LOG_COLS`), with the formula guard (`csvCell`). Numbers and level names are as the page shows them. The note of a Settings saves row is its note, its summary and one line per field: `Section: label: old → new`, `added …; removed …`, or `changed`.
  - Redaction stays on the server. `forReader` takes out the values for the reader's Role before the rows go out. So values of Hidden sections read `changed`, and secrets always do.
  - Access: as the `log` rule. The page sends the `exportSession` token in `X-Sode-Session` (none for a Guest). With no token, the reader is a Guest, which fails 401 while the log lock is on. A held Lock is 403.
  - Each read writes one `command` row with why `download`. By is the user, else the address. Note says full log or filtered rows, the count of Log rows sent and their time range (UTC). For filtered rows the count is the rows sent to the page, not the rows in the file. The server cannot see what the page keeps. A reply cut by an error writes result `error`.
- Uptime graph: uptime.go keeps JSONL (SODE_UPTIME) of state changes (up, down, off; connecting counts as down). It also keeps per-minute counts of bad (not ACKed or tries > 1) and slow (AckMs over 300) messages, counted in logSent before the append. No file I/O under mu: State and Note change memory only. Run writes (5s) plus <path>.alive each minute. Stop writes off. A file whose last state is not off gets off at the alive stamp. Lines older than uptimeKeep (keepAge, 365 days) drop. Then the oldest drop until the file is under keepBytes (5 MB). The last state before the cutoff stays. The uptime request {from,to,slot,id,router} is answered by uptimeReply with counts summed per slot. `router` is the router UID, blank for the first router, and the reply echoes it. A UID with no router gets nothing recorded. Only the first router has a file (`SODE_UPTIME`); each other router keeps its uptime in memory. uptime.js (pure): red = no up time, yellow = partly down or bad or slow, grey = no record. Toggles 1h/24h/7d/30d set the log's From (chipOn; cleared by hand-typed times or Clear times). With two or more routers, /log has one uptime line for each router (`syncUpLines` in log.js). It has a head with the router's name (`routerName`) and its summary, then its bars (`data-router`). The first router keeps `#log-uptime-bars`, and the others go in `#log-uptime-more`. With one router there is no head and `#log-uptime-sum` has the summary. Each refresh sends one request per router (`upWant`), and a change of any router's link state refreshes. Bars are buttons: enterSlot sets From/To, forces newest first and shows #log-slot (One bar). Show all bars restores, and the strip's range chip stays pressed. Each strip is one Tab stop (`roveBars` in uptimebars.js): the picked bar, else the newest. The arrow keys, Home and End move the focus and the stop. slotFor keeps it under 200 slots. It also keeps it under one slot for each 8 px of the strip (`maxBars` in log.js), so the phone gets wider bars. A bar's tip opens over the strip, lined up with the strip's nearer end. The phone layout's rules are in log.css; the table keeps its native bar there. The bars come from uptimebars.js and their CSS (`sode-up__*`) is in base.css. They are shared with each instance's strip on /panels (docs/agents/panels.md). slotText receives the words for up and down. The router list of the status bar (statusinfo.js) is a second `uptime` reader. It shows on every page with the Server and Router status, and on the phone. An open row holds a 24-hour strip and the time since the Router link came up. The list sends one `uptime` request for each router whose row is open (`wants` maps the reply id to the router). The hover box of the status (statusinfo.js `makeHover`, desktop only) is a third reader. Each time it opens, it sends one request for each router that it shows, at most 8. Its ids start at 1,000,000,000, above log.js's, so neither takes the other's reply. It asks only when `logReadable` (statusinforules.js) says the access passes the rule's needLog gate, since a refused `uptime` writes a locked row. The Server run time comes from `/api/health` `uptimeSeconds`, read on a 503 too; `/healthz` has no run time.
- Page: log.js imports core.js and device.js but not initTheme; filter in sode-log-filter. With two or more routers, the Routers chips (`#log-routers`, `pressRouter` in logfilter.js) filter by router, as the Show chips do. The filter key `routers` holds the picked router UIDs, empty for every router. A row that names no router always passes. A router message's ends show its router prefix, and a link row's result names its router ("Router B down", `linkResult`). logpager.js (newPager, pure, #141) owns the list and one pending request (reply accepted only if it echoes that before). It keeps reading (500 at a time, up to 20 requests) until it shows 100 more rows, since the default filter hides most entries.

- Row cap: logpager.js keeps at most LIVE_CAP (500) entries in its list. A live entry past the cap drops the oldest from the list and the page (`dropRows` in log.js), never from the log file. The pager then knows that older entries exist. Each Load older or time-range read raises the cap by the entries it added, so a live row does not drop them. The read-on at open does not raise it. Load older gets 100 rows with `logPage` (no wire change). A wheel or touch pull past the end of the page presses Load older, with the same `pullToLoad` as the home page's Load more. The cap counts entries, so hidden entries count and fewer rows can show. TestChromeLogRowCap checks it.
