# Communication Log (#72, /log)

Moved from AGENTS.md unchanged.

Every message written to the router, captured at the wire, plus event rows (#139). swp08.Client.OnTx fires once per message from transmit (after ACK, NAK or give-up, with Tries) or for messages still queued when a session ends; sendMsg logs unsent when Send refuses. Each Send carries a swp08.Why. OnTx only pushes onto txq (never blocks the ACK-gated writer); logSent decodes, appends to SentLog (sentlog.go: JSONL with own seq, rotated to .1 at half SODE_SENTLOG_MB) and queues sentAdd/sentPage for connections that asked. A failed write keeps its seq unused and isn't broadcast, so seqs have no gaps; a damaged file is renamed .bad-..., not fatal. Read-only, no clear, no PIN.
- Events: kinds browser (connect/disconnect, By = IP), api (only apiEvent in app/apiaudit.go writes them, why values from the REST side: `read` (Log API reads), `refused` (a missing scope), `authFailed` (one row per address per minute, By = the address, Note = the count), `endedKeyUsed` (the same, for calls with a key that ended), `apiEnabled`, `guestApi`, `logApiReads`, `apiLimits`, the take rows (`take`, and the refusals of the rights pass), `keyCreate`, `keyRevoke`, `keyEnded` (owner changed or PIN changed) and `keyExpired` (By is Sode), `rightsEdit`, `clientEdit`, `noAutoLockEdit`, `streamConnect` and `streamDisconnect` (Note says why when a key's end closed the stream), `panelLost` and `panelBack` (By is Sode; a panel device closed its stream and 8 s passed, or missed its keepalive for more than 45 s, or returned; Note is the panel tag, then the seconds, and says when no device is left online; one row per change, never per keepalive), `panelSetup` (Note is the panel tag), `assign` (By is the user; Note is the panel tag of the instance's old panel, then `to` and the target's tag), `rename` (By is the user; Note is the panel tag with the old name, then `to` and the new name); By = actor and key name, Note = detail, then the panel tag, then the unverified via text; key-shaped text is redacted; on by default in the page filter), command (`batch`, refreshNames, clearHistory, `panelAlarm` (Note is `clear` or `stop` and the panel tag, with the instance only for a watched instance), config, filterSets, and the PIN and Lock kinds; never a PIN or settings), link (up, down, changed) and server (start, stop). They have cmd/wire/dst/src -1 and empty hex (event(); the page uses EVENT_KINDS in logkinds.js), detail in Note. logEvent pushes onto evq; logSent is the single writer of txq and evq so seq, file and feed agree; on shutdown it drains both and writes stop (Run waits for it, main waits for Run, 3s). logLink (under mu) logs down once per outage (again if the error changes) and up; a router change resets it, logs changed and marks uptime down because SetTarget never reports down. Default kinds: Connects, Commands, Router link.
- Panel tag: every row a panel page causes names the panel and the instance in Note as `panel <short name> (<name>), instance <instance>` (`panelTag` in apiaudit.go; the short name is the slug, else the id, `panelShort`). A panel's own client key proves the panel (`apiCtx.Panel`), and its key name stands in for the instance when the page sends none (keys are made per instance). The page sends `X-Sode-Panel` (the id) and `X-Sode-Instance` (its instance name) on every `/api/v1` call (`fromPanel` in panelwatchrules.js, wired in panelrun.js once the keepalive names the instance; the editor's live test sends neither). With a user's key (Session mode) the id must name a panel that exists and the tag is prefixed `unverified`, like the via text; a instance with no panel is dropped. `panelHeaders` in apiauth.go reads them; the tag is kept on unexported `Actor` fields so the actor's name and JSON stay as they were. The router messages of a panel's take carry the same tag in Note (`swp08.Why.Note`, set in `planPhase`), and the History entry gets `panel` (the panel's name, else its short name, `panelNames`) and `instance`, which the History row shows after the user. The instance name is the page's own word everywhere, as the keepalive's device name is. The page's `WHY_LABEL` (logkinds.js) words `panelLost`, `panelBack`, `panelAlarm`, `panelSetup`, `assign`, `rename`, `streamConnect` and `streamDisconnect`; there is no text filter on By or Note.
- Uptime graph: uptime.go keeps JSONL (SODE_UPTIME) of state changes (up, down, off; connecting counts as down) and per-minute counts of bad (not ACKed or tries > 1) and slow (AckMs over 300) messages, counted in logSent before the append. No file I/O under mu: State and Note change memory only, Run writes (5s) plus <path>.alive each minute; Stop writes off. A file whose last state isn't off gets off at the alive stamp; lines older than uptimeKeep (400 days) drop, keeping the last state before the cutoff. The uptime request {from,to,slot,id} is answered by uptimeReply with counts summed per slot. uptime.js (pure): red = no up time, yellow = partly down or bad or slow, grey = no record; toggles 1h/24h/7d/30d set the log's From (chipOn; cleared by hand-typed times or Clear times); bars are buttons: enterSlot sets From/To, forces newest first, shows #log-slot; Back restores. slotFor keeps it under 200 slots. The bars come from uptimebars.js and their CSS (`sode-up__*`) is in base.css, shared with each instance's strip on /panels (docs/agents/panels.md); slotText takes the words for up and down.
- Page: log.js imports core.js and device.js but not initTheme; filter in sode-log-filter. logpager.js (newPager, pure, #141) owns the list and one pending request (reply accepted only if it echoes that before); it keeps reading (500 at a time, up to 20 requests) until 100 shown rows more, since the default filter hides most entries.
