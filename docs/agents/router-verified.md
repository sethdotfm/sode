# Verified against the real Ultrix (2026-10-22, 172.17.60.101:8910)

- UI level 1 = wire 0 (SODE_LEVEL_WIRE_OFFSET=-1), display number = wire + 1 (SODE_NUM_OFFSET=1).
- Standard name requests (100/102) with 12-char names work. About 2690 sources, 720 destinations.
- Extended tally dump (0x95 to 0x97, 64 per message) works on all 17 levels; source 0xFFFF = nothing routed. Extended connect (0x82) is confirmed by 0x84.
- Routers send Connected only when a crosspoint changes. A matching connect gets no reply, so take() interrogates (0x81 to 0x83) levels already on the source. Levels unconfirmed at the 3s timeout get a 1s interrogate grace; those are reported already. The simulator mimics this.
- The router does not announce every change. On 2026-10-23, KiPro 4 went UDX 04 to UDX 03 with no 0x84 (the next entry's prev showed it). Hence found entries and the pre-take check. Also on 2026-10-23 at 18:01:40, a 0x84 arrived for a route Sode did not make (PIX 03 to DSM 03 and MV08 PIP015). It was logged as an ext burst, source unknown.
- Extended protect dump (0x93 matrix, level, startDst(2) to 0x94 matrix, level, count, firstDst(2), count x 2 bytes). State is in bits 4-5 of byte 1, and device is in the rest. Dest 65 was protected by device 9 on all levels. Single protect change messages (0x8B/0x8D/0x8F) not seen live.
- 2026-11-02 (branch spike/salvo-probe, cmd/swp08probe): 51 ordinary extended connects last about 840 ms (about 16 ms each, one dst after another). Pipelining saves under 10%. The router's own salvos, used as groups, work, although the spec says XD and Eclipse only. 120 is answered by 122, which echoes its 5 data bytes. 121 is answered by 123 (00 set, 01 cleared, 02 nothing to do; a clear of an empty group answers 02). The answers come in 5-7 ms. Standard layout: 4-bit level, numbers under 1024, group 0-127; probe used 127.
- 0x84 after a Go is unreliable. The spec (SW-P-88 Issue 4b 8.1.5) says none, and uninstrumented runs saw 0 and 3. Instrumented runs got one 0x84 per staged crosspoint, about 3-5 ms apart. The 0x84s came from about 100-130 ms after the Go to about 270-340 ms for 48-51 crosspoints. So a Go announces crosspoints about 4 ms apart (51 in about 210 ms), compared with about 16 ms for ordinary connects. It is not proven if the switch itself is simultaneous (that needs a scope). Sode must work either way.
- Extended stage 248 (F8 matrix level dstH dstL srcH srcL group) is acked by 250 (FA + same 7 bytes) and is held in the group. A standard Go (121) fires extended-staged crosspoints too (#154). So level 17 and numbers >= 1024 can ride the router's salvo. A Go-clear clears both kinds. It is possible that the router announces them with an ordinary 0x84 after the Go.
