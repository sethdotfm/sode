# Settings, the Advanced Settings PIN, shared saves

- Advanced Settings PIN: PBKDF2 hash in settingsPin (json:"-", never sent to browsers, SaveSettings carries it over). Access is per connection and per hash, and ends when Settings closes or the PIN changes. The PIN-entry message is handled inline in the read loop so a following lock wins. Wrong PINs counted globally, one check at a time, waits double from 30s after the 5th; pinMaxTries (default 10, 0 = never) locks until -reset-pin or restart. A non-hash settingsPin stops startup. SaveSettings is serialized by cfgMu and re-checks the lock.
- Device defaults (#49): deviceDefaults (theme, layout, clock, flip, scrollTop, searchFilters, setStack, nextMode) is what This browser uses until a browser picks its own. Not router-side, no reconnect. Browser values are localStorage strings (sode-theme, sode-layout, sode-clock, sode-flip, sode-scroll-top, sode-search-filters, sode-set-stack, sode-next-mode); missing or unknown means Global. resolve() in web/prefs.js (pure) picks own, then global, then built-in. device.js pref/setPref ('' removes) are the only readers and writers. Global defaults are cached in localStorage sode-device-defaults on every hello for web/prepaint.js (sync in each head; other pages pass data-only="theme"), which repeats resolve() inline; web/test/prepaint.test.mjs runs it against resolve() and fails on any disagreement. The This browser section and its my-default buttons live in web/devicesettings.js.
- Settings search: settingsindex.js (pure, own scorer) indexes fieldsets and labels (label[for], .sode__field-label[id], .pb-check, [data-find][data-label] for buttons etc). DICT maps section slugs (legend text) and control ids to search words. A new settings section must add its slug to DICT or settingsindex.test.mjs fails; add terms for new settings too. Esc in the box clears it, the next Esc leaves Settings. Its input events must not reach the form.


- Filter sets and presets save through saveShared (app/shared.go: takes cfgMu, guardSave(c,true) re-checks PIN or trusted user, update mutates a copy then Normalize, Validate, save, optional small broadcast) and replyOp(c, kind, id, n, noun, err) (logs the command, answers <kind>Result echoing id, sets locked). New saved-apart features use both. Name rules: validateNames in config/names.go (count, empty, 32 runes, unique ignoring case).
- Owned fields: Config fields saved outside the Settings form carry owned:"true" (filterSets, presets, settingsPin, deviceDefaults, users, maxPinLen, signInMode). saveSettings does cur.KeepOwned(live) so a stale browser copy can't change them. Form-saved fields carry guard:"router|pin|open": router reconnects (config.Changed(old,c,"router")), pin means only the Advanced Settings PIN may change it. TestEveryFieldChooses fails if a new Config field has neither tag. The Settings dialog strips owned lists from its config message (OWNED_KEYS in owned.js; socket limit wsReadLimit 64 KiB).
- Unknown keys: every config struct keeps keys this release doesn't know in Extra (json:"-"), so form saves, saveShared, the users editor (carries each user's Extra over) and imports keep them; Config.UnknownKeys lists them. An import without a top-level router key is refused as not a Sode configuration (a profile export shares filterSets and presets with Config, so only router tells them apart); otherwise configImportResult names the unknown keys in `kept` (config.NameKeys, at most 10). Known limit: a list item an older release rebuilds from browser JSON (an edited preset or filter set, a user's rights, API clients, Guest rights) loses the keys only the newer release knows.
- Inputs saved apart from the Settings form carry data-apart so the unsaved check skips them. emit('settingsClose',{discard:true}) closes Settings discarding the form.
- Grid is parked on branch archive/grids (#150); old grids: and gridConfirm: keys load and are ignored.
