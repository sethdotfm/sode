# Browser checks

Scripted headless Chrome against the real Handler and a built `swp08sim`. Never a live Ultrix: the only router a check may reach is the simulator it starts itself.

Run one area with `go test ./internal/app -run '^TestChromeEditor' -v`; the whole group serially takes several minutes. `-short` skips them before anything is built. Without `-short` they skip with a message when no Chrome or Chromium is found (looked up in `SODE_CHROME`, the macOS app paths, then PATH); `SODE_REQUIRE_BROWSER=1` (CI, rc.yml) turns that skip into a failure. Names must start with `TestChrome`: CI picks browser checks by name and `browserTest` fails any other name. In CI, `.github/scripts/browser-checks.sh` splits them into shards with `go test -list` and reruns a failure once, reporting a pass on the rerun as flaky. `SODE_BROWSER_SHOTS=/tmp/shots` saves a PNG at each `b.shot(...)` and on a timeout.

Files, all in `internal/app`:
- `browser_test.go`: the harness. `startBrowser(t)` skips or returns a tab, brought to front (Chrome 157 grants fullscreen only to the front tab); `open`, `eval` (JS, promises awaited), `waitFor(what, expr)` (fails the test on a miss, naming the check), `shot`, `check`. It collects console errors, uncaught exceptions and failed loads, and `b.check()` fails the test on any. Google Fonts load failures are ignored.
- `panelbrowser_test.go`: `startSim(t)` (`cmd/swp08sim` built once per test binary, free port, ready on its own `swp08sim on` log line so a parallel agent's simulator on the same port is never mistaken for it), `simApp(t, addr)` (real SW-P-08 client, user Ana with PIN 1234, API on) and the first check, `TestChromePanelSessionTake`: launch in Session mode, the PIN pad, stage and Take, then the tally read over REST.
- `panelrefusals_browser_test.go`: `TestChromePanelKioskAndRefusal`, a kiosk panel with the header hidden and a route outside the user's Rights refused on the page.
- `panelkeybrowser_test.go`: `TestChromePanelSetupLink` (secure mode), `TestChromeShareModalKeyTab` and `TestChromePanelLinkKeyLeavesAddress`: a keyed link loses `#key=` but keeps `?instance=` and `#kiosk=1`, a reload runs on the stored key, a rotate shows the ended-key note, and with `setItem` made to throw the key stays in the address.
- `panelassign_browser_test.go`: `TestChromeAssignSwitchesARunningPanelPage`, a keyed kiosk panel page in a second tab (`Target.createTarget`) assigned from the panels page: the server sees it hold the target's stream, its address (read with `Target.getTargets`) keeps `?instance=` and `kiosk=1` without the key, and this tab opens that address on the stored key. `TestChromeAssignToAUserModePanelShowsTheDevicesSignIn`: an Assign to a panel that acts as a user drops the page's key, opens the target and shows its own sign-in.
- `panelkeyless_browser_test.go`: `TestChromeKeylessPageIsAssignedAndRuns`, a page whose key was revoked shows the ended-key note, is listed as a Keyless instance with Key ended, and a Trusted user's Assign from the panels page switches it with no prompt; it runs the target and opens it again on a reload.
- `panelrename_browser_test.go`: `TestChromeRenameARunningPanelPageFromThePanelsPage`, two browsers: a Rename from the panels page reaches the running page named by its link, which shows the new name in its header and address and keeps it on a reload.

Add a check:
1. Name the test `TestChrome...` so one `-run` pattern finds it. Call `startBrowser(t)` first, then `startSim(t)`.
2. Build the app with `simApp`, run it (`a.Run(ctx)`), serve `a.Handler(web.FS)` from `httptest`, and make fixtures through the REST helpers (`userKey`, `makePanel`, `apiSend`). Don't use `apiTestApp` or `panelsApp` here: they replace the router with a fake.
3. Wait on the server for names and tally before opening the page (see the loop in the first check), since a page reads names only every 30 s.
4. Act with `b.eval(...)` and wait with `b.waitFor(...)` on DOM state, never `time.Sleep`. Assert the router's side through REST, not only what the page shows. End with `b.check()`.
   After a save in the panel editor, wait with `b.waitSaved(what)`, never on the Save button being disabled: Save disables it before the PUT returns. `TestBrowserChecksWaitForSaved` fails on such a wait.
   Bootstrap's reboot sets `scroll-behavior: smooth`, so `scrollTo` and `scrollIntoView` animate: after a scroll, wait for the element's rect to be in view before pressing at its coordinates (`TestChromeEditorFindFitsViewport`).
5. Keep checks few: each costs a Chrome start.

The simulator starts with destination d routed from source d on every level (`SIM_*` options: docs/reference.md).
