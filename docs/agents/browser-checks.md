# Browser checks

Scripted headless Chrome against the real Handler and a built `swp08sim`. Never a live Ultrix: a check must reach no router except the simulator it starts itself.

Run one area with `go test ./internal/app -run '^TestChromeEditor' -v`. A serial run of the whole group lasts several minutes. `-short` skips them before anything is built. Without `-short`, they skip with a message when no Chrome or Chromium is found. The search order is `SODE_CHROME`, then the macOS app paths with Chrome for Testing first, then PATH. `SODE_REQUIRE_BROWSER=1` (CI, rc.yml) turns that skip into a failure. Names must start with `TestChrome`: CI picks browser checks by name and `browserTest` fails any other name.

In CI, `.github/scripts/browser-checks.sh` splits them into shards with `go test -list`. It reruns a failure once and reports a pass on the rerun as flaky.

On macOS, install Chrome for Testing (`npx @puppeteer/browsers install chrome@stable`, then move the `.app` to /Applications). Then a headless check never shares an app with the Chrome you browse in. A leaked headless Google Chrome makes the Dock icon open no window. `watchChrome` kills a check's Chrome within about 3 s after the test binary dies. `t.Cleanup` cannot do that after a `-timeout` panic or a kill. `SODE_BROWSER_SHOTS=/tmp/shots` saves a PNG at each `b.shot(...)` and on a timeout.

Files, all in `internal/app`:
- `browser_test.go`: the harness. `startBrowser(t)` skips or returns a tab, brought to front, because Chrome 157 grants fullscreen only to the front tab. The harness also has `open`, `eval` (JS, promises awaited), `waitFor(what, expr)` (polls through a navigation, names the check on a miss), `shot` and `check`. It collects console errors, uncaught exceptions and failed loads, and `b.check()` fails the test on any.
- `panelbrowser_test.go`: `startSim(t)`, `simApp(t, addr)` and the first check. `startSim(t)` builds `cmd/swp08sim` one time per test binary and runs it on a free port. It is ready on its own `swp08sim on` log line, so the harness never mistakes a parallel agent's simulator on the same port for it. `simApp(t, addr)` gives a real SW-P-08 client, user Ana with PIN 1234 and the API on. The first check is `TestChromePanelSessionTake`: launch in Session mode, the PIN pad, stage and Take, then the tally read over REST.
- `routers_browser_test.go`: the harness for several routers, one swp08sim for each. `simRoutersApp(t, addrs)` is `simApp` with one router on each address: router A first, then B and up. With two or more routers a REST read needs `?router=`: `waitRouterRead(t, a, key, uid, name)` waits for one router's names and tally, and `routerTallyHas(t, a, key, uid, dst, src)` for a route on it. `TestChromeMainPatchesTwoRouters`: the main page patches on router A, and every match shows `A.`. Then it types `B12`, sets the default router of the Destination box to B, and types `4`. Both find router B's names with the prefix, and the default router stays after a reload. The route view shows router B's tally before and after the take. Each take reaches only its own router (REST).
