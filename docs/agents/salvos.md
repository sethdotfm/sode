# Native fire mode (#154)

`fireMode` (`sequential`, the default, or `native`) is global, and a change to it does not reconnect. `salvoGroup` is 0-127, default 127. Code: app/fire.go, swp08/salvo.go. Native mode makes the routes of a confirm land closer together (measurements in docs/agents/router-verified.md). Sode does not promise that they land in one frame.

- When: in native mode, a take of 2 or more items runs `markStages`, which sets takeReq.Stage (router levels) for each item. It stages every level that exists on the router (`ExtSalvoFits`) and that the take uses one time for that destination. If the take uses a destination and router level two times, neither item stages it, and each sends an ordinary connect. If 2 or more items have something to stage, the take goes to `takeNative`, else it is sequential. Protected and bad takes drop out in `prepare`. If fewer than 2 staged takes are left, all are sequential.
- Stage command rule: levels that `SalvoFits` accepts (matrix and router level 0-15, numbers 0-1023) use 120. Anything else (level 17, numbers >= 1024) uses the extended 248. Both ride the same Go.
- Phases: `takeNative` prepares every take (bigTake NoCheck as usual). Then `fireSalvo` runs under `App.fireMu`, which allows one fire at a time. The fire never holds `mu` across waits. `fireSalvo` does these steps:
  1. It sends Go-clear and waits for 123. If no 123 comes, Sode treats that as no group salvos and falls back.
  2. It stages each native level, with `stageChunk` (64) queued at a time. It waits for every 122 or 250, matched by decoded bytes (`swp08.Staged`). A stage that the link gave up on gets no ack, so the Go never fires with one missing.
  3. It sends Go-set (121) and waits for 123.

  A deferred Go-clear runs after every fire. Acks arrive through `a.fire` (`fireState`, set only during a fire). `onRouterMsg` passes them to `onSalvoAck`, which drops them when no fire is in progress. Each command waits `salvoReply` (1s) after its ACK. Then each take runs sendTake + complete. sendTake skips connects for native levels and interrogates them, and the waiter confirms on whichever comes first, a 0x84 or the tally.
- Waiter rules: `routeLevel.native` levels get own keys like sequential ones, because it is possible that the router announces the Go. If it does, the 0x84 is ours: it confirms the level, and the level is not `already`. `see` sets `already` for them only if `l.same`. `unregister` keeps the key of a native level that a tally confirmed until `goAt` + `salvoAnnounceFor` (2s). Then the key expires silently. A 0x84 for a route that the cache already has still uses its key (the else branch of `applyTally`). `sawOwn` extends the latest matching cause, so an External follow of a destination that the router announced late still ties to the take. The Go resets the `seen` and `now` of the native levels and sets `cause.sent`. For takes with a changed level, it also sets `cause.saw`. `awaited()` keeps confirming tallies out of found.
- Failures: a failure before the Go (no first 123, a missing ack, or a refusal from the link) clears the group. Then `unNative` turns the levels back to connects (and adds own keys), and the whole take goes sequential. Sode logs this as a salvo command with result fallback. After Sode sends the Go, it never sends the Go again and never sends connects after it. If the 123 is missing or is a 02, Sode logs it (salvo error), and the interrogates say what happened (still on, Failed/Now). In native mode only, `onRouterUp` clears the group under `fireMu` on every new session (`clearStaleSalvo`). Sequential mode sends no salvo command at all. If the router has no group salvos, each multi-take confirm waits 1s before fallback.
- Log: sent kinds salvoStage (120), salvoStageExt (248), salvoGo (121, Note "salvo N: set|clear"), in the Connects group. 122/123/250 are inbound, so they appear only through salvo command events: the fire ("N crosspoints set in X ms", fallback, error) and, after takes finish, logSalvoTiming ("N of M crosspoints confirmed, the last X ms after the Go (a by Connected, b by interrogate)"). Confirm interrogates usually answer before the router's late 0x84s, so that time is when Sode knew, not when the router switched.
- Simulator: it handles 120/248/121 with a staged list per group that all clients share. It answers 122/250/123 after 6 ms. By default it sends no Connected after a Go. SIM_SALVO_ANNOUNCE=1 sends one per changed crosspoint, from about 110 ms after the Go, 4 ms apart in dst/level order. SIM_NO_SALVO=1 ignores all three.
- Tests: fire_test.go has `fakeSalvo` (announce 0/1/2 = none, all, every other; `announceAfter` delay). TestNativeFire runs all four worlds. TestNativeFits covers level 17 and numbers >= 1024, mixed 120 and 248, and one Go. TestNativeNoExtStageAck uses `loseExt` to drop 250s.
