# Native salvos (#154)

Moved from AGENTS.md unchanged.

fireMode (sequential default, or native; global; no reconnect) and salvoGroup (0-127, default 127). Code: app/fire.go, swp08/salvo.go. Native makes a confirm's routes land closer together (see measurements above); not promised to be one frame.
- When: a batch of 2+ items in native mode runs markStages, setting takeReq.Stage (wire levels) per item: every level that exists on the router (ExtSalvoFits) and a dst+wire level used once in the batch (used twice = neither staged, an ordinary connect). If 2+ items have something to stage it goes batchNative, else sequential. Stage command rule: SalvoFits levels (matrix and wire level 0-15, numbers 0-1023) use 120, anything else (level 17, numbers >= 1024) uses extended 248; both ride the same Go. Protected and bad takes drop out in prepare; fewer than 2 staged takes left means all sequential.
- Phases: batchNative prepares every take (bigBatch NoCheck as usual), then fireSalvo under App.fireMu (one fire at a time, never holding mu across waits): Go-clear and wait for 123 (none = no group salvos, fall back), stage each native level (stageChunk 64 queued at a time) and wait for every 122 or 250 matched by decoded bytes (swp08.Staged; a stage the link gave up on gets no ack, so the Go never fires with one missing), then Go-set (121) and wait for 123. A deferred Go-clear runs after every fire. Acks arrive through a.fire (fireState, set only during a fire; onRouterMsg to onSalvoAck, dropped otherwise); each command waits salvoReply (1s) after its ACK. Then each take runs sendTake + complete: sendTake skips connects for native levels and interrogates them, and the waiter confirms on whichever comes first, a 0x84 or the tally.
- Waiter rules: takeLevel.native levels get own keys like sequential ones, because the router may announce the Go (then it is ours, confirms the level, isn't already). see sets already for them only if l.same. A native level confirmed by tally keeps its key until goAt + salvoAnnounceFor (2s) in unregister, then expires silently. A 0x84 for a route the cache already has still uses its key (applyTally else branch) and sawOwn extends the latest matching cause, so follows of a late-announced destination still tie to the take. The Go resets their seen/now and sets cause.sent, plus cause.saw for takes with a changed level. awaited() keeps confirming tallies out of found.
- Failures: anything before the Go (no first 123, a missing ack, the link refusing) clears the group, unNative turns levels back to connects (adding own keys) and the whole batch goes sequential, logged as a salvo command with result fallback. Once the Go is sent it is never resent or followed by connects: a missing 123 or a 02 is logged (salvo error) and the interrogates say what happened (still on, Failed/Now). On every new session onRouterUp clears the group under fireMu (clearStaleSalvo), native mode only; sequential mode sends no salvo command at all. A router without group salvos costs each multi-take confirm a 1s wait before fallback.
- Log: sent kinds salvoStage (120), salvoStageExt (248), salvoGo (121, Note "salvo N: set|clear"), in the Connects group. 122/123/250 are inbound, so they appear only via salvo command events: the fire ("N crosspoints set in X ms", fallback, error) and, after takes finish, logSalvoTiming ("N of M crosspoints confirmed, the last X ms after the Go (a by Connected, b by interrogate)"). Confirm interrogates usually answer before the router's late 0x84s, so that time is when Sode knew, not when the router switched.
- Simulator: 120/248/121 with a staged list per group shared by all clients, 122/250/123 after 6 ms, no Connected after a Go by default; SIM_SALVO_ANNOUNCE=1 sends one per changed crosspoint from ~110 ms after the Go, 4 ms apart in dst/level order; SIM_NO_SALVO=1 ignores all three. Tests: fire_test.go (fakeSalvo; announce 0/1/2 = none, all, every other; announceAfter delay; TestNativeFire runs all four worlds), TestNativeFits (level 17 and numbers >= 1024, mixed 120 and 248, one Go), TestNativeNoExtStageAck (loseExt drops 250s).
- Not yet seen live through Sode: extended stage, the whole path on the Ultrix, whether the switch is simultaneous, whether router follows (PiP after DSM) fire after a Go, what the router does with a group staged by a session that dropped.
