# Presets

A Preset is a saved plan: a set of entries fired in one confirm. Keep it apart from the router's own salvos in code. There, preset is the saved set (config presets, message presets, Entry.Preset, localStorage sode-presets, CSS sode__preset*). The router's salvo is only the router feature (fireMode native, salvoGroup, fire.go, swp08/salvo.go, the salvo-prefixed Communication Log kinds). Old data still loads. This covers salvos: in config.yaml (Config.LegacySalvos, moved by Normalize) and "salvo" in history lines (Entry.UnmarshalJSON). It also covers sode-salvos and sode-salvo-pins in localStorage (migrateLegacyKeys in presetstore.js), and salvo on a `batch` from a pre-rename page.

config.Preset {name, items:[{src,dsts,levels}]} is all numbers (internal src/dst, UI levels, [] = defaultLevels), never names. Caps in config/presets.go (30 presets, 100 sources, 100 dsts per source, names unique ignoring case). Global ones are cfg.presets (SavePresets in app/presets.go through saveShared, PIN-guarded like filter sets, presetsResult then a presets broadcast; owned). Per-browser ones are in localStorage sode-presets. presetstore.js is the store and pure parts (resolvePreset, parseRefs, validation mirroring Go, tested against web/test/preset_cases.json). presets.js is the strip and editor. Firing: presetPlan (plans.js) makes a plan with verb preset (leaves the boxes alone) plus plan.title and plan.warnings. The warnings are what no longer exists on the router, shown and left out. The showing layout opens its normal confirm through presetHost({active,confirm,patch}). sendTakes sends one `batch`: one History Group, Undo all. bigTake (6)+ skips the pre-take check. With fireMode native it fires as one group send.
- History trigger: sendTakes sends the bare name as a top-level preset string on `batch`. The handler cleans it (cleanPresetName: printable runes, 32 max) and sets takeReq.Preset. The name is not matched against cfg.Presets, since per-browser ones exist. planPhase copies it to Entry.Preset. Groups show Preset: name (folderTitle), single takes through entryNote. Quick search matches it. Retry, redo and undo do not carry it; ext rows never have it.
- Pinning: Preset.Pinned (*bool, nil = true, filled by normalizePresets; local presets carry their own). The strip shows effective pins (pinnedPresets, effectivePin): this browser's override sode-preset-pins {lowercase name: bool} (everyone's presets only) beats the flag. setLocalPin drops an override equal to the flag. Pinning for everyone is only in the editor (its Pinned checkbox); the popup has no Pin-for-everyone or Share. With presets but none pinned the strip shows Presets… (Ctrl+G). Strip DOM order is arrow-key order: Edit, Show all, pinned chips. Edit and Filters share .sode__chipbtn (desktop only).
- Filters and the preset editor work alike: an editable name box, and Save writes the new name with the rest. A name already in use in that scope is refused, and there is no Rename button. Save as… is the only other name row. Both have the same layout: picker alone, then name, Save for, Save, Save as…, Share, Delete, then Save as row, PIN row, note, share link. If you change one set bar, change both. Every field has a small label above it (labeled() in widgets.js, class sode__fld; index.html's Filters markup uses the same label class).
- Scope move: Save for stays enabled for a saved preset or set. cur.from is where it lives, cur.scope what the select says. If they differ, it is a move. The move copies into the target first (a name already in use is refused). Then it removes from the source (removeFrom, removeSet, moveTo) and drops this browser's pin override when it leaves Everyone.
- Add from History… hides the editor and starts pick mode (historypick.js). Each mode is a descriptor in MODES (text, count, Add, Esc rule), and picking()/boxPicking() ask the mode. indexRows and pickedTakes are pure. Both layouts call picking()/pickBox(key) while they build rows, and redraw on pick. bindPick(list) turns History clicks into ticks except the Group disclosure. Keys e<id> and f<group>; Include External follow entries adds e.follows and f.followers. Esc, locking or a lost socket cancels.
- Add from Patch Boxes… (same bar and state, startPick({mode:'boxes'})): the editor steps aside. The patch boxes stay live (data-sode-pick="boxes", CSS hides Take). The bar's Add or Enter (patchNow; phone last step: boxPicking()/addPatch()) turns the boxes' patch into a row and calls the host's clear(). Done, a lock or a lost socket returns, and Esc too unless a box has text or an open list. picking() is false in this mode so History keeps its buttons.
- Dialog look: buttons beside a labelled field are full height (no pb-btn--sm), bottom-aligned. Preset editor: action row (Add row, Add from Patch Boxes…, Add from History…) above the rows, and labels on the first row only. Blank rows are ignored on save (isBlankRow). Footer: Import & Export…, Cancel, Save (saves and closes). Filters footer: Clear all, Cancel, Save. Cancel, Esc and a click outside restore the filter and set as on open (openSnap, filterstore snapshot/restore). Save writes the edited/renamed/moved set (saveSet(done)) and closes when done runs, that is, after the write has landed (the server's answer for Everyone or Me). It stays open for a PIN or error. Every landed write (save, save as, move, delete) calls landed() to move the Cancel snapshot forward, so Cancel never rolls back past it. Show all is a plain chip with a list icon; a preset chip's tip is presetTip (SRC to DST, SRC to N Destinations). The editor ("Edit Presets") and the popup ("All Presets") link to each other from their headers (Preset Organizer / Preset Editor, desktop).
- Shift-click a preset (strip chip, Alt+Shift+1-9, or Shift+click / Shift+Enter in the popup): fillBoxes (presets.js) puts its first existing take into the boxes. It goes through the host's fill (desktop only) and sends nothing. A preset of several says only the first was filled.
- Alt on Windows/Linux: the release of a bare Alt would focus the browser's menu bar. So presetkeys.js cancels the Alt keyup (not on a Mac) while presets show. Alt+digit, Alt+P and Alt+arrows cancel their keydown. Unverified on a real Windows browser.
- Pin order: for a signed-in user, the pinned presets' order (strip and popup) is Profile.PinOrder. Else it is this browser's sode-preset-order. PinOrder keys are scope:lowercase name, built by presetKey in the browser and opaque to Go. config/profile.go trims, deduplicates and caps them, but never lowercases them, since Go's ToLower and JS's differ. They are saved with profileSave pinOrder. pinnedPresets/orderPins/setPinOrder/movePin/moveKey in presetstore.js are the one source. The popup's drag and Alt+arrows call movePin {before}|{by}. setPinOrder returns the save; a failed one is redrawn from the real order. Unlisted pins come after, and stale keys are ignored. The popup lists pinned first, with a column that shows each Alt+1-9 slot. With an empty search they drag (grip icon too) or move with Alt+arrows / Alt+Cmd/Ctrl+J/K.
- Key hints: the boxes' own s/d/f (and Shift+S/D in the filter boxes) show only in keyboard mode. That is html[data-keys-on], set with the hist class by setKeys in desktop.js, cleared on click or when History loses focus. The closed Next chip shows its Ctrl+Shift key after the tag. While Alt is held (html[data-alt], keys.js), the first nine preset chips wipe an accent-coloured Alt+1-9 in from their right edge. The key (.sode__chip-key) is absolute and clipped with clip-path on itself. Never use overflow hidden on the chip, which clips its data-pb-tip. The shortcuts dialog is in sections (index.html): add new keys there.
- One-row chip lists: History's filter-set chips and the Presets strip (.sode__sets) stay on one row. The first chip (All, Show all) and its divider are pinned. The rest are in .sode__sets-run, which scrolls sideways (styled scrollbar on desktop, hidden on phone). Desktop History is a title row, then one row with the Filter by boxes (always side by side) and the sets plus Filters button (.sode__recent-tools). Preset chips are control-height tall to read apart from filter chips. data-pb-tip tips cannot hang off a chip in a scroller. So CSS hides them there, and tooltip.js shows the same text in its floating .pb-tip (hover and focus).
- Source/Destination lists (desktop): focus on a box with no text, or with a confirmed choice, lists nothing. showall.js shows a small "Show all sources/destinations" button under it. The button also shows when a search finds nothing, and hides while a list is open. The button or a bare ↓/↑ opens the whole list (combobox.browse). The chosen item is highlighted, and no cursor is drawn until ↓/↑ moves it: the first forward press lands on the row the list stands at. Enter/Tab/+ accept a row only after it is clicked or the highlight moved (browsing, set only by browse, cleared by any other show/move). cb.moved says the list is a browse list that was moved. desktop.js wantsMatch is the one test that Enter, Tab and addDst use. The list is windowed (listwindow.js, 150 rows, grown by scroll and redrawn around the row on a jump or wrap). Rows have no listeners; one pair on the menu reads data-i. So a thousand names cost nothing. A typed list is drawn whole. A names update redraws the focused box's open list on the row it was on (showList). A closed one stays closed. The count and keys line is a sibling element in .sode__menu-pop next to the ul (the combobox foot option), so nothing measures its place. Unconfirmed text keeps its matches. Esc closes the list first, then clears or enters keyboard mode.
- Popup: presetpopup.js, opened by emit('presetPopup') so presets.js does not import it. Ctrl+G (Cmd+G on Mac) opens it from any box, except with Settings, a modal, the phone sheet or a lock up. Search (rankPresets), all presets with scope and Pin/Unpin; arrows or Ctrl+J/K move, Enter closes and fires, Esc clears then closes. Hidden presets stay fireable. Phone: a Presets button ends the strip. Keyboard mode p focuses the first preset chip (emit('presetStrip')).
