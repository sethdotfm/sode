# Presets

A Preset is a saved plan: a set of entries fired in one confirm. Keep it apart from the router's own salvos in code. There, preset is the saved set (config presets, message presets, Entry.Preset, localStorage sode-presets, CSS sode__preset*). The router's salvo is only the router feature (fireMode native, salvoGroup, fire.go, swp08/salvo.go, the salvo-prefixed Communication Log kinds).

config.Preset is {id, name, items:[{src,dsts,levels}]}. src and each dsts entry is a router reference {router, n, name} (config.Ref). One item is one route on one router; one preset can hold items of different routers. n is the internal number, levels are UI levels ([] = defaultLevels). Normalize fills a blank router with the one router's UID, drops `shown`, and gives a blank or repeated id a new one. Validate never refuses an unknown router, since Load runs it; such an item is Broken. On save, the server puts the router's live names into the references (namePresets in app/presets.go, Everyone and Me). A number the router does not name keeps its name. The hidden id stays through a rename. WithPresetExtras matches on it. A preset sent without an id gets the saved id of its name (a Replace). Pins, pin order, Rights and (later) panel cells and Default artwork name a preset by it. Caps in config/presets.go (30 presets, 100 sources, 100 dsts per source, names unique ignoring case). MaxPresetsBytes (48 KiB) binds before the count caps now: about 660 references fit in the worst case (5-digit numbers, 16-character names; TestPresetsMessageFits). Global ones are cfg.presets (SavePresets in app/presets.go through saveList, Trusted user like filter sets, presetsResult then a presets broadcast). Per-browser ones are in localStorage sode-presets in the same stored shape. The browser makes their id (newPresetId), and their router is the hello's routerUid. presetref.js (pure) reads a stored item into numbers {src, dsts, levels, router, srcName, dstNames} (itemNums). itemRefs makes the stored form again. saved() names each reference with the router's name now, else with the kept name. Panel pages read /api/v1/presets items through itemPlain. presetstore.js is the store and pure parts (resolvePreset, parseRefs, validation mirroring Go, tested against web/test/preset_cases.json). presets.js is the strip and editor. Firing: presetPlan (plans.js) makes a plan with verb preset (leaves the boxes alone) plus plan.title and plan.warnings. The warnings are what no longer exists on the router, shown and left out. A preset has `broken` and `moved` lists (config.Missing), which the Broken check keeps (docs/agents/server.md). Browsers never send the marks: WithPresetExtras keeps the saved ones by id, and panelStore.replaceBody does the same for panels. normPreset keeps `broken` and `moved`, and presetPlan leaves out a reference `broken` lists, since the shown names keep a gone number. A part left out for a mark is not in plan.warnings: the Broken banner names it. The API's planPreset does the same. It names each part it leaves out as `CAM 3 (source 13)`, or `source 13` with no stored name. The showing layout opens its normal confirm through presetHost({active,confirm,patch}). sendTakes sends one `take` with `preset` (the name, for History) and `presetId` (for Rights): one History Group, Undo all. bigTake (6)+ reads the whole take before it (checkRoutes, docs/agents/server.md). With fireMode native it fires as one group send.
- History trigger: sendTakes sends the bare name as a top-level preset string on `take`. The handler cleans it (cleanPresetName: printable runes, 32 max) and sets takeReq.Preset. The name is not matched against cfg.Presets, since per-browser ones exist. planPhase copies it to Entry.Preset. Groups show Preset: name (folderTitle), single takes through entryNote. Quick search matches it. Retry, redo and undo do not carry it; ext rows never have it.
- Pinning: Preset.Pinned (*bool, nil = true, filled by normalizePresets; local presets carry their own). The strip shows effective pins (pinnedPresets, effectivePin): this browser's override sode-preset-pins {id: bool} (everyone's presets only) beats the flag. setLocalPin drops an override equal to the flag. Pinning for everyone is only in the editor (its Pinned checkbox); the popup has no Pin-for-everyone or Item link. With presets but none pinned the strip shows Presets… (Ctrl+G). Strip DOM order is arrow-key order: Edit, Show all, pinned chips. Edit and Filters share .sode__chipbtn (desktop only).
- Filters and the preset editor work alike: an editable name box, and Save writes the new name with the rest. A name already in use in that scope is refused, and there is no Rename button. Save as… is the only other name row. Both have the same layout: picker alone, then name, Save for, Save, Save as…, Delete, then Save as row, PIN row, note. The preset editor adds Item link before Delete and the Item link box after the note, for an Everyone or Me preset only. Filter sets have no Item link. If you change one set bar, change both. Every field has a small label above it (labeled() in widgets.js, class sode__fld; index.html's Filters markup uses the same label class).
- The editor holds the preset's id (cur.id) through a rename and a Scope move. Save as… sends no id, so it gets a new one; Save as… over a taken name keeps that preset's id. build() carries the names of numbers the rows cannot show (carryNames).
- Scope move: Save for stays enabled for a saved preset or set. cur.from is where it lives, cur.scope what the select says. If they differ, it is a move. The move copies into the target first (a name already in use is refused). Then it removes from the source (removeFrom, removeSet, moveTo) and drops this browser's pin override when it leaves Everyone.
- Add from History… hides the editor and starts pick mode (historypick.js). Each mode is a descriptor in MODES (text, count, Add, Esc rule), and picking()/boxPicking() ask the mode. indexRows and pickedTakes are pure. Both layouts call picking()/pickBox(key) while they build rows, and redraw on pick. bindPick(list) turns History clicks into ticks except the Group disclosure. Keys e<id> and f<group>; Include External follow entries adds e.follows and f.followers. Esc, locking or a lost socket cancels.
- Add from Patch Boxes… (same bar and state, startPick({mode:'boxes'})): the editor steps aside. The patch boxes stay live (data-sode-pick="boxes", CSS hides Take). The bar's Add or Enter (patchNow; phone last step: boxPicking()/addPatch()) turns the boxes' patch into a row and calls the host's clear(). Done, a lock or a lost socket returns, and Esc too unless a box has text or an open list. picking() is false in this mode so History keeps its buttons.
- Dialog look: buttons beside a labelled field are full height (no pb-btn--sm), bottom-aligned. Preset editor: action row (Add row, Add from Patch Boxes…, Add from History…) above the rows, and labels on the first row only. Blank rows are ignored on save (isBlankRow). Footer: Import & Export…, Cancel, Save (saves and closes). Filters footer: Clear all, Cancel, Save. Cancel, Esc and a click outside restore the filter and set as on open (openSnap, filterstore snapshot/restore). Save writes the edited/renamed/moved set (saveSet(done)) and closes when done runs, that is, after the write has landed (the server's answer for Everyone or Me). It stays open for a PIN or error. Every landed write (save, save as, move, delete) calls landed() to move the Cancel snapshot forward, so Cancel never rolls back past it. Show all is a plain chip with a list icon; a preset chip's tip is presetTip (SRC to DST, SRC to N Destinations). The editor ("Edit Presets") and the popup ("All Presets") link to each other from their headers (Preset Organizer / Preset Editor, desktop).
- Shift-click a preset (strip chip, Alt+Shift+1-9, or Shift+click / Shift+Enter in the popup): fillBoxes (presets.js) puts its first existing take into the boxes. It goes through the host's fill (desktop only) and sends nothing. A preset of several says only the first was filled.
- Alt on Windows/Linux: the release of a bare Alt would focus the browser's menu bar. So presetkeys.js cancels the Alt keyup (not on a Mac) while presets show. Alt+digit, Alt+P and Alt+arrows cancel their keydown. Unverified on a real Windows browser.
- Pin order: for a signed-in user, the pinned presets' order (strip and popup) is Profile.PinOrder. Else it is this browser's sode-preset-order. PinOrder keys are scope:id, built by presetKey in the browser and opaque to Go, so a rename keeps the place. config/profile.go trims, deduplicates and caps them, but never lowercases them, since Go's ToLower and JS's differ. They are saved with profileSave pinOrder. pinnedPresets/orderPins/setPinOrder/movePin/moveKey in presetstore.js are the one source. The popup's drag and Alt+arrows call movePin {before}|{by}. setPinOrder returns the save; a failed one is redrawn from the real order. Unlisted pins come after, and stale keys are ignored. The popup lists pinned first, with a column that shows each Alt+1-9 slot. With an empty search they drag (grip icon too) or move with Alt+arrows / Alt+Cmd/Ctrl+J/K.
- Key hints: the boxes' own s/d/f (and Shift+S/D in the filter boxes) show only in keyboard mode. That is html[data-keys-on], set with the hist class by setKeys in desktop.js, cleared on click or when History loses focus. The closed Next chip shows its Ctrl+Shift key after the tag. While Alt is held (html[data-alt], keys.js), the first nine preset chips wipe an accent-coloured Alt+1-9 in from their right edge. The key (.sode__chip-key) is absolute and clipped with clip-path on itself. Never use overflow hidden on the chip, which clips its data-pb-tip. The shortcuts dialog is in sections (index.html): add new keys there.
- One-row chip lists: History's filter-set chips and the Presets strip (.sode__sets) stay on one row. The first chip (All, Show all) and its divider are pinned. The rest are in .sode__sets-run, which scrolls sideways (styled scrollbar on desktop, hidden on phone). Desktop History is a title row, then one row with the Filter by boxes (always side by side) and the sets plus Filters button (.sode__recent-tools). Preset chips are control-height tall to read apart from filter chips. data-pb-tip tips cannot hang off a chip in a scroller. So CSS hides them there, and tooltip.js shows the same text in its floating .pb-tip (hover and focus).
- Source/Destination lists (desktop): focus on a box with no text, or with a confirmed choice, lists nothing. showall.js shows a small "Show all sources/destinations" button under it. The button also shows when a search finds nothing, and hides while a list is open. The button or a bare ↓/↑ opens the whole list (combobox.browse). The chosen item is highlighted, and no cursor is drawn until ↓/↑ moves it: the first forward press lands on the row the list stands at. Enter/Tab/+ accept a row only after it is clicked or the highlight moved (browsing, set only by browse, cleared by any other show/move). cb.moved says the list is a browse list that was moved. desktop.js wantsMatch is the one test that Enter, Tab and addDst use. The list is windowed (listwindow.js, 150 rows, grown by scroll and redrawn around the row on a jump or wrap). Rows have no listeners; one pair on the menu reads data-i. So a thousand names cost nothing. A typed list is drawn whole. A names update redraws the focused box's open list on the row it was on (showList). A closed one stays closed. The count and keys line is a sibling element in .sode__menu-pop next to the ul (the combobox foot option), so nothing measures its place. Unconfirmed text keeps its matches. Esc closes the list first, then clears or enters keyboard mode.
- Popup: presetpopup.js, opened by emit('presetPopup') so presets.js does not import it. Ctrl+G (Cmd+G on Mac) opens it from any box, except with Settings, a modal, the phone sheet or a lock up. Search (rankPresets), all presets with scope and Pin/Unpin; arrows or Ctrl+J/K move, Enter closes and fires, Esc clears then closes. Hidden presets stay fireable. Phone: a Presets button ends the strip. Keyboard mode p focuses the first preset chip (emit('presetStrip')).

- Broken banner and status (web/brokenrules.js pure, node-tested; brokenview.js, brokenbanner.js, brokenbadge.js; GLOSSARY.md Broken and Name moved): `fire` (presets.js) and `pickSet`/`toggleSet` (filterstore.js) emit `itemUsed`. The banner (`[data-broken]`, one copy per layout) shows one entry per used item with Broken marks. Each entry has the left-out lines (`leftOutLines`) and Edit for whoever can edit it (`editPresetAt`, `editFilterSetAt`). An Administrator also gets Swap… (`swapAt`). settings.js then opens Settings > Routers and the Swap dialog with the side and number, and runs Find. A mark counts only while the item still holds that reference (`presetMarks`, `filterSetMarks`), because the server keeps old marks until its next name read. So an edit that drops the reference clears the entry at once. Dismiss keeps the entry hidden while its marks stay the same, for the page's lifetime; a new missing part shows it again. Name moved alone never shows it. Filter set entries keep the server's `broken` beside `f`, so a save never sends them. This browser's presets and sets have no server marks. `localPresetMarks` finds Name moved and `localFilterMarks` finds an exact term no name matches. A gone number cannot be seen there, since the shown names keep its old name. Status with text (`statusBadge`) is in the strip chips, the popup and the /panels list. The editor's picker and the filter set select show the text only, and the filter set chips show both. A Buttons panel cell gets an icon only (`cellStatus`, panelview.js). Grid panel cells and the editors show none yet.
- Broken and Name moved counts (web/brokencount.js; server brokencount.go): `brokenCount` counts everyone's items and needs an Administrator. `brokenCount {mine}` counts a signed-in user's Me items and owned panels. Each answers per router with `broken`, `moved` and the items. An item with both kinds of mark counts as Broken. The page shows the server's numbers in Settings > Routers (`router-1-broken`) and the user's own Profile dialog (`account-broken`, profiles.js). Each count has a list with Swap… and Edit. Counts follow the server's marks, so an edit shows in the count after the next name read.
- Replace term (web/filterreplace.js): the Filters dialog shows a row for each Broken number or exact term of the active set still in the text (`replaceRows`). `replaceTerm` swaps it in the filter like a hand edit; Save stores it. The box holds the mark's `now`, the name the Broken check saw replace the old one (docs/agents/server.md).
