# Presets

A Preset is a saved plan: a set of entries fired in one confirm. Keep it apart from the router's own salvos in code. There, preset is the saved set (config presets, message presets, Entry.Preset, localStorage sode-presets, CSS sode__preset*). The router's salvo is only the router feature (fireMode native, salvoGroup, fire.go, swp08/salvo.go, the salvo-prefixed Communication Log kinds).

config.Preset is {id, name, items:[{src,dsts,levels}]}. src and each dsts entry is a router reference {router, n, name} (config.Ref). One item is one route on one router; one preset can hold items of different routers. n is the internal number, levels are UI levels ([] = defaultLevels). Normalize fills a blank router with the one router's UID, drops `shown`, and gives a blank or repeated id a new one. Validate never refuses an unknown router, since Load runs it; such an item is Broken. On save, the server puts the router's live names into the references (namePresets in app/presets.go, Everyone and Me). A number the router does not name keeps its name. The hidden id stays through a rename. WithPresetExtras matches on it. A preset sent without an id gets the saved id of its name (a Replace). Bookmarks (`preset:<scope>:<id>`), Rights and panel cells and Default artwork name a preset by it. Caps in config/presets.go (30 presets, 100 sources, 100 dsts per source, names unique ignoring case). MaxPresetsBytes (48 KiB) binds before the count caps now: about 660 references fit in the worst case (5-digit numbers, 16-character names; TestPresetsMessageFits). Global ones are cfg.presets (SavePresets in app/presets.go through saveList, Trusted user like filter sets, presetsResult then a presets broadcast). Per-browser ones are in localStorage sode-presets in the same stored shape. The browser makes their id (newPresetId), and their router is the hello's routerUid. presetref.js (pure) reads a stored item into numbers {src, dsts, levels, router, srcName, dstNames} (itemNums). itemRefs makes the stored form again. saved() names each reference with the router's name now, else with the kept name. Panel pages read /api/v1/presets items through itemPlain. presetstore.js is the store and pure parts (resolvePreset, parseRefs, validation mirroring Go, tested against web/test/preset_cases.json). presets.js is the strip and editor. Firing: presetPlan (plans.js) makes a plan with verb preset (leaves the boxes alone) plus plan.title and plan.warnings. The warnings are what no longer exists on the router, shown and left out. A preset has `broken` and `moved` lists (config.Missing), which the Broken check keeps (docs/agents/server.md). Browsers never send the marks: WithPresetExtras keeps the saved ones by id, and panelStore.replaceBody does the same for panels. normPreset keeps `broken` and `moved`, and presetPlan leaves out a reference `broken` lists, since the shown names keep a gone number. A part left out for a mark is not in plan.warnings: the Broken banner names it. The API's planPreset does the same. It names each part it leaves out as `CAM 3 (source 13)`, or `source 13` with no stored name. The showing layout opens its normal confirm through presetHost({active,confirm,patch}). sendTakes sends one `take` with `preset` (the name, for History) and `presetId` (for Rights): one History Group, Undo all. bigTake (6)+ reads the whole take before it (checkRoutes, docs/agents/server.md). With fireMode native it fires as one group send.
- History trigger: sendTakes sends the bare name as a top-level preset string on `take`. The handler cleans it (cleanPresetName: printable runes, 32 max) and sets takeReq.Preset. The name is not matched against cfg.Presets, since per-browser ones exist. planPhase copies it to Entry.Preset. Groups show Preset: name (folderTitle), single takes through entryNote. Quick search matches it. Retry, redo and undo do not carry it; ext rows never have it.
- Bookmarks (GLOSSARY.md, Bookmark) took the place of pins. v2 is a clean install, so nothing reads the old `pinned` flag, `pinOrder`, `sode-preset-pins` or `sode-preset-order`. The Bookmarks strip is bookmarks.js, in [data-presets] in both layouts. It is one row. It holds the Bookmarks label, Edit (the Bookmarks editor), All presets (the Presets popup, Ctrl+G) and a chip for each bookmark of the shown list. All presets has the popup's name, since the popup lists presets, not bookmarks. Edit and All presets are the same ghost button. Strip DOM order is arrow-key order. Edit, All presets and Filters share .sode__chipbtn (desktop only).
- Bookmark lists: Everyone's is cfg.bookmarks (message `bookmarks`, a Trusted user or an Administrator, saveList; the hello carries it). Me is Profile.bookmarks (profileSave `bookmarks`). This browser's is localStorage `sode-bookmarks`. The export file carries all three: Everyone's in bookmarks.yaml, Me in the profile, This browser's in browser.yaml (docs/agents/profiles.md). bookmarkstore.js reads and saves them, bookmarkrules.js holds the pure rules (node-tested), and web/test/bookmark_cases.json holds the refusals that config/bookmarks.go checks too. A bookmark is { key } (a Palette row key, palettecatalogue.js) or { url } (http: or https: only), plus label and newTab. Sode refuses a list over 24. It refuses a URL with a user name, a `#key=`, `#setup=` or `#share=` part, or a `key`, `token` or `setup` query. The strip shows one list, never merged: This browser's if it has one, else Me, else Everyone (shownList).
- A bookmark opens its row through the Palette's runRow (palette.js), so it has the row's guards. A preset asks for its Confirm, and Clear History still confirms. A bookmark of a Settings button that an action does (Sign out) is that action (`alias`, docs/agents/web-layout.md). A row outside the Rights or Role shows No access and opens the Palette on its why (explainRow), with Step in or Approval. A row that is gone shows Missing, and a locked page shows Sign in. Until paletteRowsReady has read the settings and panels, nothing shows Missing. A row's live label wins over the stored label, which shows only while the target is Missing. Open in a new tab is for pages, panels and URLs (window.open with noopener). Bookmarks do not show in the Palette. Palette pins (GLOSSARY.md, Palette pin) are a list of their own. Me is Profile.palettePins (profileSave `palettePins`). This browser's is localStorage `sode-palette-pins`. There is no Everyone list, and a signed-in user sees only Me pins. pinstore.js reads and saves them, and pinrules.js holds the pure rules (node-tested). web/test/pin_cases.json holds the refusals that config/palette.go (PalettePinsProblem) checks too. A list holds at most 24 row keys, with no repeats. The export file carries pins where it carries the bookmarks of the same scope. Me pins are in the profile (users.yaml, and the own export's Profile). This browser's pins are in browser.yaml. A pin is the only way a grey row shows in the Palette. paletteView drops other grey rows, also in the Bookmarks editor's Add. The Palette's Alt+B, or Bookmark in a row's ⋯ menu, adds the row to the person's own list or removes it. That list is Me, or This browser for a Guest. The Palette never changes Everyone's list.
- Renames: a preset and a filter set keep their hidden id, so a bookmark key (`preset:<scope>:<id>`, `filterSet:<scope>:<id>`) stays. Every bookmark on the item works after a rename, in all lists and all profiles. Only the stored label changes, and only in the same scope's list. The server changes it in the same save (RenamedPresetBookmarks, RenamedSetBookmarks). The page changes This browser's list (relabelLocalBookmarks). The `presets` and `filterSets` messages carry Everyone's bookmarks after the save.
- Filters and the preset editor work alike: an editable name box, and Save writes the new name with the rest. A name already in use in that scope is refused, and there is no Rename button. Save as… is the only other name row. Both have the same layout: picker alone, then name, Save for, Save, Save as…, Delete, then Save as row, PIN row, note. The preset editor adds Item link before Delete and the Item link box after the note, for an Everyone or Me preset only. Filter sets have no Item link. If you change one set bar, change both. Every field has a small label above it (labeled() in widgets.js, class sode__fld; index.html's Filters markup uses the same label class).
- The editor holds the preset's id (cur.id) through a rename and a Scope move. Save as… sends no id, so it gets a new one; Save as… over a taken name keeps that preset's id. The Filters dialog does the same with the active set's id (saveSet, saveName in filters.js). The page makes a new set's id (newPresetId), so the active set names it before the save lands. build() carries the names of numbers the rows cannot show (carryNames).
- Scope move: Save for stays enabled for a saved preset or set. cur.from is where it lives, cur.scope what the select says. If they differ, it is a move. The move copies into the target first (a name already in use is refused). Then it removes from the source (removeFrom, removeSet, moveTo) and drops this browser's pin override when it leaves Everyone.
- Add from History… hides the editor and starts pick mode (historypick.js). Each mode is a descriptor in MODES (text, count, Add, Esc rule), and picking() asks it. indexRows and pickedTakes are pure. Both layouts call picking()/pickBox(key) while they build rows, and redraw on pick. bindPick(list) turns History clicks into ticks except the Group disclosure. Keys e<id> and f<group>; Include External follow entries adds e.follows and f.followers. Esc, locking or a lost socket cancels.
- Add from Patch Boxes… is a session in presetadd.js (`presetAdd`: active, label, rows, add, addPatch, done, end). It emits one event, `presetAdd`. It is a leaf module, so the layouts, the Grid popup, the pick bar and the editor all read it. The editor steps aside and starts it; the patch boxes stay live (data-sode-pick="boxes"). historypick.js shows the same bar in mode 'boxes' while the session is active and reads its label and note. Every Take paints from the host's takeState() (`{ word, ok, disabled }`, presets.js presetHost). That is desktop.js paintTakes, the phone's Go (mobile.js paintGo) and the popup's Take. Take reads Add in the add colour, so the bar has no Add of its own (MODES.boxes.addShown). Take or Enter (patchNow; phone last step: addBoxes) calls presetAdd.addPatch with the boxes' patch and clears the boxes on an add. There is one add path: presets.js addToPreset, for the boxes and the grid alike. It drops rows already there ("Already in the preset.") and refuses rows that would fail Save (itemsToAdd: clash, caps). A failed grid add keeps the bar's row count; a failed boxes add puts the reason in the bar. Done, a lock or a lost socket ends the session. Esc ends it too, unless a box has text or an open list. While the Grid popup covers the bar (presetAdd.cover), Esc closes the popup only. picking() is false in this mode so History keeps its buttons. The bar's left padding is the larger of the page content's left edge (#patch-view) and the lock chip's right edge plus a gap (clearChip).
- The Grid popup in that mode (gridpopup.js paintMode on `presetAdd`): an accent header names the preset and `.sode-gridpop[data-adding]` is set. The adapter's pressMode() gives the add policy (gridpaneladd.js addPolicy), else null. The body (gridpanelrun.js) asks only pressMode(). With a policy nothing is staged or sent. Take reads Add and calls the host's take(); Clear goes, Done ends the session and the shield is off (gridShield's off()). A crosspoint press, or Enter/Space on the cursor, adds that route. gridKeyAction gets `canSend: false`: Enter presses as Space does, and line, unstage, Undo and confirm do nothing. Its levels are the main Levels box's, [] while it is empty, as the boxes' Add (gridpoprules.js storedItems). A destination name adds its source now on the chosen levels (pressLevels, resolved), one row per source (gridpanelnow.js dstNow). A level whose source is outside the Rights is left out and counted. A source name adds every destination on the grid it goes to now, one row per level set (srcNow). Lines, spans and picks do nothing. The popup's note says what it added (gridpoprules.js addedLine, noRouteLine) and the bar counts rows. The preset's rows show on the grid. The policy's marks() is presetMarks with the host's words. It stays one object until fresh(), which the popup calls on each `presetAdd`. The body paints in full on a new one. paintXp and the names set the generic data-mark, and a destination's held mark shows the host's word ("in preset"). The band's `.sode-gridpop__rows` badge counts the rows (rowsWord). The bar's Switch to grid view emits `gridOpen`, so historypick.js does not import gridpopup.js.
- Dialog look: buttons beside a labelled field are full height (no pb-btn--sm), bottom-aligned. Preset editor: action row (Add row, Add from Patch Boxes…, Add from History…) above the rows, and labels on the first row only. Blank rows are ignored on save (isBlankRow). Footer: Import & Export…, Cancel, Save (saves and closes). Filters footer: Clear all, Cancel, Save. Cancel, Esc and a click outside restore the filter and set as on open (openSnap, filterstore snapshot/restore). Save writes the edited/renamed/moved set (saveSet(done)) and closes when done runs, that is, after the write has landed (the server's answer for Everyone or Me). It stays open for a PIN or error. Every landed write (save, save as, move, delete) calls landed() to move the Cancel snapshot forward, so Cancel never rolls back past it. All presets is a ghost button with a list icon; a preset chip's tip is presetTip (SRC to DST, SRC to N Destinations). The editor ("Edit Presets") and the popup ("All Presets") link to each other from their headers (Preset Organizer / Preset Editor, desktop).
- Shift-click a preset (its bookmark chip, Alt+Shift+1-9 or Shift+Enter in the popup): fillBoxes (presets.js) puts its first existing take into the boxes. It goes through the host's fill (desktop only) and sends nothing. A preset of several says only the first was filled.
- Alt on Windows/Linux: the release of a bare Alt would focus the browser's menu bar. So presetkeys.js cancels the Alt keyup (not on a Mac) while the strip shows. Alt+digit and Alt+arrows cancel their keydown. Unverified on a real Windows browser.
- Bookmarks editor (bookmarkeditor.js, the strip's Edit): one list at a time, picked in List. The edits are a draft until Save, and a second close or list change discards them. Rows move by drag, Alt+arrows on a focused row or the arrow buttons (moveBookmark). Adding has two labelled rows, From the Palette and Web address (address, Name, Add). Add from the Palette… opens the Palette in pick mode (openPalette({ pick, cancel })). The rows are one subgrid (.sode-bm__list), so the ticks and buttons line up; an absent tick is an empty cell. The dialog is wider than Filters by a rule on .sode-bm only. `#bm-count` shows only from BOOKMARKS_MAX − 5. At the cap the add controls are off and `#bm-full` says why (aria-describedby), since a disabled button shows no tip. Everyone's list is read-only below a Trusted user (canEditEveryone).
- Key hints: the boxes' own s/d/f (and Shift+S/D in the filter boxes) show only in keyboard mode. That is html[data-keys-on], set with the hist class by setKeys in desktop.js, cleared on click or when History loses focus. The closed Next chip shows its Ctrl+Shift key after the tag. While Alt is held (html[data-alt], keys.js), the first nine bookmark chips wipe an accent-coloured Alt+1-9 in from their right edge. The key (.sode__chip-key) is absolute and clipped with clip-path on itself. Never use overflow hidden on the chip, which clips its data-pb-tip. The shortcuts dialog is in sections (index.html): add new keys there.
- One-row chip lists: History's filter-set chips and the Bookmarks strip (.sode__sets) stay on one row. History's first chip (All) and its divider are pinned; in the Bookmarks strip Edit and All presets stay outside the run. The rest are in .sode__sets-run, which scrolls sideways (styled scrollbar on desktop, hidden on phone). Desktop History is a title row, then one row with the Filter by boxes (always side by side) and the sets plus Filters button (.sode__recent-tools). Bookmark chips are control-height tall to read apart from filter chips. data-pb-tip tips cannot hang off a chip in a scroller. So CSS hides them there, and tooltip.js shows the same text in its floating .pb-tip (hover and focus).
- Source/Destination lists (desktop): focus on a box with no text, or with a confirmed choice, lists nothing. showall.js shows a small "Show all sources/destinations" button under it. The button shows at all times, also with no box focused, so a user with only a mouse has a place to start. Only an open list hides it. The button or a bare ↓/↑ opens the whole list (combobox.browse). The chosen item is highlighted, and no cursor is drawn until ↓/↑ moves it: the first forward press lands on the row the list stands at. Enter/Tab/+ accept a row only after it is clicked or the highlight moved (browsing, set only by browse, cleared by any other show/move). cb.moved says the list is a browse list that was moved. desktop.js wantsMatch is the one test that Enter, Tab and addDst use. The list is windowed (listwindow.js, 150 rows, grown by scroll and redrawn around the row on a jump or wrap). Rows have no listeners; one pair on the menu reads data-i. So a thousand names cost nothing. A typed list is drawn whole. A names update redraws the focused box's open list on the row it was on (showList). A closed one stays closed. The count and keys line is a sibling element in .sode__menu-pop next to the ul (the combobox foot option), so nothing measures its place. Unconfirmed text keeps its matches. Esc closes the list first, then clears or enters keyboard mode.
- Popup: presetpopup.js, opened by emit('presetPopup') so presets.js does not import it. Ctrl+G (Cmd+G on Mac) opens it from any box, except with Settings, a modal, the phone sheet or a lock up. Search (rankPresets), all presets with scope; arrows or Ctrl+J/K move, Enter closes and fires, Esc clears then closes. Hidden presets stay fireable. Phone: a Presets button ends the strip. Keyboard mode p focuses the first bookmark chip (emit('presetStrip')).

- Broken banner and status (web/brokenrules.js pure, node-tested; brokenview.js, brokenbanner.js, brokenbadge.js; GLOSSARY.md Broken and Name moved): `fire` (presets.js) and `pickSet`/`toggleSet` (filterstore.js) emit `itemUsed`. The banner (`[data-broken]`, one copy per layout) shows one entry per used item with Broken marks. Each entry has the left-out lines (`leftOutLines`) and Edit for whoever can edit it (`editPresetAt`, `editFilterSetAt`). An Administrator also gets Swap… (`swapAt`). settings.js then opens Settings > Routers and the Swap dialog with the side and number, and runs Find. A mark counts only while the item still holds that reference (`presetMarks`, `filterSetMarks`), because the server keeps old marks until its next name read. So an edit that drops the reference clears the entry at once. Dismiss keeps the entry hidden while its marks stay the same, for the page's lifetime; a new missing part shows it again. Name moved alone never shows it. Filter set entries keep the server's `broken` beside `f`, so a save never sends them. This browser's presets and sets have no server marks. `localPresetMarks` finds Name moved and `localFilterMarks` finds an exact term no name matches. A gone number cannot be seen there, since the shown names keep its old name. Status with text (`statusBadge`) is in the strip chips, the popup and the /panels list. The editor's picker and the filter set select show the text only, and the filter set chips show both. A Buttons panel cell gets an icon only (`cellStatus`, panelview.js). Grid panel cells and the editors show none yet.
- Broken and Name moved counts (web/brokencount.js; server brokencount.go): `brokenCount` counts everyone's items and needs an Administrator. `brokenCount {mine}` counts a signed-in user's Me items and owned panels. Each answers per router with `broken`, `moved` and the items. An item with both kinds of mark counts as Broken. The page shows the server's numbers in Settings > Routers (`router-1-broken`) and the user's own Profile dialog (`account-broken`, profiles.js). Each count has a list with Swap… and Edit. Counts follow the server's marks, so an edit shows in the count after the next name read.
- Replace term (web/filterreplace.js): the Filters dialog shows a row for each Broken number or exact term of the active set still in the text (`replaceRows`). `replaceTerm` swaps it in the filter like a hand edit; Save stores it. The box holds the mark's `now`, the name the Broken check saw replace the old one (docs/agents/server.md).
