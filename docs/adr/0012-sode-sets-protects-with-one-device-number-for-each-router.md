# Sode sets Protects with one device number for each router

Sode sets and frees a Protect with one device number for each router, set in that router's settings (`protectDevice`, 0 is off). Panel IDs and SW-P-08 device numbers are one number space, and the router does not check who sends a number (measured on the Ultrix, 2026-11-16). So each number that Sode uses is an ID that a panel could take, and a panel with that ID could then clear or switch through Sode's Protects. One number gives one such ID, not one for each user. The router cannot tell Sode's users apart, so Sode keeps its own record of which user or API client set each Protect, in `protects.json` beside the config. That record survives a restart, and it is what lets a user clear their own Protect and lets an Administrator see who set one.

Sode always sets and frees every level of the destination. A Protect on some levels gives a split route, since a take to the free levels goes through. A level that the router does not confirm rolls back the levels that were set. When the rollback also fails, the levels that stay stay in Sode's record, and the History entry names them. Sode refuses its own take to a destination it Protected, the same as any Protected destination. It never clears, takes and sets again, since that leaves the destination open for a short time. Sode does not offer to clear a Protect or a Router lock that it did not set, although it could send the owner's number. This is not a permanent rule. Free Sode's Protects frees every Protect in the dump with Sode's device number, with a record or not, for the time after a lost record.

Considered: a device number for each user or panel client. This gives the router who set a Protect, but each number is one more ID that a panel can take, and Sode would need a free range of numbers that no panel uses. Also considered: a clear, a take and a set again when Sode takes to its own Protected destination. It is faster for the person who takes, but it breaks what a Protect means for the time between.

Not proved on the router, so tested in `swp08sim` only: whether device numbers split at 128 or 256 in some messages (all numbers tested were below 128), whether the "Require All" or "Best Effort" routing setting applies to levels, and what the router's own salvos do with a Protected destination. The simulator leaves a Protected crosspoint of a Go and sets the rest.
