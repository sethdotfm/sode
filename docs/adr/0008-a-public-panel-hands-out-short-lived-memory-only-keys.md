# A Public panel hands any page a short-lived, memory-only key for its client

A Public panel opens for anyone with its plain URL. The page cannot read a panel's mode before it has a key, so a page with no key posts the panel id alone to `POST /api/v1/panels/{id}/public`, and a Public panel answers with a key for its own client. That key ends 15 minutes on, and the page asks again when a call answers `key_expired` or `key_revoked`. The client's long-lived keys never reach a request that sends nothing else. The key carries the client's Rights (ADR 0006), so the grant never widens.

The route is unauthenticated, so it costs as little as it can. The keys live in memory, not in `keys.json`, so a request never writes to disk. They are bounded at 64 per panel. Past that the asking address loses its own oldest key first, so one caller looping the route cannot push out every other page's key, and the key that ends takes its streams with it. They never show in the instance list or count toward its cap.

Every keyless open of any panel asks this route, so no ask counts against the failed-key throttle: that would lock out a wall of Session tablets behind one address. Instead each address may ask 128 times a minute (twice the key cap, so a wall that reopens at once still gets its keys), or the API rate limit if lower. That cap counts every ask whatever the id. A panel that is not Public, an id that names no panel, and a Public panel asked from outside its client's networks all get the same answer, `200 {"public": false}`, so no run of asks says which ids exist.

The keys have their own shape (`sode_pub.` plus 43 characters). A key Sode dropped (expired and swept, pushed out, or ended when the panel left Public) is remembered for a while and reads as ended (`key_revoked` or `key_expired`), uncounted, so a wall of tablets asks again instead of locking itself out. A key of that shape Sode has no record of reads as ended too, so a page always asks again. It is uncounted for 15 minutes after a start, since a restart forgets every key. After that no real key can predate the start, so it counts as a wrong key. A tablet that kept a key across a restart and wakes more than 15 minutes later costs its address one counted failure.

Considered: handing out one of the client's keys. That puts a key that never ends into any request that names the panel, and switching away from Public would have to find and revoke it. Also considered: a key stored in `keys.json` like a setup link. That writes to disk on every unauthenticated request and fills the instance list and the ended-key list with keys that end every 15 minutes. Also considered: answering 404 for a panel that is not Public. That logs a browser error on every keyless open of a Session panel. Also considered: counting an id that names no panel against the failed-key throttle. A panel that exists is not counted, so eleven asks told the two apart. Also considered: signing public keys so a forgotten one proves it was real. Sode keeps no persisted signing secret, and a new one would forget the old keys on a restart anyway.

Consequences: leaving Public for any mode ends every key the panel handed out and their streams, not only switching to User, which also removes the client. A Public page's instance stream ends when its key expires and reconnects with the next one, inside the 8 second grace. History names the client, as it does for a keyed link, so the client name is the only trace of who used a Public panel. A page outside the client's networks sees a panel that is not Public and falls back to a sign-in.
