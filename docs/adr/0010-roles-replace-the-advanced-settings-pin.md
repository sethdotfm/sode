# Users hold a role in place of the shared PIN for advanced settings, and v2 drops v1 config loading

At a travel show, getting panels running hit a chain: panels needed the API, the API needed a user, and a user needed the shared PIN for advanced settings, a secret nobody owned. In v2 every user holds one Role (Standard, Trusted or Administrator) and the shared PIN goes away. At least one Administrator always exists. A signed-in Administrator types their PIN again only for a closed list of critical actions, and a lower role borrows a higher one for a single action through an Approval that History records under both names. Users may have no PIN when the install only needs to keep preferences apart. A user without a PIN acts as a Standard user, or as the Guest role when that is higher, with Rights no wider than Guest Rights, checked when they act. The full decision list is in the resolution of [Who the actors are in the new auth model](https://github.com/sethdotfm/sode/issues/378).

v2 does not load v1 config files as live config. The owner chose a better structure over keeping persisted and wire names readable, which reverses the "kept old names" rule in AGENTS.md for v2.

Considered: keeping the shared PIN as a separate break-glass secret beside an Administrator role (two ways to be an administrator, and the PIN still belongs to nobody); re-asking for the PIN on every advanced change (the friction the travel show hit); and a permanent lock after repeated wrong PINs (a defence against hostile actors, which the map rules out of scope, and it can leave a show stuck until someone reaches a shell).

Consequences: the last Administrator's forgotten PIN is fixed only from a shell. User names show before sign-in, so a guess at an Administrator PIN is limited only by the waits after wrong PINs, which the threat model accepts. Waits are counted per user name, and a name that belongs to an Administrator always waits, even where an Access preset turns waits off. ADR 0006's "a Trusted user may create a panel's API client" widens to any panel owner, still capped by their own Rights.
