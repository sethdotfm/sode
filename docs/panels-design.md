# Sode Panels: design

Validated by prototype on branch `prototype/panels` (three variants, kept as the primary source). Terms are in GLOSSARY.md under Panels. ADR 0006 covers who may create a panel's API client.

## What a panel is

A saved 4x8 grid of cells on its own URL (`/panels/<id>`, or `/panels/<slug>` once it has a short name), driving the router through `/api/v1` only. 4x8 is the default size, chosen so a panel maps one to one onto a hardware key deck later. Rows and columns become user settings, and merged cells stay inside the grid. The panels page `/panels` signs in like the rest of Sode and launches a user's panels. The editor, at `/panels/editor`, edits them live.

Pages (ADR 0007): a panel holds `pages`, 1 to 16 Pages in order, each with an id that never changes, an optional name of at most 40 characters (shown as "Page N" when empty), an enabled switch and its own `cells`. Every Page has the panel's size and shares its one plan. The store checks the list on every save (count, unique ids, name length) and fits each Page's cells to the grid, so a resize drops cells that no longer fit on every Page; the editor's status note counts them. A panel saved before Pages loads as one Page. The stored shape is built (`internal/app/panelpagelist.go`, `web/panelpages.js`); the editor edits every Page (the Pages bar, below), and Push, Copy, templates, Checkpoint sets and restores carry every Page with its id. Fixed destination keeps Destination cells out of the grid of every Page the page draws.

Page rules on the panel page (`web/panelnav.js`, `panelmodel.js`): the current Page is part of the state (`st.page`, an id) and the plan is panel-wide, so a Page change never clears the view or the staged routes, and Clear and Take act on the whole plan from any Page. Three cell kinds move between Pages. Go to Page (`goToPage`) stores its target as `page`, a Page id, so a reorder or a rename keeps it; it shows the Page's name ("Page N" when empty) unless its caption replaces it. It works when the target has no cells, and is greyed and unpressable when the target is disabled or deleted. Next Page and Previous Page (`nextPage`, `previousPage`) skip disabled Pages and wrap past the ends while the panel setting `wrapPages` is on (the default); with it off they are greyed at the ends, and with one enabled Page they are always greyed. A press sends nothing, so it works while the panel is Offline. The browser keeps the current Page in `localStorage` as `sode-panel-page-<panel id>` and reopens it after a reload; a live update keeps it; when it was disabled or deleted the page moves to the first enabled Page (Page 1 when every Page is disabled). Test it live neither reads nor writes the saved Page. The server refuses only a malformed target (not a string, or not shaped like a Page id); a missing one is stored as is. In the editor a Go to Page cell gets its Page from a list in the Cell tab (`editorpagetarget.js`), by number and name; one with no Page is unassigned, one whose Page was deleted is dashed, and the Cell tab warns when the target has no cells or is disabled. Find lists the three kinds as single entries, as it does Clear, and a template keeps a Go to Page target with either option or none, since it is layout. A paste into another panel drops the target and says how many cells came in unassigned. `TestChromePanelPages` covers the panel page.

Storage: one YAML file per panel under `panels/`, with an `id` and a display name inside the file. A user makes their own panels with their existing Rights. A Trusted user may also make a panel that acts as its own API client, with Rights no wider than theirs. Panels can be shared use-only with named users or Everyone, and a user can save a copy to edit.

## Behavior

- Pressing a Destination cell views it. The grid then shows what that destination has now: its current source is solid green and every other source is idle.
- Pressing a Source cell stages it for the viewed destination, and the staged source pulses green. Staged destinations pulse orange and show the staged source under their name.
- Take applies every staged change. Clear drops them all and the view. Pressing a staged destination again unstages just that one.
- Multi-destination is a panel setting, on by default. Off, one change is staged at a time.
- A Preset cell stages the preset's routes, so it can be previewed on the viewed destination, and works in the panel's mode. Take mode arms the Take cell. Instant mode makes pressing a Source or Preset the Confirm.
- A Take cell arms once something valid is staged. Optional guards are a hold or a double press.
- Current Destination shows only the source now on the viewed destination, under the caption "Currently".
- Panel Name shows the panel's name and Instance Name the instance's name (its device name), each with its caption as a line above. Neither can be pressed. A page that has no instance name yet, and Test it live, show the kind's words instead.
- Idle cells are the active colours muted into the control surface, so user-chosen colours carry through. The pulse breathes between about 72% and 100% of the state colour on one shared 2-second cycle, with static rings so state survives reduced motion.
- After a take, a destination shows its Result as an icon (connected, already, failed). Result text is optional and off by default.
- Refused before arming, with an error: a Protected destination, a route outside the panel's Rights, and a Source and Destination with no common level. Levels are set per panel and per Source or Destination cell, and a take sends the intersection.
- Fixed destination (`settings.fixedDests`) gives a panel a list of destinations and no viewing step. A Source press stages a route from that source to every fixed destination, leaving out one that already has it; when all of them have it, the press drops the staged routes instead. A Preset press stages only the preset's routes to fixed destinations and is refused, naming the preset, when it has none. A refusal on any one fixed destination (Protected, outside the Rights, no common level) refuses the whole press. Each press replaces the plan, so Stage several Destinations has no effect. Take mode, Instant mode and the guards work as without it, and Clear drops the staged routes but keeps the list. Destination cells stay stored but are not drawn. The page has no list of them (a strip showing each one was removed on request); the Current Destination cell and the Source cells' current state read the first one. A panel without the setting behaves as before.
- The viewed destination and the staged routes have no clock: only a press, a take or Clear ends them. (An earlier build cleared them after 30 idle seconds; a wall tablet that forgot its destination mid-thought was worse than one that kept it.) A saved edit refreshes open panels after a 10 second countdown shown in a banner with Snooze 60 s and Apply now; the banner's own section below says what each does with staged routes. A viewed destination is kept through the refresh.

## Authentication

Session mode acts as the signed-in user, with that user's Rights, and the page uses a user key tied to the session. API mode uses the panel's own API client key. A kiosk needs no sign-in: by default the panel URL itself is the credential for that client's Rights. Once a link's key works, the page stores it in that browser and drops it from the address, so it persists there until the instance is rotated or revoked. A secure mode exchanges a one-time setup link for a key stored in the browser, and remains the one-time option: its link works once.

Both (`acts: both`) is API mode with Session mode as the fallback. The panel owns an API client and its keys exactly as in API mode (a Trusted user makes it, within their Rights, ADR 0006). The page decides per open, in `panelrun.js`'s existing order: a key in the URL fragment, then a setup link, then a key this browser stored for the panel, and with none of those it starts a session key and runs as the signed-in user, behind the page lock's PIN pad when the lock requires one. A session key always needs a user, so a plain link to a Both panel asks for a sign-in; a panel shared with Everyone then opens for any user who signs in. The plain link stays valid (Copy link and the Identity link row show it, with a note), and the keyed links live under Share, Link with key. Only API mode refuses a page with no key.

Switching Authentication mode in the Access tab shows what the switch does to keys before it applies (`actsSwitch` in `web/panelsrules.js`). The field's choices are User (Session mode), Both and API. User to API or Both makes the panel's own API client with no keys yet. API or Both to User ends the client, every instance key and every setup link, so each instance opened with a key signs out. Either of those waits for the Confirm, the churning letter and lockout that Rotate and Revoke use (`web/confirmbox.js`), and Cancel puts the old mode back. API to Both or back keeps the client and every key, so it applies at once with no Confirm, and the note under the field says what it kept. Every caller that changes the mode goes through `guardActs` (`web/actsguard.js`). An Assign never changes it: it reads the target and writes neither panel, so it runs no Confirm.

## Editor

The editor is the page where a panel's grid and settings are made. It lives under the panels root as its own page (`/panels/editor`), apart from the pages for viewing, sharing and signing in to panels. The prototype is variant F on branch `prototype/panels` (`prototype/panels/editor/f`, served on :8116 by `serve-editor.mjs`).

- Layout: a toolbar with the panel picker in the middle (My panels, then Shared with me as use only, then New panel), Templates, Push, Test it live and Save. The grid is in the middle and the sidebar has Cell, Panel and Access tabs. The sidebar opens on Panel and switches to Cell when a square is selected. Cell holds the button type, a fuzzy picker for the contents, a caption that replaces the Router name, levels (the Sode main page's colored level buttons, built from the levels in the page's hello, with an All button), font size and artwork, with Hide text once a cell draws artwork, its own or its item's Default artwork, and a Default artwork row. Panel holds identity and size (rows and columns, typed or stepped), appearance (title bar, font size, theme; a font size field always shows its value, 100 when unset, so the arrows step from there), behavior (mode, Take button behavior, Fixed destination, levels, kiosk) and device and feedback (screen awake, fullscreen, landscape). Access holds who the panel acts as, limits and the sharing status; the Share button is in the toolbar.
- Fixed destination: the Panel tab's Behavior section lists the chosen destinations by name and number, each with a remove button, above a box that searches Destinations with Find's scoring and the signed-in user's Rights and Visibility (`fixedPick` in `web/findrules.js`, the field in `web/editorfixed.js`). Hidden removes what is outside the Rights and Read-only greys it, and a grey one cannot be added. The list keeps the order it was added in, since the first one is what the Current Destination cell reads, and stops at 16. Removing the last one turns the setting off. While the list is not empty, Destination cells are set aside: the editor holds them out of the grid, so no edit can touch a square nobody sees, and puts them back when the list empties (`setAside` and `putBack` in `web/gridmodel.js`). One whose squares get filled, or that no longer fits after a resize, is dropped at that edit, as on load, and the status note counts it (`heldThatFit`); an applied template replaces them with its own. Saves and the unsaved-change check use the grid with them put back, so a save keeps them stored. Type shows Destination greyed with "Fixed destination is on" beside it, Find greys every Destination with the same reason, and Stage several Destinations is disabled with a note while its stored value stays. Test it live and Save treat the field like any other panel setting.
- Selecting: click a square, or drag across several. Selecting never changes the grid by itself.
- Smart menu: a small list sits beside the selection, to its right, else its left, else below it. Merge and Unmerge act on click. Type and Find widen on hover or focus. Type reads `Type: <kind>` for the selection (Mixed for several kinds) and shows the cell kinds for the whole group, plus Empty to remove them. Find searches every kind at once (Sources, Destinations, Presets, Take, Clear, Current Destination, Panel Name and Instance Name), with an icon for each category and filter chips to narrow to Sources, Destinations or Presets. Each opening starts on the chip for the kind the selection was given and not yet filled (`findScope` in `web/findrules.js`), so an empty Preset square lists Presets; a chosen cell, mixed kinds or Take, Clear and Current open on All. When that chip leaves nothing, a "Search all instead" row (or Enter) drops it and keeps the typed text. A Take, Clear or Current result places a cell of that kind. The results respect the signed-in user's Rights and Visibility: Hidden removes what is outside the Rights, Read-only grays it and marks it.
- Filling: choosing a result fills the group from that item onward in number order, using the fill order picked in Find (across, right to left, snake across, down, bottom to top, snake down, each shown as a small path icon). A preview shows in the grid before anything changes. Shift-click or Shift+arrows pick a set of results instead, and Enter or the Fill button then places those in order. With one square selected, a click fills it, moves the selection to the next square and moves the highlight to the next result. The menu stays put, so clicking the same spot again fills the next square.
- Artwork tool: the smart menu's Artwork item sits below Find and widens on hover or focus like Find, with two picker columns: Icon A lists the vendored icons and an Upload button, and Icon B the glyphs. Unlike the Cell tab's picker it has no Uploaded section, so no Icon library icon. Choosing an Icon A (a vendored icon, or an image uploaded once from the flyout) puts it on every selected cell and leaves their Icon B alone. Choosing an Icon B gives the first cell in the fill order that glyph and each later cell the next one, leaving Icon A alone; a run stops at 16 or at Z and never wraps, and cells past the end keep what they had. Clear artwork drops each cell's own `art`, `artB` and `hideText`, as Use default does, so any Default artwork shows through. The fill order is Find's, one shared setting picked in either flyout. Squares with no cell are skipped and do not take a glyph; a cell with no item chosen yet still takes artwork. A preview shows each square as it will draw, Default artwork and the Icon B badge included, and the status line counts the cells changed, the cells left without Icon B and the empty squares skipped. Esc backs out with nothing changed. Only a cell's own artwork changes, never a Default artwork, and one choice is one change of the grid (`artToolPlan` in `web/arttoolrules.js`). The arrow toward the flyout enters it at the icon search box, Down enters the icons and the arrows walk each picker column.
- Menu chord: Merge or Unmerge (one item that changes its label) is Ctrl+M on every platform, shown beside it as Ctrl+M or, on a Mac, the Control sign (`menuChord` and `chordText` in `web/editorrules.js`), on the grid or with the menu focused. macOS minimises the window on Cmd+M before the page sees it, so Cmd+M does nothing here. A disabled item ignores it. Type and Find have no shortcut: bare letters on the grid start Find, and Enter or Tab reaches the menu. The menu closes (the selection clears) on a click or Tab outside the grid, the menu and the sidebar. A click or Tab into the sidebar keeps the selection, since the Cell tab edits it, but puts the menu away so it never covers the fields; the next grid click or key brings it back (`menuAway` in `paneleditor.js`).
- Pages bar (`web/editorpagebar.js`, rules `web/editorpagerules.js`): left of the grid, a row per Page with its number, its name ("Page N" when empty) and an On checkbox (a checkbox, not a switch, since the change waits for Save), then Rename (at most 40 characters; Enter keeps, Escape throws away), Copy to, Move up, Move down and Delete page as icon buttons. Rows drag to reorder. Add page adds an empty enabled Page and opens it, and stops at 16. Delete page asks through the churning-letter Confirm and counts the Go to Page cells that lead to the Page, which turn dashed; the last Page cannot be deleted. A plain click on a row opens that one Page; Cmd or Ctrl-click (a Mac Ctrl-click arrives as `contextmenu`) adds or removes one, up to four open, shown side by side in Page order, two to a row, one to a row under 64rem (`web/editorpageview.js`). Clicking a square of an open Page focuses it: the Cell tab, arrows, Select all, copy, cut, paste, Delete, Find and the grip act on the focused Page. Copy to copies that row's Page onto a Page picked by number in a plain dialog: an empty Page takes it at once, a Page with cells asks first ("Replace"). The target keeps its id, name and enabled; copied Go to Page cells keep their targets. It is one undo step. Dragging a selection between Pages is not supported; cut, focus the other Page and paste.
- Grid commands: Cmd or Ctrl+A selects every square of the grid. Both modifiers work on every platform, by the physical key so any keyboard layout. A focused text field keeps its own Cmd or Ctrl with X, C, V, A and Z. Copy, cut, paste and undo join the same table (`GRID_CHORDS` and `gridCommand` in `web/gridchords.js`, run through `gridCommands` in `paneleditor.js`). Cmd or Ctrl+C copies the selection to the system clipboard as a JSON block marked as Sode cells with a version (`web/gridclip.js`). It holds the selected rectangle's size and its cells as stored: contents, levels, caption, artwork, merge size and cell settings. A selection that cuts a merged cell grows to hold it, as for every selection, and a selection with no cells copies nothing. Cmd or Ctrl+X cuts: it copies exactly as Cmd or Ctrl+C does, then removes the selected cells as one grid change, so a cut can be taken back in one step. If the browser refuses the clipboard, nothing is removed. Destination cells set aside by Fixed destination are not in the grid, so a cut neither copies nor removes them; they stay held. Cmd or Ctrl+V pastes a block with its top left on the selection's top left; text that is not a Sode block changes nothing and the status line says so. A paste that fits just happens, with no dialog: a cell already in the grid that shares a square with a pasted cell goes whole, a blank square in the block leaves the grid's square as it was, and the pasted area is selected. A paste that would run past the grid's edge opens a plain dialog (not the churning-letter Confirm, since undo reverses it) with Clip, Wrap and Cancel, which names the fill order and how many cells each choice drops, moves or shrinks. Clip drops cells wholly outside and shrinks a merged cell that falls partly outside to the squares inside. Wrap places the block's cells in reading order on successive squares of the whole grid in the fill order picked in Find, from the paste square to that order's last square; blank squares in the block are skipped, a merged cell goes whole at its square when it stays inside and covers no square already placed, and otherwise shrinks to one square. Cells left when the squares run out are dropped and counted. Find's Fill order and Wrap share one definition (`squareOrder` and `FILL_ORDERS` in `web/gridmodel.js`; the rules are `web/gridedge.js`). Clip or Wrap is one undo step. Escape and Cancel change nothing. Arrow keys move between the buttons, and focus goes back to the grid. A paste into another panel, or into a panel not yet saved, drops uploaded images (they belong to the panel they were added to) and keeps vendored icons, Icon library icons and Icon B, and the status line counts the cells that lost one. While Fixed destination is on, a paste skips the block's Destination cells and the status line counts them. Cmd or Ctrl+Z undoes and Cmd or Ctrl+Shift+Z redoes (Ctrl+Y is not redo). One stack holds the panel's cell edits on every Page, so an undo pressed on Page 1 takes back an edit on Page 3, up to 100 steps, the oldest dropped first: paste, cut, Delete, Find fill, Type, merge and unmerge, drag-extend, the Artwork tool, a template apply (it replaces the whole Page list, since a template carries every Page, so its undo brings the old list back; not its panel settings), a resize with the cells it dropped on every Page, Copy to, and Cell tab edits (typing in one field of one cell is one step). Copy, selection moves, panel fields and Page Add, Delete, Rename, Reorder and Enable are not steps: an undo puts cells back by Page id and leaves Page names, order and deletions as they are. A new edit after an undo clears redo. Save keeps the stack; opening another panel or leaving the editor drops it. The status line names the step: "Undid paste.", "Redid paste.", "Nothing to undo." Destination cells set aside by Fixed destination come back with an undo and stay set aside.
- Find's flyout is patchbay's `pb-menu__sub`, positioned by CSS beside the Find item. Opened from a selection low or far right it would hang off the page, so `editorfind.js` measures it on open, hover, focus and each redraw and shifts it back inside the viewport with a `translate` (`flyoutShift` in `editorrules.js`; the top and left edges win when it is taller than the viewport).
- When the editor cannot reach its panel it says why and what to do, never a blank page (`signInNote` and `openFailNote` in `web/editorrules.js`): signing in (with Sign in), a key Sode refused or ended (with Sign in again), no users, Sode not answering, a panel that is not there or not shared with the user (choose another, or ask the owner to share it), a dead network. The sidebar and Find are built before the page waits for a sign-in.
- Keys: arrows move the selection and Shift extends it. Typing starts a search. Enter opens Find. Tab moves into the menu, arrows walk it, the arrow toward the flyout enters it and Esc backs out. Delete removes. Ctrl+J and Ctrl+K (Cmd on Mac) step a result list, as in the rest of Sode.
- Corner grip: dragging the grip at a selection's corner extends its numbering in that direction, with a tip showing the first and last name and the count.
- Toolbar: grouped with a rule between groups (the panel picker and the name, then Templates, then Share, Copy link, Open panel and Test it live, then the saved state beside Save). The name is text beside a Rename button that opens the name field: Enter keeps the new name and Esc puts the old one back. The slug stays in the Panel tab. The saved state sits in a slot as wide as its longest text (a hidden copy of "Unsaved changes" in `panels.css`), so a save or an edit never moves or re-wraps the toolbar. Ctrl or Cmd+S saves from anywhere on the page, a field included, and the browser's own Save page never opens (`saveChord`). The panel picker is at least 14rem wide. Copy link copies `linkFor(panel)` (`web/panellink.js`, the one place that builds a panel's link; the Share modal's People and Link with key tabs and the sidebar's Identity section show the same link through `web/panellinkrow.js`). A panel with its own API client has no link without its key, so Copy link is hidden for it and the others say to use Link with key.
- Unassigned cells: a cell with a kind but no Source, Destination or Preset is shown dashed. A live Test leaves them out: Test it live saves any edits, then runs the saved panel in the editor in place of the grid and sidebar (Back to editing returns), and the panel page already drops cells without a Source, Destination or Preset.
- Templates: a template is a saved layout with button types, optionally the panel settings and the cell contents, chosen apart as Store with Sources (Source and Preset cells) and Store with Destinations. By default cells come back unassigned, so a show's Sources and Destinations are filled in afterwards. Templates are saved to Me or Everyone, and saving to Everyone needs a Trusted user or the Advanced Settings PIN. Built in P16: files in `templates/me/` and `templates/everyone/` beside the config, routes `/api/v1/panel-templates` (not under `/panels/`, where `DELETE /panels/templates/{id}` would collide with `/panels/{id}/key`), and the server drops cell contents unless the save says `sources` or `dests` for that kind of cell (`contents: true` from before the split means both, and a Take caption stays once either is on), so an Everyone template never carries a Source or Destination by accident. A REST call has no Settings session to hold the PIN, so the PIN rides in the save body as `pin` and counts in the same wrong-PIN pool as Settings. The editor's Templates button (`web/editortemplates.js`) lists Me and Everyone, applies a template to the open grid as an unsaved change, and asks for the PIN only after the server refuses Everyone. An applied template's contents come back with its cells. Its settings are merged into the sidebar's unsaved fields (`setFields`) and saved with the panel.
- Push: copies a panel's saved config to other panels. Each target keeps its own name, id and sharing, and updates the way a saved edit does. A checkpoint of each target is kept first. Targets are picked by group or one by one. A checkpoint set stores one saved layout per panel in a group, so one push gives EVS 1 its own and EVS 2 its own. A panel's owner can push to their own panels. A Trusted user can push to anybody's.
- Artwork: a cell can show a vendored icon, or an uploaded JPEG, PNG, GIF or SVG up to 2 MB and 1024 by 1024 pixels. A panel holds 64 MB of artwork in all and any number of files; an image used on many cells is stored once, since cells name it by id. Push and Copy bring across what fits under the target's total, checked under the store lock so an upload at the same moment cannot pass it, and report the ids that did not (`artSkipped`). The Push modal's status line and the Copy status line in the editor and on the panels page count them per panel (`artLeftOut` in `panelrules.js`). Images are shown dimmed behind the caption so the state color still reads. The editor prepares an upload before sending it (`prepareArt` in `artcompress.js`). It checks the type first. It resizes a PNG or JPEG so neither side passes 1024, keeping the aspect ratio and the type and never enlarging it. It sends a GIF as it is, so the animation stays, and refuses one over 1024 by 1024 or 2 MB with "Resize it and upload again". SVG goes as it is. The 2 MB cap applies to the file that is sent, so a large photo that shrinks under it is accepted. The server checks the size and pixel limits again by content, so the API path is bounded too. A 1024 by 1024 image decodes to about 4 MB in the browser. A cell with artwork can hide its text (`hideText`); the words stay in the page for screen readers, and the editor square hides them the same way, so the square shows what the panel will. SVG is only ever used as an image, so scripts in it never run.
- Two icon slots. Choose icon opens a picker with two columns side by side, each with its own None and its own scroll. Icon A is the cell's `art`: the vendored icons, starting with the cell kind icons (Source, Destination, Preset, Take, Clear, Current Destination, Panel Name, Instance Name), then the Result and action icons the editor and panel use, then pictures. Icon B is `artB`: a digit 0 to 16 or a letter A to Z, so "[camera] 2" is two picks. Remove clears both. An uploaded image fills the whole cell, merged cells included, always with contain (no cover and no per-cell choice), and Icon B draws over it as a small badge in the top end corner (`artBBadge` in `panellook.js`, so the panel page, editor square and sidebar preview all follow). Beside a vendored icon, Icon B keeps its place in the row. Icon B is text (Lucide has no digit icons), never a faked sprite icon. The artwork row (`artNode` in `panelview.js`, shared by the panel page, the editor square and the sidebar preview) lays out a vendored Icon A then Icon B side by side, 40 and 60 percent, centred, dimmed behind the caption; the glyph is sized from the row's height (`cqh`) so it scales with the square like the icon. A cell with only Icon B counts as having artwork, so Hide text applies to it. Old panels have no `artB` and load unchanged; anything stored there that is not one of the choices draws nothing.
- Icon library: one install-wide set of SVG and PNG icons, `icons.yaml` beside the config with the files in the `icons/` directory (`internal/app/iconlib.go`), never in the config or a panel. Icon A's column in Choose icon opens with an Uploaded section above the vendored icons: the library's icons by name, a name box and Upload. The icon search filters both. Any user who edits panels picks from it, and the cell stores `lib:<id>` in `art`. Adding needs a Trusted user or the Advanced Settings PIN, asked for in the section after the first refusal. An upload takes the editor's artwork path (`prepareArt` in `artcompress.js`, so a PNG over 1024 is shrunk first) and the server checks it as artwork: 2 MB, 1024 by 1024 for a PNG, PNG or SVG only, and 64 MB for the whole library. The name is the typed one or the file's name without its extension, 1 to 40 characters; a name another icon has, ignoring case, is stored as "Name 2", "Name 3" and so on. An upload picks the new icon for the cell. A library icon fills the row like an uploaded image, with Icon B as the corner badge. A PNG draws as a picture in its own colours. An SVG draws like a vendored icon, in the cell's text colour, so it changes with the theme and the state colours, and a multi-colour SVG draws in one colour: the page fetches it with the session or the panel's key, as any artwork, and uses the blob URL as a CSS mask, revoked when the panel goes. A mask, like an image, never runs the file's script. The Uploaded section's tiles draw the same way. A cell naming an icon the library does not hold saves and draws no Icon A; old panels load unchanged. Push, Copy, a template and a Default artwork keep `lib:<id>` as the reference, since they stay on the same install; none copies the file or counts it toward an artwork cap. A panel moved to another install (its `GET /panels/{id}` body made a panel there) brings only the reference, and the cell draws no Icon A until the library is copied over (docs/reference.md). A Trusted user sees Manage in the section: a tile click then chooses that icon instead of picking it, and a name box with Rename and Delete appears. Others never see Manage. Rename keeps the id, so every cell naming it keeps it, and a clash becomes "Name 2" as on upload. Delete asks a Confirm (the churning letter and the lockout) that says how many cells on how many panels use the icon, counted across every panel when the Confirm opens. Those cells keep `lib:<id>` and draw no Icon A, as for any icon the library does not hold; their Icon B and text stay. No panel file is rewritten, so a delete never changes another user's panel or its `rev`, and an open panel page drops the icon on its next load. SVG and PNG files put in `icons/drop-in/` are added at start and by Rescan, which a Trusted user sees beside Manage; the file name is the icon name, the upload's limits and "Name 2" apply, an added file leaves the directory, and a skipped one stays and is listed with its reason (docs/reference.md).
- Default artwork: a Source, Destination or Preset can carry Icon A, Icon B and a Hide text choice that every cell showing it uses when the cell sets no artwork of its own. One shared set for everyone, in `artdefaults.yaml` beside the config with its images in `artdefaults.art/` (`internal/app/artdefaults.go`), never in the config or a panel. A Source or Destination default is keyed by router number and keeps the router name from when it was set; a Preset default is keyed by scope and name, and only an Everyone preset has one: the set is shared, so the server refuses scope `me` (400) and the Cell tab shows no Default artwork row on a Me preset cell (`takesDefault` in `editorrules.js`). A cell's own artwork wins whole (neither icon of the default fills in beside it). Hide text comes from the default unless the cell stores `hideText` true or false, so `false` now means "show the text" against a default; font size stays per cell. A cell that loses its item shows no default. Resolving happens only when drawing (`withDefault` in `panellook.js`, before `artNode`), so a save, Push, Copy or template carries a cell's own artwork and never the default. `GET /panels/{id}` carries the defaults of the items its cells show as `artDefaults`, and an open page compares them along with `rev` (`revOf` in `panelupdate.js`), so a changed or cleared default arrives through the same update banner as a saved edit. In the editor's Cell tab, the Default artwork row's Set as default sends the cell's own artwork and Hide text (an uploaded image is copied and gets a `d-` id), Clear default removes it, and Use default drops what the cell sets so it shows the default again. When the router now gives the number another name, the row warns that the default may be for another item, and the cell still uses it. Setting or clearing needs a Trusted user or the Advanced Settings PIN, asked for in the row after the first refusal. A Hidden key sees only defaults for items inside its Rights.

## Panels page

`/panels` lists panels and launches them. The editor (`/panels/editor`) and a panel itself (`/panels/[id]`) are separate pages. The prototype is `prototype/panels/overview/c` (:8123 with `serve-overview.mjs`). Variants A (table) and B (tile gallery) are history.

The Find box on `/panels` is a fuzzy find over name, short name and owner (the editor Find's scoring, `panelScore` in `panelsrules.js`), best match first inside each group. Ctrl or Cmd with J and K, or the arrow keys, move the highlighted panel; Enter in the Find box moves focus to Launch. Anywhere on the page, Ctrl or Cmd with Enter launches and with E edits the highlighted panel, and J and K step (`listKey`; Cmd counts on a Mac only), and the buttons show the keys. An open modal turns them off.

- Layout: a list on the left, grouped under My panels and Shared with me, each row with a mini picture of the grid, its owner, whether it acts as a user or an API client, and an online dot. The right side shows the chosen panel: a large Launch button, Edit, Share, Link with key, Push to panels and Delete, then the instances open now and a Watch checkbox.
- A panel shared with you opens for use. It shows Save a copy instead of Edit.
- A Trusted user sees every user's panels, grouped by owner, and can edit, share, push to and watch any of them.
- Delete needs a second press.
- Assign to (as built): on any panel, a Trusted user (or anyone with the Advanced Settings PIN, which the modal asks for after a `trusted_required` refusal) opens a list of the Sode panel pages seen in the last 24 hours, each with its name, the panel it shows now, its address, its uptime since its current stream connected and its sign-in state in words (Signed in as the panel's client, Signed in as a named user, Key ended, Not signed in), and clicks one (`panelassign.js`, rules in `panelassignrules.js`). Rows sort by current panel, then name. Only pages that have held the instance stream are listed, which keeps other API clients out. An instance already on the panel is greyed, and a page whose stream has ended is greyed with "last seen" and cannot be assigned (the server refuses it too). `POST /api/v1/panels/{id}/assign` makes a key for the target's client named for the instance, so it has the target's rights, and sends it as the last line of that instance's newest stream only; when no stream wrote it, the key is revoked and the Assign fails. The page stores the key under the address it will open (the short name, else the id), rewrites the address with its `?instance=` and kiosk kept and the old key dropped, and loads the target with a full load, so the staged routes go and no prompt or banner shows. A reload opens the same address with the stored key. The old panel's key stays valid, and the old panel forgets the instance instead of raising a lost notice. The target panel is never written, so its Fixed destination list and Authentication mode stay. One `assign` row names the user, the instance and both panels. A Find box at the top ranks the rows with the panels list's scoring (`wordScore`) over the instance name, current panel, address and sign-in state; arrows or Ctrl/Cmd+J and K move the highlight and Enter assigns the highlighted row, doing nothing on a greyed or timed-out one (`rankAssign`, `stepRow`, `enterRow`). A target that already holds that name, as a key or as any instance Sode holds, offline ones included, is never rotated: it answers 409 `name_taken` with a suggested name, the name plus 2 or the next free number, and a small dialog offers it, editable, and sends again with `name`. The instance then uses the chosen name as its device name on the target: the page rewrites `?instance=` when the address has one, else stores it as `sode-panel-device`. Assigning an instance back to a panel that still holds its old key is such a clash. A target at its 20 instances is refused with the reason, before any clash. A target that acts as a user gets no key: the page drops its key for the target's address, opens the target and shows that panel's sign-in, so the person at the device types their own PIN and nobody types it for them. A panel that acts as both offers Its own key (the default) or Sign in above the list. A device signed in as a user stays signed in; when that user cannot open the target, its row says Not shared with them and a click first asks Send anyway or Cancel, and the page then shows "No panel here that you can use." A page with no working key is a Keyless instance (ADR 0008): it holds `GET /api/v1/panels/{id}/instances/keyless` with no key, under the name it already holds and never asking for one, and is listed with Not signed in, or Key ended once its key answered `key_revoked` or `key_expired`, and its address. It is named by its own name, else the last name a stream from its address carried, else the address. A keyless page is never greyed as already on the target, since assigning it to the panel it shows is how it gets a key. It gets a key only from inside the target's allowed networks. A page whose key ended stops polling, shows its note and still announces itself; a page that gets a working key stops announcing. Sode keeps at most 1000 keyless entries for 24 hours in memory, oldest dropped.
- Rename (as built): on the panels page's Open now list, a pencil beside an instance's name turns it into a field; Enter saves and Escape or leaving drops the edit (`nameSlot` in `panelsmon.js`, rules `renameState` and `renameProblem` in `panelassignrules.js`). It is offered to whoever is sent the instances (the owner or a Trusted user); the route also accepts the Advanced Settings PIN, and a `trusted_required` refusal shows a PIN field beside the name, as the Assign to modal does. Only a Sode panel page holding its stream can hear the name: a page that timed out shows the pencil disabled with "offline", and its key is not renamed alone. `POST /api/v1/panels/{id}/instances/rename` renames the device name itself: the name is up to 40 characters and unique on the panel ignoring case, against its keys and every instance Sode holds, offline ones included. A held name opens the same dialog as an Assign's clash, the name plus 2 or the next free number, editable. Sode renames the instance's key, moves per-instance watches to the new name and sends a `rename` line down the stream. The page applies it as its header rename does and reopens its keepalive and stream under it; a page named by its link rewrites `?instance=` instead of storing the name, so a reload keeps it. The old name leaves the list with no lost notice. One `rename` row names the user, the old name and the new one. A keyless instance is not in the Open now list, so it has no pencil.
- Share is a modal with two tabs. People sets Only me, Named users or Everyone. Link with key is for a panel that acts as an API client: the key sits in the URL fragment (`#key=`) so it never reaches a request line or proxy log, the link is masked until revealed, and the tab offers Copy link, a QR code, Copy kiosk link, Rotate and Revoke (each confirmed). A panel that acts as a user has no key and asks for a PIN at launch. The modal opens on the tab that fits: Link with key for an API client panel, People for a Session panel.
- A panel holds one key per named instance. Rotating a key signs out that instance and kills its old link, and Revoke ends that instance. The other instances are not touched, and the panel keeps its client.
- Link with key as built (`panelkeytab.js`, rules in `panelkeyrules.js`): the tab lists the instances (name, made, last used, online or offline in words, and a pending setup link with when it expires) with Rotate and Revoke on each row, then a New link form. Every link is made for a named instance: the name is required, unique ignoring case, at most 40 characters, and is also the instance's device name, as with `?instance=`. Making a link for a held name rotates that instance. A panel holds at most 20 instances, the cap set so a wall of kiosks fits and a fleet does not (`panelKeyMax`). The two kinds of link are a Named instance link (a key, shown once) and a One-time setup link (works once for one hour, and the device keeps its own key). The secret exists only in the answer to the make call, so a link is never shown again; a lost link is replaced by rotating the instance. Rotate, Revoke and any make that replaces a key each ask for a Confirm (the churning letter, then the button or the key). The link is masked until Show link, and the QR (`qr.js`, built in the browser so the key never reaches a server; up to 106 bytes, longer links say so) appears only then. Copy kiosk link copies the same link with `kiosk=1` after the key (`?instance=` stays) and says Copied, as Copy link does; its icon is `monitor`. The tab also edits the allowed networks, which apply to every instance. A modal opened for a panel reads `hasKey` and `clientNetworks` from the panel, and the list from `GET /panels/{id}/keys`, refreshed every 5 seconds so Online stays current.
- A Session panel's Link with key tab is greyed but readable. It says a link to the panel asks for a sign-in in any tab or device not signed in to Sode, shows the plain panel link and offers no key action; the way out is Acts as its own API client on the Access tab. Changing Acts as saves the panel at once, since it makes or removes the client. A refusal shows under the field and puts the choice back.
- Short links. A panel may have a short name (slug), set in the editor's Panel tab: `/panels/<slug>` opens it and the id URL keeps working. The page route serves the panel page for any segment shaped like an id or a slug and says nothing about which exist. The panel read route (`GET /panels/<slug>`) and the setup route resolve the slug, and an unknown or unusable one gives the same 404. Changing or clearing a slug stops links that used it, which the tab's hint says. One link builder, `linkFor` in `web/panellink.js`, serves the Share modal's Link with key tab. A link with a key is `panels/<slug or id>#key=<key without sode_>`, with `?instance=<instance name>` before the fragment when the link names the instance. The page reads `instance` as the device name and skips its question. The name is no secret, so a query parameter is fine, and the page does not store it. Measured with `http://sode.lan:8080/`: the old link by id was 91 characters, the new link with a short name is 60, and 65 by id. A key is 128 bits now (22 characters), which is enough because keys are throttled, revocable and belong to one panel.
- Secure mode: each instance has one credential. A setup link ends that instance's key and any older link for the name, lasts one hour and works once. The page opens `panels/<id>#setup=<token>`, posts it to `/api/v1/panels/{id}/setup`, keeps the key in `localStorage` and rewrites the address without the token. A stored key is used when the address has no key; a 401 clears it. A key in the fragment wins over a stored one. A plain `#key=` link is kept the same way once its first call succeeds (a key the server refuses is never stored), replacing a stored key that differs, and the address keeps `?instance=` and the other fragment parts, such as `kiosk=1`. With `localStorage` blocked or full the key stays in the address, since a reload would have nothing else to read. Unlike a setup link, the key link itself stays valid until rotated or revoked.
- Allowed networks: an optional CIDR list on the panel's API client, one per line in the tab; a bare address is one host. A key used from outside it is 403 `network_not_allowed`, checked in the auth path for that client's keys, so it covers every route and the setup exchange. An open page whose key is refused stops polling and says so (a revoked or rotated key says the link no longer works). No alert for a key used from a new place, by decision.
- Share as built: `panelshare.js` opens the modal (`openShare(panel, {api, onSaved})`); another tab joins by pushing a function onto `shareTabs` that returns `{id, text, panel}` or null. People saves only the `share` field through `PUT /api/v1/panels/{id}`. The picker reads `GET /api/v1/panels/people` (names only, a user's key only). Pure rules (`shareDraft`, `pickList`, `shareBody`, `shareChanged`) are in `panelsrules.js`.

## Monitoring

Proposed, not prototyped.

- Each open panel page is an instance with a device name given the first time it opens. It sends a keepalive every 15 seconds. Sode keeps the last seen time and state for each instance, and a panel is online while at least one instance is.
- A user can watch panels. A user can watch the panels they own, and a Trusted user can watch any panel. The watch list is a set of checkboxes in the editor and in the My panels page.
- When a watched panel loses its last instance, or its keepalive is missed for more than 45 seconds (8 seconds once its stream closes, see the as-built notes below), every watcher is notified: a toast and a badge in Sode, and a browser notification if the user allowed them. A second notice goes out when it comes back. The notice names the panel, the device and how long it was missing.
- Open questions, decided below: no expected instance count, and no alert for a key used from somewhere new.

## Monitoring (as built)

- Modules: `panelmon.go` (devices, watches, sweep, notices), `panelkeepalive.js` (device name form and the 15 s keepalive), `panelwatch.js` and `panelwatchrules.js` (toast, badge, browser notification, text), `panelsmon.js` (online mark, Open now list and Watch checkbox on the panels page; the editor Access tab mounts the same checkbox), `panelmon.css`. Routes and fields are in docs/api.md.
- An instance is a device name, ignoring case, so a reload or a rebooted kiosk with the same name is the same instance and raises nothing. The name is asked once per browser (`sode-panel-device`). A page also holds a stream (`GET /panels/{id}/instances/stream`, fetch with the Authorization header, which also covers Session mode), so Sode sees a closed page at once and counts the device lost after an 8 s grace; a reload with the same name inside the grace raises nothing. The 45 s keepalive miss stays as the fallback for a page without a stream or whose stream went quiet. A panel is online while any device counts. Devices live in memory only, so a restart of Sode alerts nothing. A lost device is dropped after 24 hours.
- The Sode page shows a banner at the top for the watched panels that are offline, with Open panels and a Clear button. Clear expands to "Clear alarm for now" (hides that outage for the user until the panel's next notice, memory only) and "Stop monitoring this panel" (ends the watch); both go as the `panelAlarm` socket message. Pages without a banner keep the badge. The Watch checkbox shows what the browser allows for notifications, asks when Watch is turned on, has an Allow notifications button while the answer is open, and says when the browser has blocked them.
- A sweep runs from `periodic` and tells each watcher once when a device passes its limit (45 s, or 8 s after a closed stream), and once when it returns, naming panel, device and seconds, with `offline` true when no device is left. Each change is one `panelLost` or `panelBack` row in the Communication Log, naming the panel's short name and the instance, as every row from a panel page does (docs/agents/comm-log.md).
- Watchers: the owner or a Trusted user, checked again when a notice goes out. The list is `panelwatch.yaml` beside the config, never in a panel file, and the API only sends the caller's own `watching`. Notices go to connections signed in as the watcher and not under the Lock. `panelsOffline` rebuilds the badge after a reload or sign-in; a notice sent while nobody was signed in is not kept.
- Deleting a panel forgets its devices and watches. Making, rotating or revoking an instance's key forgets that device, so an ended kiosk does not alert.
- A panel client's keys share one rate limit that scales with its live devices, since each page polls every 2 s. Its streams are capped at 64 per key and not counted per address.
- Watch is per panel and per instance (alpha G). The panels page's Open now list has a checkbox on each instance, and a user may hold both. A whole-panel watcher hears about every device as before. An instance-only watcher hears only about that instance: a lost or back toast that never says the panel is offline, an alarm row `Wall lost Studio A`, and Stop monitoring on that row removes only that instance's watch. The editor's checkbox stays whole-panel.
- Dead peers: the server turns on TCP keepalive for every accepted connection (2 s idle, 1 s apart, 3 misses), so a device that vanished without a FIN ends its stream in about 5 s and is lost 8 s later, inside 15 s. A proxy that keeps its upstream connection open hides this, and the 45 s miss applies. The panels page refreshes the online marks and Open now every 2 s.
- The offline toast's title links to the panel, and its "has not been heard from for" time counts up while the toast is open until the device returns.
- Decided: no expected-instance count, and no alert for a key used from a new place.
- Not built: the Watch checkbox in the editor (story 90; mount `watchBox` from `panelsmon.js` when wanted). It is on the panels page.

## Panel page (as built)

- Modules: `panelmodel.js` (pure state model: view, stage, arm, Take, results), `panelrules.js` (URL, API answers, cell checks, error text), `panelview.js` (draws the grid), `panelrun.js` (loads the panel, polls, sends the take), entry `panelpage.js`.
- Stored cell: `{ r, c, rs?, cs?, kind: source | destination | take | preset | clear | current | panelName | instanceName | goToPage | nextPage | previousPage, n?, scope?, name?, page?, caption?, levels? }`, with `r` and `c` from 1. A Preset cell holds `scope` (`everyone` or `me`) and `name` instead of `n`; `current` is the Current Destination cell; a Go to Page cell holds `page`, its target Page's id. Cells that are outside the grid, unknown, a Source or Destination without `n`, a Preset without both, a Go to Page without `page`, or overlapping an earlier cell are not drawn. Settings read: `mode`, `multi`, `levels`, `guard` (`hold` or `double`, anything else is none), `fixedDests` and `wrapPages`.
- Fixed destination is `settings.fixedDests`, a list of at most 16 different destination numbers. The server checks it on every save and drops an empty list. A template keeps it only with `dests`, and a Push leaves each target's own list, since sibling panels often patch to different destinations; a Checkpoint set and a restore put each panel's own list back. The panel page reads it as in Behavior above (`fixedDestsOf` and `drawnCells` in `panelrules.js`); the editor sets it in the Panel tab (Editor above).
- A Preset cell stages every route of the preset (`GET /presets`, polled with names) and views its first destination. One refused route (Protected, no common level) refuses the whole preset. With `multi` off a preset with more than one destination is refused. A taken route is sent as an ordinary `POST /takes`, so History shows routes, not the preset name. Clear, Current Destination, Panel Name and Instance Name have no stored fields beyond `caption`; the last three are disabled.
- Instant mode: `startInstant` is called right after a Source or Preset press, and one route set is held at a time, so a new press replaces a failed one. The Take cell stays disabled. Guards apply to the Take cell only: `double` needs a second press within 1.5 s, `hold` 0.8 s of pointer or Enter and Space held (`guardDown`, `guardHeld`, `guardCancel`).
- A browser cannot send a Bearer header on `/api/v1/stream`, so the page polls `/tally` and `/protected` every 2 seconds and `/names` every 30. A take is `POST /takes`, which is its own Confirm, with an `Idempotency-Key`.
- Live update (P15): the page reads `GET /panels/{id}` every 5 seconds and compares `rev`, which `panelStore.writeLocked` moves on every stored change. A newer copy shows a banner counting down 10 seconds (`Refreshing in N s`) over a countdown bar, the main page's result bar (`sode__banner-bar`), with Snooze 60 s and Apply now. At zero the copy applies unless a take is in flight or routes are staged; then the banner says it waits, the bar goes, and it applies once they are taken or cleared. Snooze never dismisses the banner: it stays up, the bar counts 60 seconds, and at the end the copy applies with the staged routes dropped (the line says so: `Refreshing in N s, dropping the staged routes.`); an open page snoozes once, so after the first Snooze the button is gone for that page (the banner keeps its 60 second countdown and Apply now stays), and the next update after an apply brings one Snooze back. Apply now applies at once, staged routes or not. The rule: the countdown alone never drops a staged route, since nobody asked for the change on this page, but Snooze and Apply now are the person's own press and so are their word that the routes may go. A take in flight is never cut short by either; the copy applies once it answers. The viewed destination survives the refresh (`carryView`, `panelmodel.js`). The rules are `panelupdate.js`, the poll and banner `panellive.js`. A Push (P17) only has to store the target panel through `panelStore.replace` and open panels follow.
- The panel header shows the instance's name and a click edits it (`panelname.js`). A rename restarts the keepalive and held stream under the new name (`startKeepalive().rename`) and stores it in `sode-panel-device`; the old name is lost after the usual grace. A name from the link's `?instance=` is not editable here; the panels page can rename it, and the page then rewrites its address (Rename above). Full width is an icon-only button (`chevrons-left-right`, `chevrons-right-left`) with `aria-label` and `data-pb-tip`.
- The page cannot read a panel's mode before it has a key. A key in the URL fragment (`#key=`) means API mode. Without one the page starts a session key (Session mode) and, if the panel then turns out to act only as an API client (`acts: api`), asks for its link with the key instead of running. A Both panel runs on in Session mode.
- A failed route stays staged after a take, so Take can be pressed again. A level with nothing routed is ignored when finding the current source. `GET /panels/<id>` carries the caller's own Rights as `rights`, and the page refuses a Source or Destination outside them (and a Preset outside them) before arming, as `outside-rights`; hidden Visibility makes that message name nothing. Levels the Rights exclude drop out of the take, and none left is `no-common-levels`. The server refuses the same route anyway, so keep `rightsAllow` in step with `config.Rights`. Setting `resultText` adds the Result word beside its icon. Kiosk (`settings.kiosk` or `#kiosk=1`) hides the header and the Lock button bar (`data-sode-kiosk` on the root, `panels.css`) and fixes the box that holds the status line and the update banner (`.sode-panel__foot`, `#panel-foot`) to the bottom of the viewport, so a refusal or a countdown never moves the grid; `TestChromePanelKioskAndRefusal` and `TestChromePanelLockBarLayout` cover it. Otherwise that box sits between the header and the grid, and the page keeps the bar's height free at the top (`data-sode-chip`), so it never covers the title or the grid, in full width too.

- Offline (`offlineOf` in `panelrules.js`): when a poll fails with no answer or a 5xx, or `GET /status` says `routerUp` is false, the page blurs every other element, blocks presses and shows a large framed Offline message (`pb-state-offline`) with a sentence saying whether Sode or the router is gone. It clears on the next good poll. A key without the `status` scope gets 403 there, which counts as an unknown router link, not down. A session that is not signed in yet is not Offline. `TestChromePanelOfflineAndFullWidth` stops the Sode API and the simulator.
- Full width: the header button (`panelfull.js`) drops the page's width cap and padding and is remembered in `localStorage` as `sode-panel-full`. A panel without a title bar, or in kiosk, has no button.
- Header buttons, left of Full width and the same icon size: Full screen (browser Fullscreen API, `panelfeel.js`; tracks `fullscreenchange`, hidden where the browser refuses it) and Kiosk. Kiosk turns kiosk on for this open page only; the panel setting and `#kiosk=1` give the starting state and a reload returns to it. The header is gone in kiosk, so the way back is the Escape key (unless a dialog already took it) and a faint button in the top right corner (25% opacity, full on hover or focus). Rules in `panelchromerules.js`.
- The Panels link is an icon-only ghost button with the Sode Panels logo at the bottom left, as on Sode's main page: fixed on the desktop layout (the page is padded so it never covers the grid) and in the flow at the end on a phone. A kiosk hides it with the header.
- The Current cell reads "<destination> is currently:" for the viewed destination, and its caption when it has one. The Take cell is solid when nothing is staged, pulses when a route awaits it, and fills left to right (a transition, not an animation) while a hold or double-press guard waits.

## Look and device settings (as built)

- Modules: `panellook.js` (pure: reads settings and cell artwork), `panelart.js` (artwork fetch), `panelfeel.js` (wake lock, fullscreen, landscape), with the page wiring in `panelrun.js` and `panelview.js`. Tests in `web/test/panellook.test.mjs` and `panelart.test.mjs`.
- Panel `settings`: `titleBar` (false hides the title bar, the header with the name and the Panels link; kiosk hides it too), `fontSize` (percent, 50 to 200, default 100), `theme` (`light` or `dark`; missing uses the browser's setting; the old `backdrop` is ignored), `wake`, `fullscreen` and `landscape` (true to switch on; fullscreen is asked for on the first press, since a browser needs a touch, and landscape locks the screen turn once that fullscreen starts. Landscape alone also asks for fullscreen on a press, since Chrome locks the turn only there (`wantsFullscreen` in `panelfeel.js`), and the editor says so beside both switches. iOS has neither the lock nor iPhone fullscreen, so a portrait page with landscape on is covered by a Turn your device message, and the page's `apple-mobile-web-app-capable` meta makes a Home Screen copy open without Safari's bars). Cell fields: `art` (`icon:<vendored icon name>`, `lib:<Icon library id>` or an artwork id), `artB` (Icon B, `0` to `16` or `A` to `Z`), `fontSize` (percent, multiplies the panel's) and `hideText` (true hides the text while the cell draws Icon A or B, its own or a default's; false shows it against a default; unset takes the default's).
- Colours: an idle Source is `--pb-current-idle`, an idle Destination `--pb-view-idle`, both the state colour muted into `--pb-surface-control`. Viewed and Current are solid. Staged, pending and an armed Take swell between 72% and 100% of the state colour on `--pulse`, and each also has a static inset ring, so reduced motion (which freezes `--pulse` at 0.6) still shows state.
- Artwork: the route needs the Authorization header, so the page fetches it with the panel's key and shows a blob URL in an `<img>`. SVG is never inlined. The CSP allows `blob:` for `img-src` only. A fetch that fails leaves the cell without artwork. An icon name missing from the vendored sprite draws nothing.
- Keep the screen awake: Screen Wake Lock, requested when the page opens and again whenever it becomes visible, since a browser drops the lock when the page hides. A refusal is ignored, and a press asks again, since Safari may refuse a request made without a touch. Plain http has no wake lock, and the page says so. `featureSupport(navigator)` in `panelfeel.js` says what the browser has, for the editor to disable the switch. Haptics were tried and dropped: iOS has no vibrate and the switch-input tick and `navigator.vibrate` gave nothing on the phones tested, so an old `settings.haptics` is ignored. Result of the spec's proposal: built as described, with no extra settings.

## Push as built (P17)

- Server: `panelpush.go` (layout, checkpoints, set store) and `apipush.go` (routes). A layout is `rows`, `cols`, `pages` (every Page with its id), `settings` and unknown fields; id, name, owner, `share`, `acts`, the API client and its Rights are never copied, and missing artwork is. `panelStore.applyLocked` writes the checkpoint before the panel, so a checkpoint that cannot be saved stops the Push, and the panel write moves `Rev` for open panels (P15).
- Reach: the pusher must be able to change the source and every target (`panelReach`); one refused target changes nothing. Checkpoints sit in `panels/<id>.checkpoints`, at most 10 per panel, and a restore keeps what it replaces. Sets are in `panelsets/` (`everyone.yaml`, `me-<hex of user>.yaml`); an Everyone set needs a Trusted user to save and to change someone else's.
- A group is the panels whose names differ only by a trailing number (EVS 1 to EVS 4 are "EVS"), worked out by the page (`pushGroups` in `panelpushrules.js`); the server only knows ids. Pending the owner's confirmation: this meaning of group was chosen in the build, not in the spec. `pushTargets` is the tested selection rule.
- Web: `panelpush.js` is the modal (Push, Checkpoint sets and Restore tabs), opened by Push to panels in the panels page's detail bar. The editor toolbar has no Push control, although the Editor section lists one.

## Build notes

- Editor Find: `findrules.js` is pure (entries with Rights and Visibility, ranking, the run a choice places, the plan and `applyFind`, which sets a Preset cell's `scope` and `name`). `editorfind.js` is the flyout in the smart menu: it plugs in through `addMenuSection` and `addKeyHook`, catches `myRights` at import time because the message can arrive before the editor loads, and previews by marking the grid's squares in place. Fill order is `setOrder(id)`, default `across`.
- Editor Artwork tool: `arttoolrules.js` is pure (`artToolPlan`, `applyArtTool`). `editorarttool.js` is the flyout, added after Find through `addMenuSection` so it sits below Find. Its columns come from the Cell tab's `artPane` and its upload from `uploadArt` (`editorart.js`). Fill order is Find's: `initFind` returns `order`, `setOrder(id, { focus })` and `onOrder`.

- Vanilla ES modules and patchbay tokens only. The prototype used `pb-btn pb-xpt` cells, `pb-toolbar`, `pb-toast` and the Lucide sprite. Orange and the muted idle colours need new semantic tokens upstream, since `--pb-brand` is for navigation chrome.
- Status is icon first, with optional text. This is a documented exception to patchbay's "status always with text", and AGENTS.md has a line for it.
- One animated root custom property (`@property --pulse`) drives every pulse, so cells stay in phase across re-renders.
- The settings in the editor's sidebar are a first pass for the prototype. Several of them, such as keeping the screen awake and the networks allowed, are placeholders and may change.

## Decisions where the build differs from the design

- Monitoring: no expected-instance count, and no alert for a key used from a new place. Keepalive every 15 seconds and a held stream; a device is lost 8 seconds after its stream closes, or 45 seconds after its last keepalive when it has none, and forgotten after 24 hours.
- Allowed networks are a CIDR list, at most 16 per panel client. A bare address is one host.
- A setup link lasts one hour and works once.
- Push group: panels whose names differ only by a trailing number. Pending the owner's confirmation.
- Editor sidebar: the Panel tab has no colors or updates settings, because nothing reads them. The level boxes show every level ticked when no subset is stored, and the last ticked box cannot be cleared.
- Push has no control in the editor toolbar; it is on the panels page. The editor's Watch checkbox (story 90) is on the Access tab, beside the one on the panels page.
- Panel and cell levels and Visibility are conveniences of the page. The Rights of the user or API client are the only limit the server applies.
