# Sode Panels: design

A prototype on branch `prototype/panels` validated this design. The branch has three variants and stays the primary source. The terms are in GLOSSARY.md under Panels. ADR 0006 tells who can create the API client of a panel. ADR 0011 tells how the panel types work. The Grid panel prototypes are on the same branch (`grid/`, served by `serve-grid.mjs`).

The panel page prototype is `git switch prototype/panels && node prototype/panels/serve.mjs`: variants A, B and C on :8101 to :8103, with stub data and no router.

## What a panel is

A panel is a Buttons panel or a Grid panel. The person who makes it chooses the type, and the type never changes (ADR 0011). A panel with no stored `type` is a Buttons panel. This file is about Buttons panels, except the Grid panels section. Authentication, the panels page, Monitoring and Push cover both types.

A Buttons panel is a saved grid of cells on its own URL (`/panels/<id>`, or `/panels/<slug>` when it has a short name). The default size is 8 columns by 4 rows. It drives the router through `/api/v1` only. That size was chosen so that a panel maps one to one onto a hardware key deck later. Rows and columns become user settings, and merged cells stay inside the grid. The panels page `/panels` signs in like the rest of Sode and launches a user's panels. The editor, at `/panels/editor`, edits them live.

Pages (ADR 0007): a panel holds `pages`, 1 to 16 Pages in order. Each Page has an id that never changes, an optional name of at most 40 characters, an enabled switch and its own `cells`. A Page with no name shows as "Page N". Every Page has the panel's size and shares its one plan.

The store checks the list on every save (count, unique ids, name length). It also fits each Page's cells to the grid, so a resize drops the cells that no longer fit, on every Page. The editor's status note counts them. A panel saved before Pages loads as one Page.

The stored shape is built (`internal/app/panelpagelist.go`, `web/panelpages.js`). The editor edits every Page (the Pages bar, below). Push, Copy, templates, Checkpoint sets and restores carry every Page with its id. Fixed destination keeps Destination cells out of the grid of every Page that the page draws.

Page rules on the panel page (`web/panelnav.js`, `panelmodel.js`): the current Page is part of the state (`st.page`, an id) and the plan is panel-wide. Thus a Page change never clears the view or the staged routes, and Clear and Take act on the whole plan from any Page.

Three cell kinds move between Pages. Go to Page (`goToPage`) stores its target as `page`, a Page id, so a reorder or a rename keeps it. It shows the Page's name ("Page N" when empty) unless its caption replaces it. It works when the target has no cells. It is greyed and does not accept a press when the target is disabled or deleted.

Next Page and Previous Page (`nextPage`, `previousPage`) skip disabled Pages. While the panel setting `wrapPages` is on (the default), they wrap past the ends. With it off, they are greyed at the ends. With one enabled Page, they are always greyed. A press sends nothing, so it works while the panel is Offline.

The browser keeps the current Page in `localStorage` as `sode-panel-page-<panel id>` and reopens it after a reload. A live update keeps it. If that Page was disabled or deleted, the page moves to the first enabled Page (Page 1 when every Page is disabled). The Live Editor neither reads nor writes the saved Page. It opens on the Page that you edit and runs the saved panel with its one plan.

The server refuses only a malformed target (not a string, or not shaped like a Page id). It stores a missing target as it is.

In the editor, a Go to Page cell gets its Page from a list in the Cell tab (`editorpagetarget.js`), by number and name. A cell with no Page is unassigned, and a cell whose Page was deleted is dashed. The Cell tab warns when the target has no cells or is disabled. Find lists the three kinds as single entries, as it does Clear. A template keeps a Go to Page target with either option or none, since the target is layout. A paste into another panel drops the target and says how many cells came in unassigned. `TestChromePanelPages` covers the panel page.

Storage: one YAML file per panel under `panels/`, with an `id` and a display name inside the file. A user makes their own panels with their existing Rights. A Trusted user can also make a panel that acts as its own API client, with Rights no wider than theirs. Panels can be shared use-only with named users or Everyone, and a user can save a copy to edit.

## Behavior

- A press on a Destination cell views it. The grid then shows what that destination has now: its current source is solid green and every other source is idle.
- A press on a Source cell stages it for the viewed destination, and the staged source pulses green. Staged destinations pulse orange and show the staged source under their name.
- Take applies every staged change. Clear drops them all and the view. A second press on a staged destination unstages only that one.
- Undo stages the reverse of the newest take this instance made that nothing has undone. It works like a Preset press: Take mode arms the Take cell and its guard applies. Instant mode makes the Undo press the Confirm. A take of several routes goes back together. The staged undo replaces the plan, and its destinations pulse orange with the source they go back to. The page views the first one. With Fixed destination on, the view stays. After it is taken, the next press goes one take further back, and the status line names what was undone. With nothing to undo, the status line says so and the plan stays.
- A staged undo is one unit, because Sode works out the undo from History when it is taken and cannot send part of one. A Source or Preset press replaces it whole. A second press on one of its destinations drops it whole, and Clear drops it. If it were sent as an ordinary take, its routes would leave the take undoable, and the next Undo would stage the same take again. A second Undo press before Take stages the same take, since a take counts as undone only after its undo is sent. A staged undo is never trimmed when the router already has a route, and it holds back a live update like any staged route. After its Take is answered, the plan is empty, whatever the results. A failed route leaves its take undoable, so another Undo press stages what is left.
- Multi-destination is a panel setting, on by default. When it is off, the panel stages one change at a time.
- A Preset cell stages the preset's routes, so you can preview it on the viewed destination. It works in the panel's mode. Take mode arms the Take cell. Instant mode makes a press on a Source, Preset or Undo the Confirm.
- A Take cell arms when something valid is staged. Optional guards are a hold or a double press.
- Current Destination shows only the source now on the viewed destination, under the caption "Currently".
- Panel Name shows the panel's name, and Instance Name shows the instance's name (its device name). Each has its caption as a line above. Neither can be pressed. A page that has no instance name yet, and the Live Editor, show the kind's words instead.
- Page Name shows the Page it sits on: its name (the default), its number, or both. Checkboxes in the Cell tab set the choice. Info shows any of panel name, Page number, Page name and instance name, one per line. A new Info cell shows all but the Page number. Both read the Page they sit on, so a copy pasted onto another Page names that Page. Neither can be pressed. The choice is stored in `show` (`web/pagecells.js`).
- Idle cells are the active colours muted into the control surface, so user-chosen colours carry through. The pulse breathes between about 72% and 100% of the state colour on one shared 2-second cycle. Static rings let the state survive reduced motion.
- After a take, a destination shows its Result as an icon (connected, already, failed). Result text is optional and off by default.
- Before it arms, the page refuses these with an error. They are a Protected destination, a route outside the panel's Rights, and a Source and Destination with no common level. Levels are set per panel and per Source or Destination cell, and a take sends the intersection.
- Fixed destination (`settings.fixedDests`) gives a panel a list of destinations and no viewing step. A Source press stages a route from that source to every fixed destination, except one that already has it. When all of them have it, the press drops the staged routes instead. A Preset press stages only the preset's routes to fixed destinations. If the preset has none, the page refuses the press and names the preset. A refusal on any one fixed destination (Protected, outside the Rights, no common level) refuses the whole press. Each press replaces the plan, so Stage several Destinations has no effect. Take mode, Instant mode and the guards work as without it. Clear drops the staged routes but keeps the list. Destination cells stay stored but are not drawn. The page has no list of them (a strip that showed each one was removed on request). The Current Destination cell and the Source cells' current state read the first one. A panel without the setting behaves as before.
- The viewed destination and the staged routes have no clock: only a press, a take or Clear ends them. (An earlier build cleared them after 30 idle seconds. A wall tablet that forgot its destination mid-thought was worse than one that kept it.) A saved edit refreshes open panels after a 10 second countdown. A banner shows the countdown, with Snooze 60 s and Apply now. The Live update note below says what each button does with staged routes. The page keeps a viewed destination through the refresh.

## Grid panels

A Grid panel is a patch field: sources across the top, destinations down the side and one crosspoint for each pair. It is for a person at a desk who works on a large router, where a Buttons panel would need a cell for every item. The prototypes are on branch `prototype/panels` (`grid/`, `serve-grid.mjs`). ADR 0011 gives the type rules.

### What it stores

- A Grid panel has `type: grid`, a `sources` list and a `destinations` list. It has no `rows`, `cols`, `cells` or Pages. The server refuses a body with a non-empty `cells` or `pages`, so a client can send a read back unchanged. A change of `type` is 409 `conflict`.
- An edge (the sources, or the destinations) keeps its members apart from its per-item settings. Members are `all`, which tracks the router in router order, or an ordered list of router numbers. `hide` leaves items out of an `all` edge. A list with `hide` is refused.
- `items` holds one entry for each router number, keyed by the plain decimal number. An entry has `pinned`, `art`, `artB` and `hideText`. A pin does not stop an `all` edge from following the router. While Follow the router is on for an edge, the editor changes only its pins and artwork. Follow the router off turns `all` into a list.
- An edge pins any number of items. The API refuses a number given two times in a list or in `hide`. Items for numbers that are not members stay stored.
- The Rights are the only limit that the server applies. A Grid panel draws only the items that the router reports and the viewer's Rights allow. A list number that the router does not report, or that the Rights exclude, stays stored and is not drawn.
- Push, Copy, Checkpoint sets and restores carry the lists, hidden items, pins and item artwork. A Push or a Checkpoint set of the other type is 409 `conflict`. Default artwork shows on a Grid panel's names, and the Icon library use count includes them.

### The page

- Layout: the Source bar is across the top, the Destination bar is down the side and the crosspoints fill the rest. On the desktop layout the page's root text size is 112.5%, not 125% (owner, 2026-11-17); the phone stays at 100%. The header, the Levels box and the two search boxes are one raised band over the grid, the deck. The header row is its top row, with a line under it. It is laid out as the main page (owner, 2026-11-17). At the left are the Lock chip and a rule, then the title, the instance name and a rule, on the chip's centre line. Then come Settings, the Panels link, Edit or Copy, a rule and Full screen. Settings is a link to the main page's Settings. It shows with the Title bar setting off too; only kiosk mode hides it (owner, 2026-11-17). Edit shows when the user can change the panel. Copy (Save a copy) shows when the user can only use it and a signed-in user runs the page. These are the panels page's rules, and Copy opens the copy in the editor. The Server and Router status is at the top right. In kiosk mode the header row goes and the grid moves up (owner, 2026-11-17). Take results, refusals and the "This panel was changed" banner are one banner, the main page's, in the gap between the search boxes and Clear (owner, 2026-11-17). The banner is as tall as the Find box, with a rule between them. A success fades on the main page's timer, with its countdown bar; a failure stays until its X or until its cause clears. A success never takes the place of a failure or a state that waits. The banner's corner counts what it held back ("1 message not shown"). The X clears both. A new failure of the same kind joins the shown one ("2 takes failed"). A screen reader gets each banner's words from one live region. A result shows over the "This panel was changed" banner, and a new update notice takes the place of a result. The gap keeps at least 10 rem for it. The grid does not move when the banner shows or goes. Under the header row, rules divide three groups: the Levels box, the search boxes with the Find/Filter switch, then Clear and Take. The switch is the word over the switch. The word is the mode that is on, Find or Filter, and the tip says what each does. The search boxes are at most 14 rem wide. A column whose words change has a fixed width, so the band does not move. The Levels box looks like the main page's: large words, four picks wide. Select all is a short, quiet button under it, as wide as it, both in the picks' height. Below 1280 px the box gives way to the search boxes. The V level pick is one pick wide and two picks high, as on the main page. In Take mode, Take is at the right end of the deck and always says only Take. It is the main page's red Take (`pb-btn--danger`), and it glows on the panel pulse while routes are staged. Clear drops what Esc drops. Over Clear and Take, a chip counts the picks, or the staged routes when nothing is picked. There are no help words. In the corner, "Destinations" runs along the bottom, next to the Destination bar. "Sources" is on its side down the right edge, next to the Source bar, with an arrow along the Source bar. Each word and its arrow are centred in the role colour. Each name shows its router number before it (the number a person sees, with `numberOffset`), in the number font, for example "12 CAM 1". A source's number is on a line over its name, since a source name is one crosspoint wide. The page fills the window, and the grid goes to the edges and to the bottom.
- A new Grid panel has no sources and no destinations. A Grid panel with none on an axis shows a note in the grid. A user who can edit it also gets an Edit panel link.
- Header: the Layout item above gives the header row. The main page's Server and Router status, with the router's address (`connview.js`), is at the right. The Take button shows the take mode. Kiosk mode is a panel setting, so the Grid panel page has no Kiosk mode button. The Lock chip says "Signed in as" the user, as on the main page. Below 1152 px the status shows its dots and the address only. Full screen is a ghost icon button, as the Panels link is. The Panels link is in the header while the header shows. With the title bar off it goes back to the bottom left. On the phone layout the header has no status.
- A picked row or column of crosspoints has a wash of its role colour, and a crosspoint in both has a neutral wash. The crosshairs show through.
- Pinned sources and destinations stay at the top and side edges while the rest scrolls, and their crosspoints stay with them. A pinned band takes at most half the room past the names (`pinsShown`). So any number of pins leaves room for the grid in a short or narrow window. When an edge has more pins than that, its band scrolls on its own (owner, 2026-11-17). A little scroll bar along the pinned names, the wheel over the band, a key move or Find moves it. The band moves with the wheel px by px, as the grid does (owner, 2026-11-17), with a part pin at each end. The rest of the grid scrolls as before and does not move with it. The phone layout has no band bars, so there the pins past the band scroll with the other items, first in order. A line marks the end of each pinned band. The corner holds what is pinned on both axes. The grid scrolls on both axes, and its scroll bars always show. On the desktop layout they are Sode's own big scroll bars (bigscroll.js), 1.4rem (25 px) on both axes, in every browser. A vertical wheel over the horizontal bar scrolls the grid across. The phone layout keeps thin native bars; there `wheelAcross` in `gridpanelwindow.js` does the same over the native bar.
- Names show as text, with the item's artwork beside them: its own `art` and `artB`, else its Default artwork. Hide text works as on a Buttons cell: the item's own `hideText` true or false, else its Default artwork's. A hidden name shows only its artwork, a little larger, and screen readers still read the name.
- A crosspoint shows a pie of the destination's levels. A level that has the crosspoint's source is filled. A staged crosspoint has a pulsing ring with the same slices, filled for the staged levels. A destination whose current source is not on the panel names that source, plus "+N" for more. A protected destination shows a lock and "Protected", and its crosspoints stage nothing. A destination with a staged route shows "staged" under its name.
- The cursor is a ring on one crosspoint. It grows and shrinks, and it is still when reduced motion is set. The mouse and the keys share it (see Keys). On a bar it is a box only after a key move. The pointer never shows a box, and a press does not focus a crosspoint or a name.
- The page draws only what shows (`web/gridpanelview.js`, window maths in `gridpanelwindow.js`). It was tested at 2500 sources by 750 destinations. The number of nodes stays bounded, and a scroll adds or removes none.
- Authentication mode, sharing and Assign work as on a Buttons panel. So do the page lock, the Lock bar and the Offline message. A Grid panel has no Pages, Take cell, Preset cell or Fixed destination. A Grid panel is always full width, so it has no Full width button.

### Levels, staging and the take

- The Levels box is the main page's (`web/levelbox.js`). It starts from the panel's `levels` setting, limited to the viewer's Rights, and `f` moves focus to it. A press stages a route on the levels in the box. Levels that the Rights exclude drop out of the route.
- A press on a crosspoint stages one route. A second press on a staged crosspoint presses Take, also on a staged Diagonal or Drawn line. It opens the take confirm, and the user answers with the key it shows. In Stage + Take mode it sends at once. In Take mode, a press that adds nothing new is the second press, so the same Diagonal again also confirms. A press on new levels stages them. A press on another crosspoint stages that one. Clear and Esc drop all staged routes. A right-click or an Alt-click on a staged crosspoint, or Delete or Backspace at the cursor, unstages only that route. Clear's tip and the key list say so. Staged crosspoints pulse. Only the staged crosspoints run the animation, so a large grid costs no more than a small one. The cursor ring, the staged rings and the armed Take run the one pulse (`--panel-pulse-s`) in one phase.
- At most 128 routes can be staged. A press that would pass the cap stages nothing and says so.
- The take is its own Confirm, as `POST /takes` is. In Take mode, Enter or the Take button opens the confirm. It lists the plan and the routes that Sode left out. Under Currently, it shows the source each destination has now on the take's levels, as the main page's confirm does. In Instant mode, every press sends at once with no confirm, a Diagonal and a Drawn line too. The confirm uses the churning letter and the lockout, and the Enter-optional setting applies.
- The Panel tab's Mode for a Grid panel has three choices: Instant, Stage + Take and Stage + Take + Confirm (the default, stored as `take`). Stage + Take (`takeOnly`) has no confirm box. Take, Enter, a second press and the Undo's Take send at once. The status line names what was left out. The ask before an Undo drops staged routes stays. A Buttons panel has no confirm box, so it keeps Stage, then Take and Instant, and reads `takeOnly` as Take mode.
- Sode checks each staged route again before the take. A route is left out when its destination became protected, or when its source or destination left the Rights or the router. The confirm names each one and says why. A failed route stays staged.
- Esc drops one thing at a time. The first Esc ends a Drawn line in progress, the next drops the picks and the last drops the staged routes. This also holds in Kiosk mode.

### Picks, Diagonals and Drawn lines

- A click on a name picks it. Shift-click picks a range, and Cmd or Ctrl-click adds or removes one. A mouse drag along a bar picks the names from the press to the pointer. With Cmd or Ctrl held, it adds them to the picks. Picking stages nothing. The header shows the number of staged routes.
- A crosspoint press with names picked stages a Diagonal. It pairs the picked sources with the picked destinations in order, from that crosspoint, and stops at the last shown destination. The crosspoints that it will stage show numbered before the press, and each name of a numbered pair shows the same number. A name in more than one pair (the one source of a line) shows none.
- A Diagonal and a Drawn line skip protected destinations, and the banner names the skipped ones (three, then "+N"). In Instant mode the rest send at once, and the banner of the take names the skipped ones. If every target is protected, the press stages nothing and says why.
- A Drawn line is a drag across the crosspoints (a long-press and drag on touch, or `v` and the cursor keys). It stages one route for each destination row that it crosses. With no names picked, the line snaps to evenly spaced targets, and the preview shows the snapped line. On release the line goes and its routes stage, as a Diagonal does. Take mode only stages them. Instant mode sends them at once.
- A live update, or a Filter that changes the shown names, ends a Drawn line in progress.
- Two or more names can be picked on a bar, with the cursor on one of them. Then a move into the crosspoints goes to the first picked name. So a range picked with Shift moves numbers from its start.

### Find and Filter

- The Source bar and the Destination bar each have a search box in the deck. `s` and `d` go to them, and each box shows its key. The empty box names the mode and its bar ("Find sources", "Filter destinations"). A box matches the router number and the name, with the editor Find's scoring as a yes or no, and keeps the panel's order.
- Find marks the matches and moves the cursor to the best one, ranked as the main page's Source and Destination boxes rank them. The grid scrolls smoothly until that name is in the middle. Then a ring in the strong text colour flashes round the name three times. The name's own colours do not change. The steps go from best to worst. To step, use Enter and Shift+Enter, or Ctrl+N and Ctrl+P, in the box. The arrow buttons beside the box and `n` and `N` on the grid also step. Chrome on Windows and Linux keeps Ctrl+N for a new window. Ctrl+/ or the Filter switch changes to Filter. It is a switch, so it reads as a mode and not as an action. A Filter shows only the matches and the pinned items. One mode serves both boxes for the visit, so a change of box keeps it. `n` and `N` step the box typed in last, or the other box when that one is empty. Esc clears the box and puts focus back on the grid.
- A Filter never hides a pinned item. It does not change the picks, or the other sources that a destination names.

### Keys

- Arrows and `h`, `j`, `k` and `l` move the cursor one crosspoint (`h`, `j`, `k` and `l` by the physical key). PageUp, PageDown and Alt with an arrow move one window. Home goes to the corner and End to the last row. Ctrl or Cmd with Home or End goes to the start or the end of the row. Space stages at the cursor.
- On a bar, Space picks the name at the cursor and `x` adds or removes one name. Shift with a move along the bar picks a range. On a crosspoint, Shift with a move picks the names it crosses. A move across picks sources, and a move up or down picks destinations. A focused header button keeps its own Space and Enter.
- `g` or a right-click on a crosspoint or a destination goes to its current source, on the lowest level in the Levels box. `G` or a right-click on a source goes to the next destination that has that source on any level. A right-click on a staged crosspoint unstages it instead. A jump scrolls smoothly until the crosspoint is in the middle on both axes. Then the crosspoint and its two names flash three times, in one phase. `u` stages the Undo of this panel instance in place of the staged routes. It asks first when routes are staged. The Undo has its confirm, also in Instant mode. In Stage + Take mode, Take sends it at once.
- Esc in the Levels box only leaves the box. It never drops picks or staged routes. When the take confirm closes, focus goes back to where it was.
- `?` and Ctrl+? open the key list in the main page's style. The page lock and open dialogs take their keys first. An embedded run (the Live Editor) takes the keys only while focus is in the grid.
- A pointer move changes only the cursor. After a pointer move, a scroll keeps the cursor under the pointer. After a key, a scroll leaves it where the key put it.

### Live update

- A saved change or a Default artwork change reaches an open Grid panel through the same banner as a Buttons panel (Panel page, below). The page keeps the search, the picks, the cursor and the mode.
- The countdown alone never drops staged routes. Snooze and Apply now drop them and close an open confirm, as on a Buttons panel. A staged Undo goes with them.
- The Rights from each panel read reach an open page at once, so staged routes that leave the Rights are left out. A Rights change does not move `rev`.

### Phone and touch

- On the phone layout, a tap on a name picks it, and a long-press on a name picks a range. A double-tap on a name jumps, as `g` does. A tap on a crosspoint stages.
- The grid comes first. The page is one window high and does not scroll. The title always shows on one line. Under it, one band holds More, the levels in words, the note, Clear and Take. More or the levels open the header's buttons, the Levels box and the search boxes under the band (`web/gridpanelphone.css`). While they are open, they push the grid down. On a 390 by 844 phone the grid shows 5 columns by 11 rows.
- In the menu, Find and Filter are two named choices over the search boxes. They take the place of the Filter switch. A tap on them leaves focus where it is, so the keyboard does not open. Every field in the band is at least 16 px, since iOS zooms in on a smaller field and does not zoom back out.
- Crosspoints are 3.5rem (56 px, over the 44 pt touch minimum), names are 6rem wide and the corner is 4.5rem high. The numbered targets show while names are picked. There is no key list.
- No cursor shows on the phone layout, and on the desktop layout a touch hides it until the next mouse move or key move. The box on a bar shows only after a key move. A touch move does not move the cursor.
- A phone draws its scroll bars only while a scroll runs. So the corner gives the shown ranges (`12–16/2500`), and the body's bottom and right edges get thin position strips, display only (`web/gridpanelpos.js`). Draggable thumbs were tried, and the owner chose the strips.
- A Drawn line's edge scroll goes at most 10 crosspoints a second, with the speed the square of the depth into the zone. It is time-based, so a 120 Hz screen is not faster. A finger past the body does not make it faster, and it starts over 400 ms. The zone is 15% of the body's side, at most one crosspoint.
- Two taps on one name inside 350 ms are a double-tap. Both taps still pick or unpick, so a double-tap leaves the picks as they were.

### The editor

- The Panel tab of a new panel has a Buttons or Grid switch. It is greyed after the first save. A new Grid panel has no sources and no destinations, as a new Buttons panel has no buttons. A Grid panel shows its Sources and Destinations lists side by side in place of the grid and Templates. It keeps the same Cell, Panel and Access sidebar on the right third. The Panel tab hides the settings that a Grid panel does not use. They are size, Take button behavior, Fixed destination, Stage several Destinations, result text and Wrap between Pages.
- On a desktop the editor is one window high and the page does not scroll. Each list column has two parts with fixed shares, the panel's list over Add from the router, and each part scrolls inside itself. So an add never moves the rows under the pointer.
- Each list shows the drawn order: pinned rows first, then the rest in list order. A pin on a list moves the item up to the other pins. An unpin leaves it at the top of the rest until it is moved. A move of only pinned or only unpinned rows stops at the line between them. The heading counts the rows ("Sources 12"), and a "2 pinned" button beside it shows only the pinned rows until it is pressed again. Each row has a grip, Pin, Move up, Move down and Remove; a drag starts from the grip or the row's text. A bar of icon buttons over the list acts on every selected row: Artwork, Pin, Unpin, the four moves and Remove. With no selection they are off. Artwork opens the Cell tab with the picker open. An empty list shows only an empty state, with no bar. The Cell tab sets Icon A and Hide text on the selected rows. It runs Icon B down them in the order the panel page draws them, pinned rows first. It does the same on a Buttons panel's selected cells, in Find's fill order. Clear empties the list. The Panel tab's Router section has a Follow the router switch for each edge, which sets the edge to `all`. Switched off, the list keeps what it shows, in the same order. While it is on, Move, Remove, the drag, Clear and Add from the router are off. A note over the list says why. Pin and artwork still apply. The section is one place for these switches, so a choice for each router can go there if Sode gets more than one.
- On a Buttons panel the Cell tab edits every selected cell: text, font size, levels, artwork and Hide text. Page and Show appear when the cells are one kind. Icon B runs one glyph per cell in Find's fill order.
- On an `all` edge, a move turns the edge into a list. Remove hides the item and unpins it. Items that the Rights exclude stay stored and show as a count.
- Add from the router, under each list, shows the router's items that the panel does not have, in router order, limited to the Rights. Find narrows it, and a range such as `101-140` uses the numbers as shown. A click selects an item, Shift-click a range from the last click, and Cmd- or Ctrl-click one more. The + button at the right of the bar under Find adds the selection at the end in router order. In Find, Enter adds the highlighted match, which is the first at the start. Up and Down move the highlight. The next match takes the place of the one added. Shift+Enter, or Add all in the bar, adds every match at the end in router order. Hover does not move the highlight.
- Alt+Up and Alt+Down move the selected rows, and so do Ctrl+Up and Ctrl+Down. macOS gives Ctrl+Up and Ctrl+Down to Mission Control unless that is turned off, so Cmd+Shift or Ctrl+Shift with Up or Down also moves them. ## Authentication

Session mode acts as the signed-in user, with that user's Rights, and the page uses a user key tied to the session. API mode uses the panel's own API client key. A kiosk needs no sign-in: by default the panel URL itself is the credential for that client's Rights. After the key from a link works, the page stores it in that browser and drops it from the address. The key then persists there until the instance is rotated or revoked. A secure mode exchanges a one-time setup link for a key stored in the browser. It stays the one-time option: its link works one time.

Both (`acts: both`) is API mode with Session mode as the fallback. The panel owns an API client and its keys exactly as in API mode (a Trusted user makes it, within their Rights, ADR 0006). The page decides on each open, in the existing order of `panelrun.js`. First comes a key in the URL fragment, then a setup link, then a key this browser stored for the panel. With none of those, it starts a session key and runs as the signed-in user. In that case it runs behind the page lock's PIN pad when the lock requires one.

A session key always needs a user, so a plain link to a Both panel asks for a sign-in. A panel shared with Everyone then opens for any user who signs in. The plain link stays valid (Copy link and the Identity link row show it, with a note). The links with keys are under Share, Link with key. Only API mode refuses a page with no key.

Public (`acts: public`) is a Public panel: anyone who opens its plain URL uses it at once as the panel's own client. It owns the client and keys as API mode does. Only a Trusted user can choose it, with client Rights within their own. A switch to Public checks that even when the Rights stay as stored (ADR 0006).

The page cannot read the mode without a key. So, after the fragment key, the setup link and the stored key, it posts the panel id alone to `POST /api/v1/panels/{id}/public` (`askPublic` in `panelsetup.js`). A Public panel answers with a key for its client that ends 15 minutes later. Any other panel, an unknown id, and a Public panel asked from outside its client's allowed networks answer `{"public": false}`. The page then goes on to a session key. The page holds the key in memory. It asks again when a call answers `key_expired` or `key_revoked` (`publicFetch` in `panelkeyrules.js`). If a key in the fragment no longer works on a Public panel, the page drops it from the address. The page then runs on a Public key, so old bookmarks still open.

A change from Public to any other mode ends every key that Public handed out. A switch to User (`session`) also removes the client and its other keys, as before. Sharing (People, Everyone) has no effect on who can open a Public panel.

The panel page lock shows no PIN pad on a Public panel's page. This is true when the page runs on a Public key and when it runs on a keyed link. `panelrun.js` sends `publicPanel` on the bus when the page has a Public key or reads `acts: public`. `lock.js` then reads the server's `lockState` as if no lock were on (`pinFreeView` in `lockrules.js`). The idle auto-lock still raises the letter Lock with no PIN. A signed-in user's own held Lock (ADR 0001) still asks for their PIN. The server still counts the page locked, so it sends no user names there. A User, Both or keyed API panel behind the lock shows the pad as before. ADR 0008 tells why the key route has this shape.

A switch of Authentication mode in the Access tab shows what the switch does to keys before it applies (`actsSwitch` in `web/panelsrules.js`). The field's choices are User (Session mode), Both, API and Public. User to API or Both makes the panel's own API client with no keys yet. API or Both to User ends the client, every instance key and every setup link, so each instance opened with a key signs out. Either of those waits for the Confirm, the churning letter and lockout that Rotate and Revoke use (`web/confirmbox.js`). Cancel puts the old mode back.

A change to Public always waits for the Confirm, since anyone with the plain link can then use the panel. A change from Public ends its short-lived keys. API to Both or back keeps the client and every key, so it applies at once with no Confirm. The note under the field says what it kept. Every caller that changes the mode goes through `guardActs` (`web/actsguard.js`). An Assign never changes it: it reads the target and writes neither panel, so it runs no Confirm.

No panel file is rewritten, so a delete never changes another user's panel or its `rev`. An open panel page drops the icon on its next load.
  - SVG and PNG files put in `icons/drop-in/` are added at start and by Rescan. A Trusted user sees Rescan in the dialog's header. The file name is the icon name, and the upload's limits and "Name 2" apply. An added file leaves the directory. A skipped file stays and is listed with its reason (docs/reference.md).
- Default artwork: a Source, Destination or Preset can carry Icon A, Icon B and a Hide text choice. Every cell that shows it uses them when the cell sets no artwork of its own. It is one shared set for everyone, in `artdefaults.yaml` beside the config, with its images in `artdefaults.art/` (`internal/app/artdefaults.go`). It is never in the config or a panel.
  - A Source or Destination default is keyed by router number and keeps the router name from when it was set. A Preset default is keyed by scope and name, and only an Everyone preset has one. The set is shared, so the server refuses scope `me` (400). The Cell tab shows no Default artwork row on a Me preset cell (`takesDefault` in `editorrules.js`).
  - A cell's own artwork wins whole: neither icon of the default fills in beside it. Hide text comes from the default unless the cell stores `hideText` true or false. So `false` now means "show the text" against a default. Font size stays per cell. A cell that loses its item shows no default.
  - The default is resolved only when a cell is drawn (`withDefault` in `panellook.js`, before `artNode`). So a save, Push, Copy or template carries a cell's own artwork and never the default. `GET /panels/{id}` carries the defaults of the items its cells show, as `artDefaults`. An open page compares them along with `rev` (`revOf` in `panelupdate.js`). So a changed or cleared default arrives through the same update banner as a saved edit.
  - In the editor's Cell tab, the Default artwork row has three buttons. Set as default sends the cell's own artwork and Hide text (an uploaded image is copied and gets a `d-` id). Clear default removes it. Use default drops what the cell sets, so the cell shows the default again. If the router now gives the number another name, the row warns that it is possible that the default is for another item. The cell still uses it. A set or a clear needs a Trusted user or the Advanced Settings PIN. The row asks for the PIN after the first refusal. A Hidden key sees only defaults for items inside its Rights.

## Panels page

`/panels` lists panels and launches them. The editor (`/panels/editor`) and a panel itself (`/panels/[id]`) are separate pages. The prototype is `prototype/panels/overview/c` (:8123 with `serve-overview.mjs`). Variants A (table) and B (tile gallery) are history.

The Find box on `/panels` is a fuzzy find over name, short name and owner (the editor Find's scoring, `panelScore` in `panelsrules.js`). It puts the best match first inside each group. Ctrl or Cmd with J and K, or the arrow keys, move the highlighted panel. Enter in the Find box moves focus to Launch. Anywhere on the page, Ctrl or Cmd with Enter launches the highlighted panel, and with E edits it. Ctrl or Cmd with J and K steps the highlight (`listKey`; Cmd counts on a Mac only). The buttons show the keys. An open modal turns them off.

- Layout: a list on the left, grouped under My panels and Shared with me. Each row has a mini picture of the grid, its owner, what it acts as (a user or an API client) and an online dot. The right side shows the chosen panel: a large Launch button, Edit, Share, Link with key, Push to panels and Delete. After them come the instances open now and a Watch checkbox.
- A panel shared with you opens for use. It shows Save a copy instead of Edit.
- A Trusted user sees every user's panels, grouped by owner, and can edit, share, push to and watch any of them.
- Delete needs a second press.
- Assign to (as built): on any panel, a Trusted user can open a list of the Sode panel pages seen in the last 24 hours. The user then clicks one (`panelassign.js`, rules in `panelassignrules.js`). Anyone with the Advanced Settings PIN can do the same; the modal asks for the PIN after a `trusted_required` refusal. Each row has its name, the panel it shows now, its address, its uptime since its current stream connected, and its sign-in state in words. The sign-in states are Signed in as the panel's client, Signed in as a named user, Key ended and Not signed in. Rows sort by current panel, then name. Only pages that have held the instance stream are listed, which keeps other API clients out. An instance already on the panel is greyed. A page whose stream has ended is greyed with "last seen" and cannot be assigned (the server refuses it too).
  - `POST /api/v1/panels/{id}/assign` makes a key for the target's client, named for the instance, so it has the target's rights. Sode sends the key as the last line of that instance's newest stream only. When no stream wrote it, the key is revoked and the Assign fails. The page stores the key under the address it will open (the short name, else the id). It rewrites the address, keeps its `?instance=` and kiosk, and drops the old key. It loads the target with a full load, so the staged routes go and no prompt or banner shows. A reload opens the same address with the stored key. The old panel's key stays valid, and the old panel forgets the instance instead of raising a lost notice. The target panel is never written, so its Fixed destination list and Authentication mode stay. One `assign` row names the user, the instance and both panels.
  - A Find box at the top ranks the rows with the panels list's scoring (`wordScore`). It ranks over the instance name, current panel, address and sign-in state. Arrows or Ctrl/Cmd+J and K move the highlight. Enter assigns the highlighted row, and does nothing on a greyed or timed-out one (`rankAssign`, `stepRow`, `enterRow`).
  - A target that already holds that name, as a key or as any instance Sode holds, offline ones included, is never rotated. It answers 409 `name_taken` with a suggested name: the name plus 2, or the next free number. A small dialog offers it, editable, and sends again with `name`. The instance then uses the chosen name as its device name on the target. The page rewrites `?instance=` when the address has one, else stores it as `sode-panel-device`. An Assign of an instance back to a panel that still holds its old key is such a clash. A target at its 20 instances is refused with the reason, before any clash.
  - A target that acts as a user gets no key. The page drops its key for the target's address, opens the target and shows that panel's sign-in. So the person at the device types their own PIN, and nobody types it for them. A panel that acts as both offers Its own key (the default) or Sign in above the list. A device signed in as a user stays signed in. If that user cannot open the target, its row says Not shared with them. A click first asks Send anyway or Cancel, and the page then shows "No panel here that you can use."
  - A page with no working key is a Keyless instance (ADR 0009). It holds `GET /api/v1/panels/{id}/instances/keyless` with no key, under the name it already holds, and never asks for a name. It is listed with its address and with Not signed in, or with Key ended after its key answered `key_revoked` or `key_expired`. It is named by its own name, else the last name that a stream from its address carried, else the address. A keyless page is never greyed as already on the target, since an Assign to the panel it shows is how it gets a key. It gets a key only from inside the target's allowed networks. A page whose key ended stops polling, shows its note and still announces itself. A page that gets a working key stops announcing. Sode keeps at most 1000 keyless entries for 24 hours in memory, and drops the oldest first.
- Rename (as built): on the panels page's Open now list, the Rename icon beside an instance's name turns it into a field. Enter saves, and Escape or a move out of the field drops the edit (`nameSlot` in `panelsmon.js`, rules `renameState` and `renameProblem` in `panelassignrules.js`). Sode offers it to whoever gets the instances (the owner or a Trusted user). The route also accepts the Advanced Settings PIN. A `trusted_required` refusal shows a PIN field beside the name, as the Assign to modal does. Only a Sode panel page that holds its stream can hear the name. A page that timed out shows the Rename icon disabled with "offline", and its key is not renamed alone. `POST /api/v1/panels/{id}/instances/rename` renames the device name itself. The name is up to 40 characters and unique on the panel, with case ignored. Sode checks it against the panel's keys and every instance Sode holds, offline ones included. A held name opens the same dialog as an Assign's clash: the name plus 2 or the next free number, editable. Sode renames the instance's key, moves per-instance watches to the new name and sends a `rename` line down the stream. The page applies it as its header rename does, and reopens its keepalive and stream under it. A page named by its link rewrites `?instance=` instead of storing the name, so a reload keeps it. The old name leaves the list with no lost notice. One `rename` row names the user, the old name and the new one. A keyless instance is not in the Open now list, so it has no Rename icon.
- Share is a modal with two tabs. People sets Only me, Named users or Everyone. Link with key is for a panel that acts as an API client. The key sits in the URL fragment (`#key=`), so it never reaches a request line or proxy log. The link is masked until revealed. The tab offers Copy link, a QR code, Copy kiosk link, Rotate and Revoke (each confirmed). A panel that acts as a user has no key and asks for a PIN at launch. The modal opens on the tab that fits: Link with key for an API client panel, People for a Session panel.
- A panel holds one key per named instance. Rotating a key signs out that instance and kills its old link, and Revoke ends that instance. The other instances are not touched, and the panel keeps its client.
- Link with key as built (`panelkeytab.js`, rules in `panelkeyrules.js`): the tab lists the instances, then a New link form. Each row has Rotate and Revoke. Each row also shows the name, made, last used, online or offline in words, and a pending setup link with when it expires. Every link is made for a named instance. The name is required, unique with case ignored, at most 40 characters, and is also the instance's device name, as with `?instance=`. A link made for a held name rotates that instance. A panel holds at most 20 instances (`panelKeyMax`). The cap is set so a wall of kiosks fits and a fleet does not. The two kinds of link are a Named instance link (a key, shown one time) and a One-time setup link. A One-time setup link works one time for one hour, and the device keeps its own key. The secret exists only in the answer to the make call, so a link is never shown again. To replace a lost link, rotate the instance. Rotate, Revoke and any make that replaces a key each ask for a Confirm (the churning letter, then the button or the key). The link is masked until Show link. The QR appears only then (`qr.js`, built in the browser so the key never reaches a server). It holds up to 106 bytes; longer links say so. Copy kiosk link copies the same link with `kiosk=1` after the key (`?instance=` stays) and says Copied, as Copy link does. Its icon is `monitor`. The tab also edits the allowed networks, which apply to every instance. A modal opened for a panel reads `hasKey` and `clientNetworks` from the panel. It reads the list from `GET /panels/{id}/keys`, refreshed every 5 seconds so Online stays current.
- A Session panel's Link with key tab is greyed but readable. It says that a link to the panel asks for a sign-in in any tab or device not signed in to Sode. It shows the plain panel link and offers no key action. The way out is Acts as its own API client on the Access tab. A change to Acts as saves the panel at once, since it makes or removes the client. A refusal shows under the field and puts the choice back.
- A Public panel's Link with key tab is greyed the same way, since its plain link needs no key. It says anyone with the link can use the panel and shows the plain link, which Copy link also gives. The Access tab offers Public as a fourth Authentication mode. A choice of Public saves at once, with a note that anyone with the link can use the panel. While the panel is Public, the tab warns that its sharing does not limit who can open it.
- Short links. A panel can have a short name (slug), set in the editor's Panel tab. `/panels/<slug>` opens it, and the id URL keeps working. The page route serves the panel page for any segment shaped like an id or a slug and says nothing about which exist. The panel read route (`GET /panels/<slug>`) and the setup route resolve the slug, and an unknown or unusable one gives the same 404. Changing or clearing a slug stops links that used it, which the tab's hint says. One link builder, `linkFor` in `web/panellink.js`, serves the Share modal's Link with key tab. A link with a key is `panels/<slug or id>#key=<key without sode_>`, with `?instance=<instance name>` before the fragment when the link names the instance. The page reads `instance` as the device name and skips its question. The name is no secret, so a query parameter is fine, and the page does not store it. Measured with `http://sode.lan:8080/`: the old link by id was 91 characters, the new link with a short name is 60, and 65 by id. A key is 128 bits now (22 characters), which is enough because keys are throttled, revocable and belong to one panel.
- Secure mode: each instance has one credential. A setup link ends that instance's key and any older link for the name, lasts one hour and works one time. The page opens `panels/<id>#setup=<token>`, posts it to `/api/v1/panels/{id}/setup`, keeps the key in `localStorage` and rewrites the address without the token. A stored key is used when the address has no key; a 401 clears it. A key in the fragment wins over a stored one. A plain `#key=` link is kept the same way after its first call succeeds (a key the server refuses is never stored). It replaces a stored key that differs, and the address keeps `?instance=` and the other fragment parts, such as `kiosk=1`. With `localStorage` blocked or full the key stays in the address, since a reload would have nothing else to read. Unlike a setup link, the key link itself stays valid until rotated or revoked.
- Allowed networks: an optional CIDR list on the panel's API client, one per line in the tab; a bare address is one host. A key used from outside it gets 403 `network_not_allowed`. The check is in the auth path for that client's keys, so it covers every route and the setup exchange. An open page whose key is refused stops polling and says so (a revoked or rotated key says the link no longer works). No alert for a key used from a new place, by decision.
- Share as built: `panelshare.js` opens the modal (`openShare(panel, {api, onSaved})`); another tab joins by pushing a function onto `shareTabs` that returns `{id, text, panel}` or null. People saves only the `share` field through `PUT /api/v1/panels/{id}`. The picker reads `GET /api/v1/panels/people` (names only, a user's key only). Pure rules (`shareDraft`, `pickList`, `shareBody`, `shareChanged`) are in `panelsrules.js`.

## Monitoring

Proposed, not prototyped.

- Each open panel page is an instance with a device name given the first time it opens. It sends a keepalive every 15 seconds. Sode keeps the last seen time and state for each instance, and a panel is online while at least one instance is.
- A user can watch panels. A user can watch the panels they own, and a Trusted user can watch any panel. The watch list is a set of checkboxes in the editor and in the My panels page.
- When a watched panel loses its last instance, or misses its keepalive for more than 45 seconds, every watcher is notified. (After its stream closes, the limit is 8 seconds; see the as-built notes below.) The notice is a toast and a badge in Sode, and a browser notification if the user allowed them. A second notice goes out when it comes back. The notice names the panel, the device and how long it was missing.
- Open questions, decided below: no expected instance count, and no alert for a key used from somewhere new.

## Monitoring (as built)

- Modules (routes and fields are in docs/api.md):
  - `panelmon.go`: devices, watches, sweep, notices.
  - `panelkeepalive.js`: the device name form and the 15 s keepalive.
  - `panelwatch.js` and `panelwatchrules.js`: toast, badge, browser notification, text.
  - `panelsmon.js`: the online mark, the Open now list and the Watch checkbox on the panels page. The editor Access tab mounts the same checkbox.
  - `panelmon.css`.
- An instance is a device name, with case ignored. So a reload, or a rebooted kiosk with the same name, is the same instance and raises nothing. The page asks for the name one time per browser (`sode-panel-device`), unless the panel's `askInstanceName` is off. Then the page never asks, and a link's `?instance=` or a stored name still apply. If the setting is off and neither applies, the page sends a blank device and Sode names the instance by its address. A page also holds a stream (`GET /panels/{id}/instances/stream`). It uses fetch with the Authorization header, which also covers Session mode. So Sode sees a closed page at once and counts the device lost after an 8 s grace. A reload with the same name inside the grace raises nothing. The 45 s keepalive miss stays as the fallback for a page without a stream, or whose stream went quiet. A panel is online while any device counts. Devices live in memory only, so a restart of Sode alerts nothing. A lost device is dropped after 24 hours.
- The Sode page shows a banner at the top for the watched panels that are offline, with Open panels and a Clear button. Clear expands to two choices. "Clear alarm for now" hides that outage for the user until the panel's next notice, in memory only. "Stop monitoring this panel" ends the watch. Both go as the `panelAlarm` socket message. Pages without a banner keep the badge. The Watch checkbox shows what the browser allows for notifications, and asks when Watch is turned on. It has an Allow notifications button while the answer is open, and says when the browser has blocked them.
- A sweep runs from `periodic`. It tells each watcher one time when a device passes its limit (45 s, or 8 s after a closed stream). It tells them one time again when the device returns. The notice names the panel, the device and the seconds, with `offline` true when no device is left. Each change is one `panelLost` or `panelBack` row in the Communication Log. The row names the panel's short name and the instance, as every row from a panel page does (docs/agents/comm-log.md).
- Watchers: the owner or a Trusted user, checked again when a notice goes out. The list is `panelwatch.yaml` beside the config, never in a panel file, and the API only sends the caller's own `watching`. Notices go to connections signed in as the watcher and not under the Lock. `panelsOffline` rebuilds the badge after a reload or sign-in; a notice sent while nobody was signed in is not kept.
- Deleting a panel forgets its devices and watches. Making, rotating or revoking an instance's key forgets that device, so an ended kiosk does not alert.
- A panel client's keys share one rate limit that scales with its live devices, since each page polls every 2 s. Its streams are capped at 64 per key and not counted per address.
- Watch is per panel and per instance (alpha G). The panels page's Open now list has a checkbox on each instance, and a user can hold both. A whole-panel watcher hears about every device as before. An instance-only watcher hears only about that instance. It gets a lost or back toast that never says the panel is offline, and an alarm row `Wall lost Studio A`. Stop monitoring on that row removes only that instance's watch. The editor's checkbox stays whole-panel.
- Dead peers: the server turns on TCP keepalive for every accepted connection (2 s idle, 1 s apart, 3 misses). So a device that vanished without a FIN ends its stream in about 5 s, and is lost 8 s later, inside 15 s. A proxy that keeps its upstream connection open hides this, and the 45 s miss applies. The panels page refreshes the online marks and Open now every 2 s.
- The offline toast's title links to the panel, and its "has not been heard from for" time counts up while the toast is open until the device returns.
- Decided: no expected-instance count, and no alert for a key used from a new place.
- Not built: the Watch checkbox in the editor (story 90; mount `watchBox` from `panelsmon.js` when wanted). It is on the panels page.

## Panel page (as built)

- Modules: `panelmodel.js` is the pure state model (view, stage, arm, Take, results). `panelrules.js` holds the URL, API answers, cell checks and error text. `panelview.js` draws the grid. `panelrun.js` loads the panel, polls and sends the take. The entry is `panelpage.js`.
- Stored cell: `{ r, c, rs?, cs?, kind: source | destination | take | preset | clear | undo | current | panelName | instanceName | pageName | info | goToPage | nextPage | previousPage, n?, scope?, name?, page?, show?, caption?, levels? }`, with `r` and `c` from 1. A Preset cell holds `scope` (`everyone` or `me`) and `name` instead of `n`. `current` is the Current Destination cell. A Go to Page cell holds `page`, its target Page's id. The page does not draw a cell that is outside the grid, unknown, or overlaps an earlier cell. It also does not draw a Source or Destination without `n`, a Preset without both, or a Go to Page without `page`. Settings read: `mode`, `multi`, `levels`, `guard` (`hold` or `double`, anything else is none), `fixedDests` and `wrapPages`.
- Fixed destination is `settings.fixedDests`, a list of at most 16 different destination numbers. The server checks it on every save and drops an empty list. A template keeps it only with `dests`. A Push leaves each target's own list, since sibling panels often patch to different destinations. A Checkpoint set and a restore put each panel's own list back. The panel page reads it as in Behavior above (`fixedDestsOf` and `drawnCells` in `panelrules.js`); the editor sets it in the Panel tab (Editor above).
- A Preset cell stages every route of the preset (`GET /presets`, polled with names) and views its first destination. One refused route (Protected, no common level) refuses the whole preset. With `multi` off, a preset with more than one destination is refused. A taken route is sent as an ordinary `POST /takes`, so History shows routes, not the preset name. Clear, Undo, Current Destination, Panel Name and Instance Name have no stored fields beyond `caption`. The last three are disabled, as are Page Name and Info, which also store `show`.
- Instant mode: `startInstant` is called right after a Source, Preset or Undo press. One route set is held at a time, so a new press replaces a failed one. The Take cell stays disabled. Guards apply to the Take cell only. `double` needs a second press within 1.5 s. `hold` needs 0.8 s of pointer or Enter and Space held (`guardDown`, `guardHeld`, `guardCancel`).
- A browser cannot send a Bearer header on `/api/v1/stream`. So the page applies the tally frames of its own `/ws` socket to the last `/tally` read. It polls `/protected` and `/status` every 2 seconds, `/names` every 30 and `/tally` only every 60, as a check. While the socket is down, it polls `/tally` every 2 seconds too. A Hidden caller's page reads `/tally` again for each frame (docs/agents/web-layout.md). A take is `POST /takes`, which is its own Confirm, with an `Idempotency-Key`. To take a staged undo, the page sends `POST /panels/{id}/undo`, also with an `Idempotency-Key`. It also sends the `id` that the undo was staged from, so the server marks that take undone. When the take moved since, the server answers 409. The page then drops the plan and says to press Undo again. The page asks `GET /panels/{id}/undo` on load and reconnect, after each take or undo, and when a destination it would restore moves. It never asks on a timer, and asks only while a Page has an Undo cell. Both need only the `take` scope (a panel key has no `history`). The server finds the take by the History entry's `panelId` and `instance`, so the caller's own instance is the filter.
- Live update (P15): the page reads `GET /panels/{id}` every 5 seconds and compares `rev`, which `panelStore.writeLocked` moves on every stored change. A newer copy shows a banner that counts down 10 seconds (`Refreshing in N s`) over a countdown bar. The bar is the main page's result bar (`sode__banner-bar`). The banner has Snooze 60 s and Apply now. At zero, the copy applies unless a take is in flight or routes are staged. In that case the banner says it waits, the bar goes, and the copy applies after they are taken or cleared. Snooze never dismisses the banner. The banner stays up, the bar counts 60 seconds, and at the end the copy applies with the staged routes dropped. The line says so: `Refreshing in N s, dropping the staged routes.` An open page snoozes one time. After the first Snooze, the button is gone for that page; the banner keeps its 60 second countdown and Apply now stays. The next update after an apply brings one Snooze back. Apply now applies at once, staged routes or not. The rule: the countdown alone never drops a staged route, since nobody asked for the change on this page. But Snooze and Apply now are the person's own press, and so are their word that the routes can go. Neither cuts short a take in flight; the copy applies after the take answers. The viewed destination survives the refresh (`carryView`, `panelmodel.js`). The rules are in `panelupdate.js`, and the poll and banner are in `panellive.js`. A Push (P17) only has to store the target panel through `panelStore.replace`, and open panels follow.
- The panel header shows the instance's name, and a click edits it (`panelname.js`). A rename restarts the keepalive and held stream under the new name (`startKeepalive().rename`), and stores it in `sode-panel-device`. The old name is lost after the usual grace. A name from the link's `?instance=` is not editable here. The panels page can rename it, and the page then rewrites its address (Rename above). With `askInstanceName` off, the header shows no name at all, and an Instance Name cell with no name shows the kind's words. Full width is an icon-only button (`chevrons-left-right`, `chevrons-right-left`) with `aria-label` and `data-pb-tip`.
- The page cannot read a panel's mode before it has a key. A key in the URL fragment (`#key=`) means API mode. Without one, the page starts a session key (Session mode). If the panel then proves to act only as an API client (`acts: api`), the page asks for its link with the key. It does not run the panel. A Both panel runs on in Session mode. A Public panel never gets that far: the page asks for a Public key first (Authentication).
- A failed route stays staged after a take, so Take can be pressed again. A level with nothing routed is ignored when the page finds the current source. `GET /panels/<id>` carries the caller's own Rights as `rights`. The page refuses a Source or Destination outside them (and a Preset outside them) before it arms, as `outside-rights`. Hidden Visibility makes that message name nothing. Levels the Rights exclude drop out of the take, and none left is `no-common-levels`. The server refuses the same route anyway, so keep `rightsAllow` in step with `config.Rights`. The setting `resultText` adds the Result word beside its icon. Kiosk (`settings.kiosk` or `#kiosk=1`) hides the header and the Lock button bar (`data-sode-kiosk` on the root, `panels.css`). It also fixes the box that holds the status line and the update banner (`.sode-panel__foot`, `#panel-foot`) to the bottom of the viewport. So a refusal or a countdown never moves the grid. A Grid panel on the desktop layout has them in the status slot of its band instead, in kiosk mode too. `TestChromePanelKioskAndRefusal` and `TestChromePanelLockBarLayout` cover it. Otherwise, that box sits between the header and the grid, and the Lock bar floats over the page with no height of its own. The header clears its width (`--sode-who-w`), so the bar never covers the title or the grid, in full width too.

- Offline (`offlineOf` in `panelrules.js`): the page goes Offline when a poll fails with no answer or a 5xx, or when `GET /status` says `routerUp` is false. It then blurs every other element, blocks presses and shows a large framed Offline message (`pb-state-offline`). The message has a sentence that says which one is gone: Sode or the router. It clears on the next good poll. A key without the `status` scope gets 403 there, which counts as an unknown router link, not down. A session that is not signed in yet is not Offline. `TestChromePanelOfflineAndFullWidth` stops the Sode API and the simulator.
- Full width: the header button (`panelfull.js`) drops the page's width cap and padding and is remembered in `localStorage` as `sode-panel-full`. A panel without a title bar, or in kiosk, has no button.
- Header buttons, left of Full width and the same icon size: Full screen and Kiosk. Full screen uses the browser Fullscreen API (`panelfeel.js`). It tracks `fullscreenchange` and is hidden where the browser refuses it. Kiosk turns kiosk on for this open page only. The panel setting and `#kiosk=1` give the starting state, and a reload returns to it. The header is gone in kiosk. So the way back is the Escape key (unless a dialog already handled it) and a faint button in the top right corner. The button has 25% opacity, full on hover or focus. The rules are in `panelchromerules.js`.
- The Panels link is an icon-only ghost button with the Sode Panels logo at the bottom left, as on Sode's main page. On a Grid panel it is in the header while the header shows. It is fixed on the desktop layout, and the page is padded so it never covers the grid. On a phone it is in the flow at the end. A kiosk hides it with the header.
- The Current cell reads "<destination> is currently:" for the viewed destination, and its caption when it has one. The Take cell is solid when nothing is staged, and pulses when a route waits for it. It fills left to right (a transition, not an animation) while a hold or double-press guard waits.

## Look and device settings (as built)

- Modules: `panellook.js` (pure: reads settings and cell artwork), `panelart.js` (artwork fetch), `panelfeel.js` (wake lock, fullscreen, landscape), with the page wiring in `panelrun.js` and `panelview.js`. Tests in `web/test/panellook.test.mjs` and `panelart.test.mjs`.
- Panel `settings`:
  - `titleBar`: false hides the title bar, which is the header with the name and the Panels link. Kiosk hides it too.
  - `fontSize`: percent, 50 to 200, default 100.
  - `theme`: `light` or `dark`. When it is missing, the page uses the browser's setting. The old `backdrop` is ignored.
  - `wake`, `fullscreen` and `landscape`: true switches them on. Fullscreen is asked for on the first press, since a browser needs a touch. Landscape locks the screen turn after that fullscreen starts. Landscape alone also asks for fullscreen on a press, since Chrome locks the turn only there (`wantsFullscreen` in `panelfeel.js`). The editor says so beside both switches. iOS has neither the lock nor iPhone fullscreen. So a portrait page with landscape on is covered by a Turn your device message. The page's `apple-mobile-web-app-capable` meta makes a Home Screen copy open without Safari's bars.
  - `askInstanceName`: default true. False never asks for a device name (see Monitoring).
- Cell fields:
  - `art`: `icon:<vendored icon name>`, `lib:<Icon library id>` or an artwork id.
  - `artB`: Icon B, `0` to `16` or `A` to `Z`.
  - `fontSize`: percent, multiplies the panel's.
  - `hideText`: true hides the text while the cell draws Icon A or B, its own or a default's. False shows it against a default. When it is unset, the default's value applies.
- Colours: an idle Source is `--pb-current-idle`, an idle Destination `--pb-view-idle`, both the state colour muted into `--pb-surface-control`. Viewed and Current are solid. Staged, pending and an armed Take swell between 72% and 100% of the state colour on `--pulse`. Each also has a static inset ring, so reduced motion (which freezes `--pulse` at 0.6) still shows state.
- Artwork: the route needs the Authorization header, so the page fetches it with the panel's key and shows a blob URL in an `<img>`. SVG is never inlined. The CSP allows `blob:` for `img-src` only. A fetch that fails leaves the cell without artwork. An icon name missing from the vendored sprite draws nothing.
- Keep the screen awake: Screen Wake Lock. The page requests it when it opens and again whenever it becomes visible, since a browser drops the lock when the page hides. A refusal is ignored, and a press asks again, since it is possible that Safari refuses a request made without a touch. Plain http has no wake lock, and the page says so. `featureSupport(navigator)` in `panelfeel.js` says what the browser has, so the editor can disable the switch. Haptics were tried and dropped. iOS has no vibrate, and the switch-input tick and `navigator.vibrate` gave nothing on the phones tested. So an old `settings.haptics` is ignored. Result of the spec's proposal: built as described, with no extra settings.

## Push as built (P17)

- Server: `panelpush.go` (layout, checkpoints, set store) and `apipush.go` (routes). A layout is `rows`, `cols`, `pages` (every Page with its id), `settings` and unknown fields. Id, name, owner, `share`, `acts`, the API client and its Rights are never copied, and missing artwork is copied. `panelStore.applyLocked` writes the checkpoint before the panel, so a checkpoint that cannot be saved stops the Push. The panel write moves `Rev` for open panels (P15).
- Reach: the pusher must be able to change the source and every target (`panelReach`); one refused target changes nothing. Checkpoints sit in `panels/<id>.checkpoints`, at most 10 per panel, and a restore keeps what it replaces. Sets are in `panelsets/` (`everyone.yaml`, `me-<hex of user>.yaml`); an Everyone set needs a Trusted user to save and to change someone else's.
- A group is the panels whose names differ only by a trailing number (EVS 1 to EVS 4 are "EVS"). The page works out the groups (`pushGroups` in `panelpushrules.js`); the server only knows ids. This meaning of group still waits for the owner's confirmation. The build chose it, not the spec. `pushTargets` is the tested selection rule.
- Web: `panelpush.js` is the modal (Push, Checkpoint sets and Restore tabs), opened by Push to panels in the panels page's detail bar. The editor toolbar has no Push control, although the Editor section lists one.

## Build notes

- Editor Find: `findrules.js` is pure. It holds entries with Rights and Visibility, ranking, the run a choice places, the plan and `applyFind`, which sets a Preset cell's `scope` and `name`. `editorfind.js` is the flyout in the smart menu. It plugs in through `addMenuSection` and `addKeyHook`. It catches `myRights` at import time, because the message can arrive before the editor loads. It previews by marking the grid's squares in place. Fill order is `setOrder(id)`, default `across`.
- Editor Artwork tool: `arttoolrules.js` is pure (`artToolPlan`, `applyArtTool`). `editorarttool.js` is the flyout, added after Find through `addMenuSection` so it sits below Find. Its columns come from the Cell tab's `artPane` and its upload from `uploadArt` (`editorart.js`). Fill order is Find's: `initFind` returns `order`, `setOrder(id, { focus })` and `onOrder`.

- Vanilla ES modules and patchbay tokens only. The prototype used `pb-btn pb-xpt` cells, `pb-toolbar`, `pb-toast` and the Lucide sprite. Orange and the muted idle colours need new semantic tokens upstream, since `--pb-brand` is for navigation chrome.
- Status is icon first, with optional text. This is a documented exception to patchbay's "status always with text", and AGENTS.md has a line for it.
- One animated root custom property (`@property --pulse`) drives every pulse, so cells stay in phase across re-renders.
- The settings in the editor's sidebar are a first pass for the prototype. Several of them, such as keeping the screen awake and the networks allowed, are placeholders, and it is possible that they change.

## Decisions where the build differs from the design

- Monitoring: no expected-instance count, and no alert for a key used from a new place. Keepalive every 15 seconds and a held stream. A device is lost 8 seconds after its stream closes, or 45 seconds after its last keepalive when it has none. It is forgotten after 24 hours.
- Allowed networks are a CIDR list, at most 16 per panel client. A bare address is one host.
- A setup link lasts one hour and works one time.
- Push group: panels whose names differ only by a trailing number. It still waits for the owner's confirmation.
- Editor sidebar: the Panel tab has no colors or updates settings, because nothing reads them. The level boxes show every level ticked when no subset is stored, and the last ticked box cannot be cleared.
- Push has no control in the editor toolbar; it is on the panels page. The editor's Watch checkbox (story 90) is on the Access tab, beside the one on the panels page.
- Panel and cell levels and Visibility are conveniences of the page. The Rights of the user or API client are the only limit the server applies.
