## Beta 1.8.3

- **Sode Panels.** A panel is a grid of large touch cells that patches the router through `/api/v1`. A cell views a destination, stages a source, takes a preset, clears the plan, shows the Current Destination, or is the Take cell. Panels run in Take mode or Instant mode, can drop multi-destination, can require a hold or a double press on Take, and refuse a route outside their Rights, a Protected destination or a pair with no common level before Take arms. Each destination shows its Result as an icon, with optional text. The viewed destination and the staged routes stay until a press, a take or Clear ends them. A panel can set a title bar, font size, light or dark theme, per-cell captions, levels and artwork, keep the screen awake. A panel opens at `/panels/<id>`.
- **Acts as.** A Session mode panel acts as the signed-in user through a session key that ends with the session. A Trusted user can instead make a panel act as its own API client, capped at the creator's Rights (only the Advanced Settings PIN widens it). The client and its keys go with the panel. The panel's link carries the key in the URL fragment, so no request line or proxy log sees it. Secure mode swaps a one-hour, single-use setup link for a key stored in the browser. Rotate and Revoke each ask for a confirm, and an optional list of allowed networks (up to 16 CIDR entries) limits where the key works.
- **Panels page and sharing.** `/panels` lists your panels and those shared with you, with a mini grid, owner, how it acts and an online dot. Launch, Edit, Save a copy (for a use-only panel) and a two-press Delete are one click away. Share sets Only me, Named users or Everyone, and for a panel that acts as an API client adds a Link with key tab with Copy link, a QR code and a Regular or Kiosk choice for the link. A Trusted user sees and edits every panel.
- **Panel editor** at `/panels/editor`. Select squares, then use the menu beside them to set a type, merge or unmerge, and fill from one Find across Sources, Destinations and Presets that respects Rights and Visibility. Six fill orders, a corner grip that extends numbering, Test it live, and a sidebar with Panel, Cell and Access tabs. A click in the sidebar puts the menu away without losing the selection, and Find's flyout stays inside the window. Cells carry two icon slots: Icon A is a vendored icon (the cell kind icons first) or an upload, Icon B is a digit 0 to 16 or a letter, drawn beside it. Hide text shows in the editor square.
- **Fixed destination.** A panel can hold a list of up to 16 destinations it always patches to, with no Destination cell to press first. A Source press stages a route to each of them, a Preset press stages only its routes to them (and is refused, naming the Preset, when it has none), and a refusal on any one refuses the whole press. In the editor's Panel tab a picker with Find's search, Rights and Visibility adds and removes them; while the list is not empty, Destination cells are set aside (stored, not drawn, back when the list empties), Destination is greyed in Type and Find, and Stage several Destinations is disabled with a note. `settings.fixedDests` over the API; a Push keeps each panel's own list and a template keeps it only with Store with Destinations.
- **Both.** A panel's Acts as has a third choice: with a key in its link or stored on the device it acts as its own API client; opened without one it runs as the signed-in user. `acts: both` over the API.
- **Public panels.** A Trusted user can make a panel Public: its plain URL opens it with no sign-in, PIN or key in the link, and it acts as its own API client within the creator's Rights. The page gets a 15-minute key from `POST /api/v1/panels/{id}/public`, held in memory on both ends, and asks again when it ends. Each address may ask 128 times a minute. Any other panel, an unknown id, and a Public panel asked from outside its allowed networks all answer `{"public": false}`. The panel page lock shows no PIN pad on a Public panel, and the idle letter Lock still works. Leaving Public or deleting the panel ends every key it handed out. `acts: public` over the API.
- **Ask for an instance name.** A panel setting, on by default. Turned off, a page never asks for a device name, and an unnamed instance goes by its address in monitoring and the Communication Log. While it is on, a keepalive or instance stream with no device name is still refused. `settings.askInstanceName` over the API.
- **Templates, Push and checkpoints.** A Template saves a layout (optionally its settings and contents) for Me or Everyone. Everyone needs a Trusted user or the Advanced Settings PIN. Push copies a panel's saved layout to your other panels, keeping each one's name, id and sharing, after saving a Checkpoint of each. A Checkpoint set holds one layout per panel in a group, so one Push gives each panel its own. Open panels pick up a saved edit or a Push with a countdown banner: Snooze 60 s keeps it up and applies when its bar runs out, Apply now applies at once, and in a kiosk the banner and the status line sit at the bottom of the viewport so the grid never moves.
- **Monitoring.** Each open panel page is an instance with a device name and sends a keepalive every 15 seconds. A panel is online while any instance is. Watchers get a toast, a badge and a browser notification when the last instance goes quiet for more than 45 seconds, and again when it returns. History shows panel takes as "Seth (Panel p-1a2b3c4d)".
- **API.** New `panels` and `panelsmanage` scopes and routes under `/api/v1/panels`, `/api/v1/panel-templates` and `/api/v1/panel-sets`, all in `openapi.yaml`. Panel client keys allow 64 streams and a rate limit that scales with the live instances. Renaming or removing a user updates panel owners and sharing.
- **Ended keys.** A key that worked and was then ended (revoked, rotated, its session ended, its owner removed or their PIN changed) now answers 401 `key_revoked` instead of `invalid_key`, and an expired one stays `key_expired`. Both are final, and neither counts toward the ten failed keys per address, so a forgotten tab or tablet still sending an old key no longer makes every page at its address wait. Sode's pages stop calling when their key ends and wait out `Retry-After` after a 429. A signed-in browser holds one session key per tab, up to 16, so tabs no longer end each other's.
- **Auto-lock on the server.** Sode now keeps an idle clock for each signed-in session and raises the held Lock when it passes the auto-lock minutes, even with every tab closed, so a browser that comes back meets the PIN pad. It covers every page. One gap: a Session mode panel's session key still answers the API under the Lock, though the panel page drops it. Open pages send an `activity` message about every 30 seconds while someone is using them, any tab on the session keeps it awake, and a change to the minutes applies at once (0 turns it off). Nobody is signed out, users marked No auto-lock are skipped, and a restart starts every clock over.
- **Assign and Rename.** On `/panels` a Trusted user sends a running panel page to another panel with Assign to. The page switches at once with no prompt: to a panel that acts as an API client it gets a new key over its stream, never in a REST answer, and to one that acts as a user it shows its own sign-in. Rename gives a running page a new device name, and its header and address follow. A name another instance holds is refused with a free one suggested.
- **Keyless instances.** A panel page with no working key, or whose key ended, announces itself by its device name or its address, so a Trusted user can see it on `/panels` and Assign it. The announcement grants nothing and answers the same for a panel that does not exist.
- **Panel key in browser storage.** A keyed link drops `#key=` from the address once the page stores the key in the browser under the address's panel id or short name, so a reload runs on the stored key. Where storage does not work the key stays in the address.
- **Icon library.** One install-wide set of PNG and SVG icons, kept in `icons.yaml` and `icons/` beside the config. Choose icon's Uploaded section lists it, and a cell stores `lib:<id>`. Adding, renaming and deleting need a Trusted user or the Advanced Settings PIN. Files put in `icons/drop-in/` are added at start and on Rescan, and a skipped file is reported in the status line and the Communication Log. An SVG icon draws in the cell's text colour.
- **Default artwork.** A Source, Destination or Everyone preset can carry Icon A, Icon B and Hide text that every cell showing it uses when the cell sets none of its own. One shared set in `artdefaults.yaml`, changed from the Cell tab by a Trusted user or with the Advanced Settings PIN. Open panels pick up a change through the update banner. `/api/v1/default-artwork` over the API.
- **Artwork tool.** The editor's smart menu has an Artwork item below Find: one Icon A for every selected cell, Icon B counting on in Find's fill order, or Clear artwork, with a preview first.
- **Artwork limits.** An uploaded image is at most 2 MB and 1024 by 1024 pixels; the editor shrinks a larger PNG or JPEG before sending it. The 40-file cap per panel is gone and a panel holds 64 MB of artwork in all. Push and Copy bring across what fits and the status line counts the images left out. Artwork stored before the limits still loads and serves.
- **Panel Pages, stored.** A panel file now holds `pages`, an ordered list of up to 16 Pages that share its size, each with an id that never changes, an optional name of up to 40 characters and an enabled switch. A panel saved before this loads as one Page and its next save writes only `pages`; Sode does not write `cells` as well, so an older Sode opens such a panel as an empty grid instead of half of it. Push, Copy, templates, Checkpoint sets and restores carry every Page with its id, and a resize drops cells that no longer fit on every Page. Over the API a panel and a template carry `pages`, and a body with only `cells` changes Page 1; a panel or template body may be up to 4 MB.
- **Pages on the panel page.** Go to Page cells open a chosen Page, kept by its id so a move or rename never changes the target, and draw greyed when that Page is disabled or deleted. Next Page and Previous Page skip disabled Pages and go round at the ends unless Wrap between Pages (Panel tab, `settings.wrapPages`) is off. Page Name and Info cells show the Page's number and name, and Info also the panel and instance names. The last enabled Page cannot be turned off, in the editor or over the API.
- **Pages in the editor.** A Pages bar left of the grid adds, renames, turns on and off, reorders, deletes (with a Confirm that counts the Go to Page cells leading there) and copies a Page onto another with Copy to. Up to four Pages open side by side. Test it live runs the Page being edited.
- **Grid commands.** Select all, Copy, Cut and Paste of cells (within a panel, across Pages and between panels, where uploaded images and Go to Page targets are dropped with a note), and Undo and Redo of grid edits. A paste that runs past the edge asks Clip or Wrap; Wrap goes on to the later empty enabled Pages. A pasted block is checked field by field and refused whole if any cell is malformed.
- **Editor and page polish.** Changing Authentication mode shows what the switch does to the client and its keys, and one that makes or ends the client, or makes the panel Public, waits for a Confirm. The toolbar's name has a Rename button. Turning off Automatically enter fullscreen now keeps the page out of fullscreen unless Enforce landscape orientation needs it. An Open now instance's checkbox reads Notify on disconnect. The Lock bar floats over the panel page's header row.
- **Stream frames name their topic.** `/api/v1/stream` change frames now carry `topic`, so a client reading 1.8.0 frames sees a new field.
- **Review fixes before the candidate.** A setup link for a Both panel now trades for a key. A refused panel save (a taken short name) no longer ends the panel's API client and keys first, and a save no longer loses artwork, an owner rename or Rev written meanwhile. A held instance stream ends when its key ends, so an Assign never sends a key down a stream whose key is gone, and leaving Public ends its keys after the save. A Public key's panel reads name no user. In Instant mode a refused press sends nothing. A Session mode take with no session key is refused at once instead of waiting for the next sign-in. A refused network no longer makes the panel page forget its stored key. Share saves from the stored panel, so it cannot undo an edit saved meanwhile. The editor asks before Back or Forward leaves unsaved changes. Checkpoint sets follow a user rename.
- **Patchbay 2.2.0** adds the `--pb-view`, `--pb-view-idle` and `--pb-current-idle` tokens for panel state colours. `docs/agents/panels.md` and `docs/panels-design.md` cover how panels are built.

## Beta 1.8.0

- **An authenticated API** under `/api/v1`, off until an administrator turns on *API enabled* (Settings, advanced). Other apps can read names, tally, Protected destinations, presets, History, status and, with the log scope, the Communication Log. They can fire a take by routes or by a preset, and Undo, Redo or Retry a History entry. A take request waits and returns a Result per route with the History entry ids, and has a worst case of about 35 seconds, so a proxy that cuts at 60 seconds needs a longer read timeout for `/api/v1`. An optional `Idempotency-Key` header makes a retry return the first answer. A take of 6 or more routes skips the Before check and says so with `checkSkipped`. `GET /api/v1/history/groups/last` returns the latest Group so a caller can undo each entry. Undo, Redo and Retry work on one entry at a time in v1. Sode serves the contract at `/api/v1/openapi.yaml`, and [docs/api.md](docs/api.md) is the guide.
- **API keys and API clients.** A key is shown once and only its hash is kept (`keys.json` beside the config). It has a key name such as "Panel 21", an optional expiry and a last used time, and History and the Communication Log show the actor as "PanelsBot (Panel 43)". A user's key acts as that user and ends when their PIN changes or they are renamed or removed. A key of an API client carries the client's own rights and scopes and ignores user PINs. Revoking a key, its expiry or removing its owner now also closes any `/api/v1/stream` open on it, with the reason in the Communication Log. Users make their own keys under Settings > My user > *My API keys* with their own PIN, with a copy button and a QR code. Administrators add API clients and their keys, see every key and revoke any with the Advanced Settings PIN. New messages `keyCreate`, `keyRevoke`, `keyListOwn`, `keyListAll`, `keyCreateFor`, `keyRevokeAny`, `keyRevokeAll` and `apiSettings`.
- **Rights and visibility.** Each user, each API client and Guest has allowlists of sources, destinations, levels and presets (an unset list means everything, so an old file changes nothing) and a visibility, read-only or hidden. A take with any route outside the rights is refused whole before anything is sent, with no History entry: a browser gets a failed Result per route, the API a 403 `outside_rights`. Undo checks the destination and level but not the Before source. Hidden removes out-of-rights routes from what an API caller sees, and applies to API callers only (ADR 0004). A signed-in browser gets its own rights in a new `myRights` message, never in the hello, and greys out what it cannot take.
- **Manage users is one dialog** with Users, API clients and Rights tabs and one Save. Each user row has *Edit user rights*. Guest has its own rights and API scopes, which start at names, tally, protected destinations and status. *Guest API*, the rate limit, the take cap and *Log API reads* are API settings.
- **No auto-lock**: an administrator can mark a user on the Rights tab, such as a wall browser's, to be skipped by the idle auto-lock. The Lock button still works. It is a flag per user and is not the old exempt flag.
- **Require HTTPS** under Settings > Proxy refuses every request but `/healthz` and `/api/health` unless a trusted proxy says it arrived over HTTPS, and sends a short HSTS. It will not save with no trusted proxies, or from a request that did not arrive securely. `sode -reset-https` turns it off from the console (ADR 0005).
- **Communication Log** gets an `api` kind, on by default in the filter. It has every API command and refusal, key created, revoked or expired, rights and client edits, stream connects and disconnects, the API and Require HTTPS switches, and failed keys (one row per address per minute with a count). No key, key hash or PIN is written.
- **Review fixes.** *Import* of a server configuration refuses turning on Require HTTPS from a request that did not arrive securely, and writes the same `api` rows as the saves it replaces. At startup, a user's keys end when their PIN changed in the config file while Sode was down (`keys.json` records a one-way fingerprint of the PIN hash; keys from an older file are kept and stamped at the first start). `GET /api/v1/status` and the stream's `status` topic give the router address and error text only to a caller with the `log` scope; everyone else gets an `error` flag.
- **Docs**: [docs/api.md](docs/api.md) is new, and the reference, the notes for agents and the glossary cover keys, rights and the API. ADRs 0002 to 0005 record why a take request is its own Confirm, user keys die with the PIN, hidden is API-only and Require HTTPS trusts the proxy header.

## Beta 1.7.0

- **Sign-in mode switches both ways**: in Manage users, *Fill empty usernames* sets each empty username to the Name without spaces (numbered on a clash, case ignored, never over a typed one), so an existing install switches to Username and PIN in one save. Switching back to PIN only is allowed. It needs a new PIN for every user in the same save, because Sode can't tell whether saved PINs match. The server refuses the save, naming the users, when a user has no new PIN or two users typed the same one, and Manage users marks each row and blocks the save until every user has a different new PIN. Nothing new is stored and PIN hashing is unchanged.
- **Settings search takes Ctrl+J/K**: with the search box focused and results showing, Ctrl+J/K (⌘J/K on a Mac) move the highlighted result like in the other search lists. With no results, or focus elsewhere, they still step between sections. The shortcuts list has a Settings entry.
- **External, not External change**: the History badge and filter read *External*, and GLOSSARY.md retires "external change". Nothing persisted or sent changed.
- **Settings reordered, search hit more obvious**: the order is This browser, My user, Global defaults, Router & matrix (Router and Matrix merged), Takes, Router names, Level colors, Branding, Access, Users, History, Proxy, Export & import, Server backup. *Me* is *My user*, *Sode Networking* is *Proxy*, and the contents tab for the names section reads *Router names*. A found setting now pulses blue (three times, once the scroll ends) instead of sitting in the accent outline.
- **Settings opens with the cursor in the search box**, not in *Re-read every (s)*.
- **Ctrl+J/K in Settings no longer waits on the scroll animation**: each press jumps straight to the next section, so repeated presses walk one section each.
- **Settings search finds Fire mode**: typing "fire", "sequential" or "native" now lists the Fire mode setting.
- **Tabs of one sign-in no longer share a Lock after a resume**: when a PIN resume ends a tab token that only carried the Lock, each tab keeps its own session, so locking or signing out in one tab no longer locks or signs out the others. Sign-in mode saves treat an empty `signInMode` as "keep the current mode", as before.
- **Cleanup, no behavior change**: Settings saves decode over a copy of the live config, connections on one token share one session struct, `lock.js` is renamed and its idle sharing moved to `idleshare.js`, the This browser section moved out of `settings.js`, the filter and preset editors take a target object (`editortargets.js`), and the Go tests can shorten take timers.

## Beta 1.6.0

- **One vocabulary across the UI, docs and code** (GLOSSARY.md). No behavior changed in this part, only words. The renames you will notice:
  - *Recent* is *History* everywhere (the bar, the keyboard mode, *Clear History*, *Hidden destinations in History*). A folder of takes is a *Group*.
  - Changes from a panel or Companion are *External changes* (the filter reads *External changes*, not *Other panels*), and a change that seems to follow another is an *External follow*, no longer "automation".
  - *This device* is *This browser*, and the personal section is *Me*, no longer *Your account*.
  - *Settings PIN* is *Advanced Settings PIN* in the UI, the lock help, the log lines and `-reset-pin`. Settings the PIN guards are marked *(advanced)*, and shared settings say a Trusted user may change them.
  - *Log in* and *Log out* are *Sign in* and *Sign out*. The PIN button on a locked page reads *Enter*, not *Unlock*, and *Lock after idle* reads *Auto-lock after idle*.
  - The sent log is the *Communication Log*.
  - A batch of takes is one *take* (or a *Group* in History), and a pending take is a *plan*.
  - A saved *salvo* is a *Preset*. *Router salvo* names only the router's own group send (*Router salvo group*, and the Communication Log's *Router salvo stage* and *Router salvo go*).
  - The connection banners read *Lost link: Server link down* and *Lost link: Router link down*.
  - *Refresh names* is *Re-read names* (*Re-read now*, *Re-read every (s)*), and *Wire level offset* is *Level offset*.
  - Config keys, `localStorage` keys, wire message types and `SODE_*` and `SIM_*` env keep their names, so existing files, compose files and browsers carry on. `docs/persisted-names.md` lists each kept name.
- **Behind it**: `TestRetiredWordsCoverGlossary` and the vocabulary scans now enforce every retired word in docs, UI text and web identifiers, with no pending list left. Go and web identifiers say Route and take as the glossary defines them.
- **Sign-in mode screens**: Manage users has a *Sign-in mode* box (*PIN only* or *Username and PIN*) and, in Username and PIN mode, a *Username* column beside each Name. In that mode the sign-in screen asks for a username above the PIN pad and sends nothing until both are given. The Lock of a signed-in user still asks for the PIN only. - **The Lock keeps a signed-in user signed in and the server holds it**: Ctrl+L, the chip's lock button and Lock in Settings raise the Lock without ending the session. A reload or reconnect shows the PIN pad again, the server refuses takes, name re-reads, history clearing and log reads from that session until the same user's PIN resumes it, and another user's PIN does not (it counts as a wrong try). Other tabs of the session lock and resume together. **Sign out** on the Lock ends the session and revokes its tokens (new message `userSignOut`; `userLock` now only locks). The locked flag is saved with the session token in `tokens.json`. With nobody signed in, the Lock is still the page-only letter. This reverses #198, where locking signed the user out.
- **A Lock held for a user who is not persistent survives a reload too**: the Lock hands that tab a token (new `tab` flag on the `session` message) that only carries the held Lock, never a sign-in under a PIN lock, and it dies when the PIN resumes the session.
- **Idle is per browser**: activity in any tab of a browser resets the auto-lock timer of all its tabs, so a background tab no longer locks the session while you work in another.
- **Manage users says what a rename does**: renaming a saved user shows that they are signed out everywhere. Their Profile and PIN stay.
- **The Profile dialog says a Profile is not private**: trusted users and the Advanced Settings PIN can see and edit every Profile.
- **Last chip is per browser**: a browser that has made no take has no Last chip, and Ctrl+S/D/F and the Next chip and keys do nothing until it makes one. The fallback to the newest Sode take in History is gone, so a fresh browser never fills a box with someone else's take.
